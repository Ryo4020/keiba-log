- **概要**:
  - 共通
    - 対象ユーザーは JWT オーソライザーが検証したクレームの `sub` のみで特定し、`recordKey` から対象の馬券記録アイテムのキーを組み立てる

    - 存在しない・他ユーザーの記録は区別せず `404`
  - `GET /records/{recordKey}`（`getRecord`）のエンドポイント
    - AP-04: 馬券記録アイテム1件の取得（強い整合性のある読み取り）
    - 取得したアイテムから `Record` 形式（レース記録は買い目・買い目の集合を含む `RaceRecord`、簡易記録は `SimpleRecord`）のレスポンスを組み立てる

    - リクエストボディ（`RecordInput`）による記録全体の置き換え（部分更新は行わない）
    - 値の検証（`business-rules.md` に従う）。不正な場合は保存せず `400` で不正な項目を `details` に返す
      - 記録種別ごとの項目の値（日付の範囲・競馬場・レース番号・金額の範囲と購入単位）
      - `recordType` が対象の記録の記録種別と異なる場合は `400`
      - 買い目の件数の範囲（レース記録全体で1件以上200件以下、集合は1件以上）

      - 買い目の集合の組合せが `methodSpec` から成立する組合せと一致すること、各買い目の購入額が `unitAmount` と一致すること
      - 既存の集合（`betGroupId` 指定）の券種・買い方が登録時と同じであること
      - 結果の確定状態に応じた各買い目の結果状態・払戻額の成立条件
    - 既存の買い目・買い目の集合の識別子の引き継ぎと、新規の買い目・集合の識別子の採番
    - 集合をバラす操作（集合を `betGroups` から外し、含まれていた買い目を `bets` に移した構成）の受け入れ
    - フォーメーションの指定内容の変更で成立する買い目が1点になった構成（該当の集合を `betGroups` から外し、その1点を通常の買い目として `bets` に1件入れたもの。バラした場合と同じ構成）の受け入れ。この構成は通常の買い目を含む `bets` として通常どおり検証・算出する
    - 1点だけを含む買い目の集合の受け入れ（拒否しない）。ボックス・ながしの1点の集合、および API に直接送られたフォーメーションの1点の集合のいずれも対象とする。集合の買い目は1件以上であればよく、点数・購入額（`unitAmount × 点数`）・寄与額は通常の集合と同じ算出とする
    - 集合の指定内容の変更による「作り直し」（集合を `betGroups` に残し、`methodSpec` から成立する組合せと各買い目の組合せが一致する構成）の検証は、上記の検証のとおり行う
    - 結果状態・払戻額の検証は、作り直しかどうかを判別せず、送られた値を「結果入力のルール」で通常どおり検証する（確定前は全買い目が結果未確定で払戻額なし、確定後は的中は払戻額必須、不的中は 0、返還は払戻額なし）。作り直された買い目は、クライアントが結果未入力相当（確定前は結果未確定、確定後は不的中・払戻額 0 相当）で送るため、この検証のみで足りる
    - レース記録の購入額・集合の点数と購入額・集計対象額（寄与額）のサーバー側算出
    - AP-06: 馬券記録アイテムの更新と、生涯収支集計アイテムへの寄与額の差分（更新前の記録アイテムが保持する寄与額の減算・更新後の寄与額の加算）の反映を1つのトランザクション書き込みで行う
      - 日付を変更しない場合: 対象アイテムの更新と集計アイテムの差分更新
      - 日付を変更する場合: 旧 `SK` のアイテムの条件付き削除・新しい `SK`（`createdAt`・`recordId` は既存値を維持）でのアイテム作成・集計アイテムの差分更新
    - 応答: 成功は `200`（更新後の `Record`。日付を変更した場合は新しい `recordKey`）、書き込みの競合は `409`、想定外エラーは `500`

- **概要**:
  - 馬券記録編集画面（`/records/edit?key=<recordKey>`）
    - 画面共通: 画面タイトル「馬券記録を編集」、記録種別バッジ（表示のみ）と記録種別は変更不可の注記、保存アクションバー（「変更を保存」「キャンセル」と注記。レース記録では購入額合計を表示）
    - グローバルサイドバー・グローバルフッター・記録種別バッジ・記録共通入力ブロック・買い目入力ブロック・確認ダイアログを配置する
    - 初期表示
      - クエリ `key` を読み取り（複数あるときは最初の値）、`GET /records/{recordKey}` で記録を取得し、記録種別に応じたフォームを既存の内容が入力済みの状態で表示する。取得中は入力フォームを操作させない
      - `key` が無い・空のときは API を呼ばず、記録が見つからない状態を表示する。`key` の形式はクライアント側で判定しない
      - `400`・`404` は記録が見つからない状態（見出し「記録が見つかりません」と説明・「馬券記録一覧へ戻る」。入力フォーム・保存アクションバー・記録の削除・記録種別バッジは表示しない）、`401` は認証状態を終了してログイン画面（`/login`）へ遷移、`500` は取得できなかったことを示して再読み込みでやり直せるようにする
    - レース記録の編集
      - 日付・競馬場・レース番号・結果の確定状態（確定前／確定後の単一選択と注記）
      - 買い目ヘッダー（件数と上限・購入額合計）、買い目の注記、残り追加可能件数
      - 「＋ 買い目を追加」で買い目入力モーダルを開き、確定内容を通常の買い目または買い目の集合として追加する
      - 通常の買い目の購入額の変更・削除（買い目が0件になる削除は行わせない）
      - 買い目の集合の見出し（券種名・買い方名・指定内容・点数は表示のみ）、1点あたりの購入額の入力（集合内の全買い目の購入額を揃え、小計・購入額合計を再計算）、集合の削除（残る買い目が0件になる場合は行わせない）
      - 集合の「指定内容を変更」: 現在の指定内容を初期値として買い目入力モーダルを開く（指定内容の変更モード）。モーダルには購入額の入力欄があり、指定内容と同時に購入額も変更できる（初期値は呼び出し時点の集合の「1点あたりの購入額」。集合の入力欄に未保存の編集中の値があるときはその現在値）。確定した値が作り直された買い目（置き換わった1件）の購入額になる。確認ダイアログは出さない。成立する点数と買い方で動作が分かれる
        - フォーメーションで変更後が2点以上: 集合は残り、集合内の買い目を変更後の指定内容から作り直す。点数・購入額合計を再計算する
        - ボックス・ながしで変更後が1点以上（1点でも）: 集合は残り、集合内の買い目を変更後の指定内容から作り直す。1点になっても1点だけを含む集合として保持し、集合の見出しも表示したままにする。点数・購入額合計を再計算する
        - フォーメーションで変更後が1点: 集合を解体してその1点を通常の買い目1件に置き換える（元に戻せない）。集合の見出し（集合チップ・買い方名・指定内容・点数・1点あたりの購入額の入力欄・「指定内容を変更」「バラす」・集合の削除）は消え、通常の買い目として表示される。買い目の件数（集合の旧点数 → 1）と購入額合計を再計算する。置き換わった1件の購入額はモーダルで確定した購入額とする。以降は通常の買い目として購入額の変更・削除を個別に行える
        - 結果の扱い（上記すべて共通）: 作り直された（置き換わった）買い目の結果の指定（的中・返還）と払戻額は未入力に戻る。確定前のレース記録は変化しない。確定後のレース記録では的中・返還の指定が外れた状態（不的中）になり、払戻額は破棄される。他の買い目・他の集合の結果は変えない。指定内容が実際に変わらず購入額だけを変えたときは作り直しが起きず、結果も変わらない
        - 「バラす」は従来どおり結果の指定・払戻額を保持する（上記の結果の未入力化の対象外）
      - 集合の「バラす」: 確認ダイアログ（集合を解体して含まれる買い目を通常の買い目にすること、結果の指定と払戻額は保持されること、元に戻せないこと。ボタンは「キャンセル」「バラす」、通常の主操作の見た目）。承認で集合を解体し、含まれていた買い目を結果状態を変えずに通常の買い目として表示する
      - 集合内の買い目は確定後のときだけ見出しの下に1点ずつ表示し（組は表示のみ、結果・払戻額のみ入力可）、個別の追加・削除・購入額の変更の操作を提供しない
      - 確定前 → 確定後は確認なしで切り替え、結果（的中・返還の指定）の入力欄と集合内の買い目を表示する
      - 確定後 → 確定前は確認ダイアログ（すべての買い目が結果未確定になること、入力済みの的中・返還の指定と払戻額が破棄され元に戻せないこと。ボタンは「キャンセル」「確定前に戻す」、通常の主操作の見た目）。承認ですべての買い目を結果未確定に戻し、結果の入力欄と集合内の買い目を非表示にする。キャンセルで確定後のまま
      - 結果の指定（的中・返還の2択、どちらも選ばない買い目は不的中、的中のみ払戻額の入力欄を表示）
    - 簡易記録の編集: 日付・競馬場・購入額・払戻額と入力項目の注記
    - 保存・キャンセル
      - 「変更を保存」でクライアント側チェックを行い、`PUT /records/{recordKey}` に記録全体を送る（`recordType` は変更しない。既存の買い目・集合は識別子を引き継ぐ）。送信中は再押下させない
        - 保存時の構成: 解体した集合（「バラす」、またはフォーメーションの指定内容の変更で1点になったもの）は `betGroups` から外し、含まれていた買い目（後者では残った1件）を `bets` に移す。どちらも同じ構成で送る。ボックス・ながしの集合は、指定内容の変更で1点になっても `betGroups` に残し、1点だけを含む集合として送る
        - 作り直された買い目（置き換わった1件を含む）の結果は、結果未入力相当で載せて送る（確定前なら結果未確定・払戻額なし、確定後なら不的中・払戻額 0 相当）。作り直されなかった他の買い目・集合は現在の結果の指定・払戻額のまま送る
      - `200` は遷移元（馬券記録一覧画面またはホーム画面）に戻る（URL の `key` は書き換えない）、`400` は不正と判定された項目を項目ごとに示す、`401` はログイン画面へ遷移、`404` は記録が見つからない状態を表示、`409` は入力内容を保持したままやり直しを促す、`500` は保存されていないことを示してやり直せるようにする
      - 「キャンセル」で変更を破棄して遷移元に戻る
    - 入力値不正: 保存を実行せず、不正な項目（集合の1点あたりの購入額を含む）の入力枠をエラー表示にして直下に注釈を出す。エラーバナーは出さず、最初の不正な項目へフォーカスを移す。再送信時は直前のエラー表示をクリアする
    - 共通の操作性: 最小タップ領域、視覚順のキーボード操作、確認ダイアログの初期フォーカスと閉じ方、モーダル・ダイアログを閉じたときのフォーカスの戻し先
  - 買い目入力モーダル（編集画面からの起動）
    - 「＋ 買い目を追加」からの起動（件数の上限を超える確定はさせない）
    - 「指定内容を変更」からの起動（指定内容の変更モード）
      - 対象の集合の券種・買い方・指定内容を初期値として開く。券種・買い方は表示のみで変更させない
      - 購入額の入力欄を置く。初期値は呼び出し時点の集合の「1点あたりの購入額」で、指定内容の変更と同時に変更してよい。確定した値が、作り直された買い目（フォーメーションで1点になる場合は置き換わった1件）の購入額になる。見出し・確定ボタンのラベルは追加ではなく変更であることが分かるものにする
      - 購入額のラベルと確定ボタンのラベル（買い方と変更後の点数で切り替える）
        - フォーメーションの集合で変更後が2点以上: ラベルは「1点あたりの購入額」、確定ボタンは「この内容に変更」。プレビューで集合の買い目を作り直すことを示す。確定で対象の集合の買い目を作り直す
        - フォーメーションの集合で変更後が1点: ラベルは「購入額」、確定ボタンは「通常の買い目にして変更」。プレビューで「確定すると通常の買い目になること」と「集合として保持されず元に戻せないこと」を示す。確定で集合を解体して1点を通常の買い目1件（購入額は入力欄の値）に置き換えてモーダルを閉じる
