- **概要**:
  - 共通パーツ「コード入力欄」（本画面がオーナー。ラベル・補助テキスト・入力枠・エラー注釈で構成し、状態（通常／エラー）を持つ。パスワード再設定画面で再設定コード用に文言を差し替えて流用できる形にする）
    - 数字キーボードの入力・ワンタイムコードの自動入力（`type="number"` にしない）、貼り付けを妨げない、自動送信しない
    - 前後・途中の空白の除去と全角数字の半角変換
  - 確認コード入力画面（`/verify-email`）
    - 共通パーツ「未認証画面レイアウト」「グローバルフッター」を用いた画面構成（見出し・案内文・本文スロットのフォーム・「ログイン画面に戻る」導線）
    - メールアドレスの示し方の切り替え（表示時に決め、画面にいる間は切り替えない）
      - 前の画面から引き継いだとき: 「確認するメールアドレス」を表示のみで示す（編集不可・フォーカス順に含めない・読み取り専用のユーザー名として扱う）
      - 引き継いでいないとき（直接の経路・再読み込み・URL を直接開いた場合）: メールアドレス入力欄を出す
      - 示し方ごとの案内文・バナー文言の差し替え
    - 入口ごとの初期フォーカス（表示のみは確認コード欄、入力欄はメールアドレス欄）。表示時に確認コードを自動で再送しない
    - 結果バナー（エラー／案内の 2 種類、1 件のみ表示、自動で消さない）
    - 「確認する」ボタン・「確認コードを再送する」ボタンと再送の補助テキスト（送信中のラベル変更と、両ボタンの非活性化による二重送信・同時実行の防止）
  - 入力値のクライアント側チェックと項目ごとのエラー注釈
    - メールアドレス（入力欄のときだけ。必須・形式・最大文字数）
    - 確認コードの未入力（「確認する」押下時のみ。桁数・文字種は判定しない）
    - 入力値不正のときは結果バナーを出さない。次の操作時にエラー表示とバナーをクリアして出し直す
  - Cognito User Pool の `ConfirmSignUp` の呼び出しと、応答ごとの表示の対応（`email-verification.md` 3.7）
    - 成功: 本文を「確認完了」に差し替え、「ログイン画面へ進む」でログイン画面（`/login`）へ遷移する（自動遷移・自動ログインはしない）
    - コードの誤り・期限切れ・確認済みアカウント・ユーザーが存在しない: すべて同じ「確認失敗」のエラーバナー（再送へ誘導する文言、入力値は残す、入力枠はエラー表示にしない）
    - トリガー関連のエラー: 本文を「確認結果不明」に差し替え、「ログイン画面へ進む」でログイン画面へ遷移する
    - 回数の超過: 回数上限のエラーバナー。それ以外: 通信エラーのエラーバナー
  - Cognito User Pool の `ResendConfirmationCode` の呼び出しと、応答ごとの表示の対応（`email-verification.md` 3.7）
    - 成功・確認済みアカウント・ユーザーが存在しない: 同じ「再送済み」の案内バナーを出し、確認コード欄を空にしてフォーカスを移す
    - 回数の超過: 回数上限のエラーバナー。それ以外: 通信エラーのエラーバナー
  - 確認・再送はメールアドレスだけで実行し、パスワードの入力・ログイン・トークンの保持を伴わない
  - 引き継いだメールアドレスの破棄（ログイン画面への遷移時、「確認完了」「確認結果不明」への切り替え時）。URL・ブラウザのストレージに残さない
  - 結果の表示に原因ごとの差（文言・バナーの種類・色・表示時間）を作らない
  - フォーカス移動（結果バナー、「確認完了」「確認結果不明」の見出し）・スクリーンリーダーへの通知・キーボード操作順・最小タップ領域（`email-verification.md` 3.8）
