## 1. 画面の目的

ログイン後に最初に表示される認証必須画面。これまでに登録した全馬券記録から算出した生涯の収支額と回収率を確認できる（`REQ-SUMMARY-001`）。直近の馬券記録5件を確認し、そこから編集画面を開ける（`REQ-TICKET-006`）。グローバルサイドバーのアカウントメニューを起点に、パスワード変更・ログアウト・アカウント削除に到達できる（`REQ-AUTH-003` / `REQ-AUTH-005`）。集計期間の指定・絞り込み・並び替え、記録の削除、閲覧専用の詳細画面への遷移は本画面に置かない。

## 2. 表示要素

| 要素 | 説明 |
|---|---|
| グローバルサイドバー | ナビゲーション（ホーム・馬券記録一覧）とアカウントメニューの入口。共通パーツ（オーナー: 本画面） |
| 画面タイトル行 | 画面タイトル「ホーム」と、狭い画面幅でのサイドバー開閉トリガー。ヘッダーの帯は設けない |
| 新規登録の導線 | 馬券記録登録画面へ遷移するボタン。記録種別は選ばせない。共通パーツ（オーナー: 本画面） |
| 収支サマリー: 収支額 | 生涯の収支額（`GET /summary` の `balance`）。主数値として最も目立たせる。符号付きで表示し、0のときは均衡であることが分かる表記にする |
| 収支サマリー: 収支の状態チップ | 利益／損失／均衡のいずれかを示すラベル。収支の正負を色だけに頼らず伝えるための併記要素。判定は `balance` の正負で行い、回収率の表示値では判定しない |
| 収支サマリー: 回収率 | 生涯の回収率（`recoveryRate`）。副数値。API が返す小数第1位までの値をそのまま小数第1位まで表示する（例 85.3%、100.0%、0.0%）。整数に丸めず、100%ちょうども 100.0% と表記する。表示側で丸めない・再計算しない。算出できない場合は値の代わりにプレースホルダーと注釈を出す |
| 収支サマリー: 補助情報 | 購入額合計（`totalPurchaseAmount`）・払戻額合計（`totalPayoutAmount`）・記録件数（`recordCount`）。ラベル付きで併記する |
| 直近記録リスト: セクション見出し | 「直近の記録」。リスト領域の役割を示す |
| 直近記録リスト: 一覧への導線 | 馬券記録一覧画面へ遷移するリンク（「すべて見る」） |
| 直近記録リスト: 馬券記録リスト行 | `GET /records/recent?limit=5` の `items` を返ってきた順（日付の新しい順）に最大5件。クライアント側で並べ替えない。1行が1記録を表し、押下で編集画面へ遷移する。共通パーツ（オーナー: 本画面） |
| 馬券記録リスト行: 日付 | `date` |
| 馬券記録リスト行: 競馬場とレース番号 | `venue` と `raceNumber`（例「東京 第11R」）。簡易記録はレース番号を持たないため競馬場のみ |
| 馬券記録リスト行: 記録種別バッジ | `recordType`（レース記録／簡易記録）。結果の確定状態はこのバッジでは表さない。共通パーツ（オーナー: 本画面） |
| 馬券記録リスト行: 購入額 | ユーザーが入力した買い目の購入額合計（`purchaseAmount`）。収支計上対象額（`balanceTargetPurchaseAmount`）とは別物であり、購入額には使わない |
| 馬券記録リスト行: 払戻額 | 確定状態により分岐する（下表）。共通パーツ「収支表示」の書式に従う |
| 馬券記録リスト行: 収支 | 収支計上対象の払戻額と購入額の差（`balanceTargetPayoutAmount − balanceTargetPurchaseAmount`）。確定状態により分岐する（下表） |
| 空状態表示 | データが0件の領域に差し替えて出す、その領域に何が表示されるはずかを説明する表示。共通パーツ（オーナー: 本画面） |
| 確認ダイアログ | アカウント削除など取り消せない操作の実行前確認。共通パーツ（オーナー: 本画面） |
| グローバルフッター | 全画面共通。共通パーツ（オーナー: ログイン画面）のため本画面では設計しない |

馬券記録リスト行の確定状態による表記の分岐:

| 条件 | 購入額 | 払戻額 | 収支 |
|---|---|---|---|
| `recordType` = `RACE` かつ `confirmationStatus` = `PENDING` | `purchaseAmount` を金額で表示（ユーザー入力の確定値のため隠さない） | 「確定前」 | 「確定前」（確定前は収支計上の対象外で算出できない） |
| `recordType` = `RACE` かつ `confirmationStatus` = `CONFIRMED` | `purchaseAmount` を金額で表示 | 金額で表示。的中がなければ「0円」 | 金額で表示 |
| `recordType` = `SIMPLE`（`confirmationStatus` を持たない） | `purchaseAmount` を金額で表示 | 金額で表示 | 金額で表示 |

「確定前」と「0円」は必ず別の表記にする。「0円」は確定済みで払戻がなかったことを表す。

画面に出さない項目: `items[].recordId`, `items[].createdAt`（同一日付の並び順の根拠であり表示はしない）。集計はサーバー側の責務であり、画面では再計算しない。

## 3. インタラクション仕様

### 3.1 遷移・開閉

| 操作・状況 | 動作 |
|---|---|
| サイドバー開閉トリガー押下（サイドバーが常時表示されない画面幅） | サイドバーをドロワーとして開き、背後にオーバーレイを敷く |
| オーバーレイ押下 / 閉じるボタン押下 / Esc | ドロワーを閉じる。開いているアカウントメニューも同時に閉じる |
| サイドバーの項目「ホーム」 | 現在位置。押下しても遷移しない。ドロワー表示時は閉じるだけ |
| サイドバーの項目「馬券記録一覧」 | 馬券記録一覧画面へ遷移。ドロワー表示時は閉じてから遷移する |
| アカウントのアイコンボタン押下 | アカウントメニューを開閉する。メニュー外の押下・Esc で閉じる |
| メニュー「ログイン中のメールアドレス」 | 押下不可。フォーカスを受け取らず、押下しても何も起きない |
| メニュー「パスワード変更」 | パスワード変更画面へ遷移 |
| メニュー「ログアウト」 | 認証状態を終了してログイン画面へ遷移（`REQ-AUTH-003`）。確認は求めない |
| メニュー「アカウント削除」 | 確認ダイアログを開く（`REQ-AUTH-005` #2）。この時点では何も削除しない |
| 新規登録の導線 | 馬券記録登録画面へ遷移。記録種別は選ばせない（登録画面のタブで選ぶ） |
| 直近記録リストの行 | その記録の馬券記録編集画面へ遷移。遷移には `recordKey` を使う（`REQ-TICKET-006` #5） |
| 「すべて見る」 | 馬券記録一覧画面へ遷移（`REQ-TICKET-006` #7） |
| 直近記録リスト内の削除操作 | 置かない。スワイプ削除・長押しメニューも設けない（`REQ-TICKET-006` #6） |
| 直近記録リストのページング・もっと見る | 置かない。5件未満のときは存在する件数だけ表示する（`REQ-TICKET-006` #2 / #3） |

### 3.2 アカウント削除の確認ダイアログ

| 操作・状況 | 動作 |
|---|---|
| 「キャンセル」押下 / オーバーレイ押下 / Esc | ダイアログを閉じる。アカウントも馬券記録も削除しない（`REQ-AUTH-005` #6）。取りやめ手段はこの3つを必ず提供する |
| 「削除する」押下 | `DELETE /me` を1回だけ呼ぶ。実行中は両ボタンを押下不可にし、ラベルを「削除中…」に変える（二重送信の防止） |
| `204` を受け取った | 認証状態を終了し、ログイン画面へ遷移する（`REQ-AUTH-005` #5） |
| `401` を受け取った | 認証状態を終了し、ログイン画面へ遷移する（`REQ-AUTH-004`） |
| `500` を受け取った | ダイアログを閉じずにエラーメッセージを表示する。ボタンを押下可能に戻し、同じ操作をやり直せる状態にする |

ダイアログ本文では、馬券記録もすべて削除されることと、削除を取り消せないことの両方を明示する（`REQ-AUTH-005` UI設計上の留意点）。初期フォーカスは取りやめボタンに置く。

### 3.3 データの状態による表示の分岐

| 操作・状況 | 動作 |
|---|---|
| `recordCount` が0 かつ `items` が空 | 収支サマリー領域と直近記録リスト領域をそれぞれ空状態表示に差し替える（`REQ-SUMMARY-001` #8 / `REQ-TICKET-006` #8）。画面全体を空状態にしない。差し替え時もセクション見出しと「すべて見る」は残し、領域の位置が分かる状態を保つ |
| `recoveryRate` が `null`（購入額合計が0） | 回収率の値を出さずプレースホルダーに置き換え、直下に「購入額合計が0円のため回収率を算出できません」の注釈を出す（`REQ-SUMMARY-001` #5）。このとき収支額は0のため均衡の表記・状態チップになる。「確定前のレース記録だけを登録している」場合に起こる |
| `items` に `confirmationStatus` = `PENDING` の行がある | 該当行の払戻額・収支を「確定前」と表記する。購入額は表示する |
| 収支の正負の伝達 | 色だけで伝えない。符号と状態チップを必ず併用する（`REQ-SUMMARY-001` UI設計上の留意点） |
| 利益・損失・均衡の判定 | 収支額（`balance`）の正負で決める（正は利益、負は損失、0は均衡）。状態チップ・色・符号はすべてこの判定に従い、丸めた回収率では決めない。回収率が 100.0% と表示されていても、`balance` が負なら損失、正なら利益の表記にする |
| 回収率の表示値 | `recoveryRate` を小数第1位まで表示する（例 85.3%、100.0%）。API が丸めた値を返すため、画面では再計算・再丸めをしない |

`recordCount` = 0 のとき回収率の表示自体を出さないため、空状態と「回収率が算出できない状態」は同時に起こらない。

### 3.4 読み込み中とエラー

収支サマリー領域と直近記録リスト領域は別々のAPIを呼ぶため、読み込みとエラーを領域ごとに独立して扱う。片方が失敗してももう片方は表示する。

| 操作・状況 | 動作 |
|---|---|
| 読み込み中 | 対象領域だけをプレースホルダーに差し替える。画面全体をブロックしない |
| `GET /summary` / `GET /records/recent` が `500` | 対象領域をエラー表示に差し替え、「再読み込み」ボタンを置く。押下で当該APIのみ再取得する |
| いずれかのAPIが `401` | 画面を表示せずログイン画面へ遷移する（`REQ-AUTH-004`） |
| `DELETE /me` の完了 | 認証状態を終了してログイン画面へ遷移する |

### 3.5 共通の操作性

- 押下できる要素は最小タップ領域を下回らない。記録種別バッジは表示専用のため対象外。
- キーボード操作の順序は画面の視覚順（タイトル行 → 新規登録 → サマリー → リスト行 → フッター）に合わせる。
- ドロワー・アカウントメニュー・確認ダイアログを開いている間は背後の要素にフォーカスを移さない。閉じたときは開く操作を行った要素にフォーカスを戻す。
- 馬券記録リスト行はホバーで面の見え方を変え、選択できる行であることを示す（`REQ-TICKET-006` UI設計上の留意点）。

## 4. 共通パーツ

本画面は次の7件のオーナーであり、Figmaの「共通パーツ（オーナー: ホーム画面）」フレームのコンポーネントが唯一の正となる。他画面はインスタンスとして配置し、再デザインしない。

| パーツ名 | 役割 | 他画面で流用する際の注意 |
|---|---|---|
| グローバルサイドバー（アカウントメニューを含む） | サービス名・ナビゲーション項目（ホーム／馬券記録一覧）・アカウントメニューの入口。メニュー項目はログイン中のメールアドレス（押下不可の表示のみ）／パスワード変更／ログアウト／アカウント削除の順 | 現在位置のハイライトを当該画面の項目に付け替えるだけにする。項目の追加・順序変更・アカウント削除の位置変更は行わない。アカウント削除は必ず最後に置き、日常操作から視覚的に分離した状態を保つ（`REQ-AUTH-005` UI設計上の留意点） |
| 記録種別バッジ | `recordType` が `RACE` なら「レース記録」、`SIMPLE` なら「簡易記録」を示す表示専用のラベル | 2値のみ。結果の確定状態をこのバッジで表さない（確定状態は払戻額・収支の表記で表す） |
| 収支表示 | 収支額を符号付きで示す。0は均衡、確定前は金額を出さず「確定前」、算出不可はプレースホルダーと表記する | 色だけで正負を伝えない。主数値として使う場面では状態チップ（利益／損失／均衡）を必ず併用する。リスト行内では符号で判別できる |
| 馬券記録リスト行 | 1記録を日付・競馬場とレース番号・記録種別バッジ・購入額・払戻額・収支で表す行。行全体が押下可能で編集画面へ遷移する | 行の構成要素と確定状態による表記の分岐は変えない。削除などの行内操作を足す場合は独立した操作として置き、行全体の押下と競合させない |
| 新規登録の導線 | 馬券記録登録画面へ遷移するプライマリボタン | 記録種別を選ばせない（登録画面のタブで選ぶ）。1画面に1つだけ置く |
| 空状態表示 | 見出し・説明・アクションスロットで、その領域に何が表示されるはずかを伝える | データが0件の領域だけを差し替える。画面全体を空状態にしない。アクションを置く場合はスロットに「新規登録の導線」パーツをそのまま入れる。本画面ではアクションスロットを使わない（上部に新規登録の導線があるため導線を重複させない） |
| 確認ダイアログ | 取り消せない操作の実行前確認。見出し・本文・注意ブロック・取りやめ／破壊的操作のボタン行で構成する | 何が一緒に消えるかと取り消せないことを本文と注意ブロックで必ず示す。初期フォーカスは取りやめボタンに置く。実行中は両ボタンを押下不可にする。取りやめ手段はボタン・オーバーレイ押下・Esc の3つを提供する |

## 補足: 本画面の設計が前提としている未解決点

| # | 内容 |
|---|---|
| 1 | グローバルフッターはオーナーがログイン画面であり、まだデザインされていない。Figmaでは領域のプレースホルダーのみを置いている |

以下は Cognito が担う仕様として解決済み。

- アカウントメニューに表示する「ログイン中のメールアドレス」は、Cognito User Pool が発行する ID トークンに含まれるため、API を呼ばずクライアント側でトークンから取得する（`designs/api.md`）
- ログアウトはブラウザから Cognito に対して行う操作であり、本 API にエンドポイントは存在しない。クライアント側で認証状態（トークン）を終了する操作として実装する
