## 1. 画面の目的

レース記録の買い目を入力するモーダル。馬券記録登録画面・馬券記録編集画面の「買い目を追加」から開き、買い方と券種を選び、チェックボックスの表で組合せを指定する。確定すると呼び出し元の画面に買い目が追加される。

買い方の選択肢は「通常・フォーメーション」「ボックス」「ながし」の3つ。業務上の買い方である「通常」と「フォーメーション」は、チェックボックスの表の構成が同じため、画面上は1つの選択肢にまとめている。「通常・フォーメーション」では、成立した点数が1点なら通常の買い目1件、2点以上ならフォーメーションの買い目の集合1件として追加される。ボックス・ながしは成立した点数が1点でも、買い目の集合1件として追加される（`business-rules.md` の「買い目の集合」項番18 (d)）。入力した内容から成立する買い目は、チェックを変えるたびに追従して表示され、確定前に内容を確認できる（`REQ-TICKET-001` UI設計上の留意点）。

本モーダルには2つの開き方がある。

| 開き方 | 呼び出し元の操作 | 用途 |
|---|---|---|
| 追加モード | 「買い目を追加」 | 新しい買い目または買い目の集合を追加する。ここまでの説明はこのモードのもの |
| 指定内容の変更モード | 買い目の集合の「指定内容を変更」（馬券記録登録画面・馬券記録編集画面） | 既存の買い目の集合の指定内容を変更する。現在の指定内容を初期値として開き、券種・買い方は変更させない（`business-rules.md` の「買い目の集合」項番1・2）。指定内容と同時に「1点あたりの購入額」も変更してよい（同項番11）。詳細は 3.2.2 |

## 2. モーダルの構成

上から順に次の要素を並べる。

| # | 要素 | 役割 |
|---|---|---|
| 1 | オーバーレイ | モーダル背後に敷く。呼び出し元の画面が透けて見える。押下で取りやめる |
| 2 | ヘッダー | 見出し「買い目を追加」と閉じるボタン。指定内容の変更モードでは、追加ではなく変更であることが分かる見出しにする（3.2.2） |
| 3 | 買い方の選択 | 通常・フォーメーション／ボックス／ながしの3択。指定内容の変更モードでは、開いた集合の買い方を表示のみとし、切り替えさせない |
| 4 | 券種の選択 | 選択式。選択中の買い方で成立しない券種は選択させない。指定内容の変更モードでは、開いた集合の券種を表示のみとし、切り替えさせない |
| 5 | ながしのパターンの選択 | 買い方がながしのときのみ表示する。選べるパターンは券種によって変わる |
| 6 | 組合せ入力表 | 番号の行 × 役割の列のチェックボックス表（3節） |
| 7 | 購入額の入力 | 追加モードでは、成立が1点で通常の買い目として追加されるときは「購入額」、それ以外（2点以上、またはボックス・ながし）は「1点あたりの購入額」とラベルを切り替える。指定内容の変更モードでも入力欄を置く。初期値は変更前の集合の「1点あたりの購入額」で、指定内容の変更と同時に変更してよい。ラベルは、成立が1点でフォーメーションの集合が通常の買い目になるときは「購入額」、それ以外は「1点あたりの購入額」とする（3.2.2） |
| 8 | 成立した買い目 | 指定内容・点数・購入額の合計・組合せの一覧と、通常の買い目／買い目の集合のどちらとして追加されるか。チェックに追従して更新される。指定内容の変更モードでは、変更後にどうなるか（集合の買い目を作り直す／通常の買い目になる）と、作り直しに伴う結果状態・払戻額の注記を示す（3.2.2） |
| 9 | フッター操作 | 確定と取りやめ。確定ボタンのラベルは状況に応じて切り替える |

## 3. 組合せ入力表

### 3.1 表の構造

**番号の行 × 役割の列**という構造で、交差するマスのチェックボックスをチェックして組合せを指定する。

| 項目 | 内容 |
|---|---|
| 行 | 番号。選択対象が馬番の券種は馬番の範囲、枠番の券種（枠連）は枠番の範囲で行を並べる。範囲は `business-rules.md` の「レース番号・馬番・枠番の取りうる値」に従う |
| 列 | 買い方に応じて意味と数が変わる（3.2） |
| 更新 | チェックを変えるたびに「成立した買い目」が追従して更新される |

### 3.2 買い方ごとの列の構成

| 買い方 | 列の構成 | 列ごとの選択数 |
|---|---|---|
| 通常・フォーメーション | 券種の選択数ぶんの列。着順を区別する券種は着順（1着・2着・3着）、区別しない券種は順序を表さない見出しにする。どちらに該当するかは `business-rules.md` の「券種の属性」の「着順の区別」に従う | 各列で複数選択できる。各列から1つずつ選んだ組合せが買い目になる。ただし選択数が1の券種（単勝・複勝）は列で1つだけ選択できる |
| ボックス | 列は1つだけ。着順の概念がないため、選択した番号の集合だけを指定する | 複数選択できる |
| ながし | 「軸」「相手」の2列 | 軸列は選択数に上限がある（3.3）。相手列は複数選択できる |

券種の選択数（1〜3）は `business-rules.md` の「券種の属性」に従う。選択数が1の券種（単勝・複勝）は列が1つになる。ボックス・ながし・フォーメーションでは成立しない（`business-rules.md` の「券種 × 買い方 のマトリクス」）ため、次のように扱う。

- 買い方がボックス・ながしのときは、単勝・複勝を券種として選択させない。
- 買い方が「通常・フォーメーション」のときは単勝・複勝を選択できるが、列で1つだけ選択できるようにする。成立は常に1点となり、通常の買い目として追加される。上限に達した状態で他のマスを選択すると、ながしの軸列（3.3）と同じくチェックがそちらに移る。

### 3.2.1 追加モードでの追加のされ方

買い方と成立した点数で、追加されるものが決まる（`business-rules.md` の「買い目の集合」項番18 (d)）。

| 買い方 | 成立した点数 | 追加のされ方 | 購入額のラベル |
|---|---|---|---|
| 通常・フォーメーション | 1点（各列で1つずつ選択） | 通常の買い目1件 | 購入額 |
| 通常・フォーメーション | 2点以上 | フォーメーションの買い目の集合1件 | 1点あたりの購入額 |
| ボックス・ながし | 1点以上 | 買い目の集合1件（1点でも、1点だけを含む集合として追加する） | 1点あたりの購入額 |

どちらとして追加されるかは、成立した買い目のプレビューに表示する。確定ボタンのラベルも「この買い目を追加」と「この買い目の集合を追加」で切り替える。ボックス・ながしは点数にかかわらず「この買い目の集合を追加」とする。

### 3.2.2 「指定内容を変更」から開いたとき（指定内容の変更モード）

買い目の集合の指定内容を変更するモード。現在の指定内容を初期値としてチェックを入れた状態で開く。券種・買い方は表示のみで変更させない。これは `business-rules.md` の「買い目の集合」項番1・2に従う。

購入額の入力欄も置く。初期値は変更前の集合の「1点あたりの購入額」で、指定内容の変更と同時に変更してよい（項番11）。変更後の値が、作り直される各買い目の購入額になる。

確定時の扱いは、開いた集合の買い方と、変更後に成立する点数で決まる。

| 開いた集合の買い方 | 変更後に成立する点数 | 確定したときの結果 | 購入額のラベル | 確定ボタンのラベル |
|---|---|---|---|---|
| フォーメーション | 2点以上 | 集合の買い目を変更後の指定内容から作り直す。各買い目の購入額は入力欄の値になる（項番11） | 1点あたりの購入額 | この内容に変更 |
| フォーメーション | 1点 | 集合を解体し、その1点を通常の買い目1件に置き換える（項番18 (a)）。復元はできない。置き換わった買い目の購入額は入力欄の値になる（項番18 (b)） | 購入額 | 通常の買い目にして変更 |
| ボックス・ながし | 1点以上 | 集合の買い目を変更後の指定内容から作り直す。1点になっても集合は解体せず、1点だけを含む集合のまま保持する（項番12・18 (c)）。各買い目の購入額は入力欄の値になる | 1点あたりの購入額 | この内容に変更 |

作り直された（置き換わった）買い目の結果状態・払戻額は、上表のどの行でも未入力に戻る（項番11、「結果入力のルール」の「買い目の集合の作り直し・置き換えに伴う結果の扱い」）。呼び出し元のレース記録の結果の確定状態が確定前なら変化はない。確定後なら、的中・返還の指定が外れた状態（不的中）になり、払戻額は破棄される。指定内容が実際に変わらず（成立する組合せが変わらず）購入額だけを変えたときは作り直しが起きないため、結果状態・払戻額は変わらない。

確定前にプレビュー領域で次のことが分かるようにする。確定ボタン押下で、そのまま変更が反映される。

- フォーメーションで1点になるとき: 「この内容で確定すると通常の買い目になる」ことを、成立した点数と同じ領域に示す（追加モードで1点のときに「通常の買い目として追加」と示すのと同じ考え方）。あわせて、集合として保持されなくなり元に戻せないことを短く添える。確定ボタンのラベルも「通常の買い目にして変更」に切り替える。
- 買い目が作り直されるとき（フォーメーションの1点を含む、上表のすべての行）: 「結果（的中・返還）と払戻額は未入力に戻る」旨の短い注記をプレビュー領域に出す。この注記は、呼び出し元のレース記録の結果の確定状態が確定後のときだけ表示し、確定前は変化がないため出さない。成立する組合せが変わらないときも出さない。呼び出し元は、結果の確定状態をモーダルに渡す。

注記をプレビュー領域に出す判断理由: 結果が消える影響は確定後に気づくと戻れないため確定前に見える位置に置くが、モーダルの構成（ダイアログの追加など）は変えず、1点になる表示と同じ領域に収めるため。

### 3.3 ながしの軸列の選択数の制御

軸列で選択できる数は、選択中のながしのパターンによって決まる。上限に達した状態で他のチェックボックスを選択すると、**チェックがそちらに移動する**（エラーにはしない）。

| ながしのパターン | 軸列の選択数 | 上限に達した状態で他を選択したとき |
|---|---|---|
| 軸1頭系のパターン | 1つ | 既存のチェックが外れ、新しく選択したマスにチェックが移る |
| 軸2頭系のパターン | 2つ | 最も古いチェックが外れ、新しく選択したマスにチェックが移る |

どのパターンが軸1頭系・軸2頭系に該当するか、および券種ごとに選べるパターンは `business-rules.md` の「ながしのパターン」に従う。

### 3.4 枠連のゾロ目

枠連でゾロ目（同一枠番同士の組合せ）を組合せに含められるかは買い方によって異なる（`business-rules.md` の「枠連のゾロ目のルール」）。この制御は実装時に扱い、デザイン上の表現は設けない。

## 4. 成立した買い目のプレビュー

組合せ入力表の下（`md` 以上では表の右）に配置し、チェックを変えるたびに追従して更新される。

| 表示項目 | 内容 |
|---|---|
| 指定内容 | 入力した買い方の指定内容の文字列表示。表記は `business-rules.md` の「買い方の指定内容の表記ルール」に従う |
| 点数 | 指定内容から成立する買い目の件数。算出は `business-rules.md` の「点数（買い目数）の算出ルール」に従う |
| 購入額の合計 | 1点あたりの購入額 × 点数 |
| 組合せの一覧 | 成立する買い目の組合せを列挙する。表記は `business-rules.md` の「組合せの表記ルール」に従う |

買い目の件数が、呼び出し元のレース記録が持てる上限（`business-rules.md` の「エンティティの関係と件数の制限」）を超える場合は確定させない。その旨をプレビュー領域で示す。

## 5. インタラクション仕様

### 5.1 選択と入力

| 操作・状況 | 動作 |
|---|---|
| 買い方を切り替える | 組合せ入力表の列構成が切り替わる。ながしを選んだときはながしのパターンの選択欄が現れる。券種の選択肢も、切り替え後の買い方で成立するものに絞られる |
| 券種を切り替える | 列の数（選択数）と行の番号の範囲が切り替わる。着順を区別するかどうかで列の見出しも変わる |
| ながしのパターンを切り替える | 軸列で選択できる数が変わる。選択済みの数が新しい上限を超える場合は、超過分のチェックを外す |
| チェックボックスを操作する | 成立した買い目のプレビューが追従して更新される |
| 軸列で上限を超えて選択する | エラーにせず、チェックを新しく選択したマスへ移す（3.3） |
| 成立しない券種・買い方の組み合わせ | 選択肢として提示しない。エラーとして出すのではなく選択させない形で防ぐ（`REQ-TICKET-001` #5） |

### 5.2 確定と取りやめ

| 操作・状況 | 動作 |
|---|---|
| 確定ボタン押下（追加モード） | 呼び出し元の画面に買い目を追加してモーダルを閉じる。「通常・フォーメーション」は成立した点数に応じて通常の買い目1件またはフォーメーションの買い目の集合1件、ボックス・ながしは点数にかかわらず（1点でも）買い目の集合1件として追加する（3.2.1） |
| 確定ボタン押下（指定内容の変更モード / フォーメーション2点以上、ボックス・ながし（1点を含む）） | 呼び出し元の画面の該当集合の買い目を、変更後の指定内容と入力欄の購入額から作り直してモーダルを閉じる。ボックス・ながしは1点でも集合のまま保持する（3.2.2） |
| 確定ボタン押下（指定内容の変更モード / フォーメーション / 1点） | 呼び出し元の画面の該当集合を解体し、その1点を通常の買い目1件（購入額は入力欄の値）に置き換えてモーダルを閉じる（3.2.2） |
| 指定内容の変更モードで購入額だけを変更して確定 | 指定内容が変わらないときは買い目を作り直さず、購入額だけを変更する。結果状態・払戻額は変わらない（3.2.2） |
| 取りやめボタン押下 / 閉じるボタン押下 / オーバーレイ押下 / Esc | モーダルを閉じ、何も追加・変更しない |
| 組合せが未指定・不足のとき | 確定させない。成立する買い目が0点の状態では追加できない |
| 件数の上限を超えるとき | 確定させない（4節） |

### 5.3 共通の操作性

- 押下できる要素（買い方の選択・券種の選択・ながしのパターンの選択・購入額の入力・確定・取りやめ・閉じる）は最小タップ領域（`tap-target-min`）を下回らない。
- **チェックボックスの表のみ、この最小タップ領域の例外とする。** 行数が多く列も複数あるため、チェックボックス自体は最小タップ領域より小さい。代わりに行と列が交差するセル全体を押下領域とし、セルの面積を確保することで誤タップを避ける。
- 行数が少ない券種（枠連）では行の高さとチェックボックスを広く取る。
- `base` では18行すべてを縦に並べ、モーダル全体を縦スクロールして操作する。`md` 以上では表の内部を縦スクロールする領域とし、モーダルの高さを画面内に収める。
- モーダルを開いている間は背後の要素にフォーカスを移さない。閉じたときは開く操作を行ったボタンにフォーカスを戻す。

## 6. 共通パーツ

本モーダルは共通パーツのオーナーではなく、流用する共通パーツもない。モーダル内の入力要素は本モーダル固有のものである。

呼び出し元の画面が持つ共通パーツ「買い目入力ブロック」（オーナー: 馬券記録登録画面）とは役割が分かれている。券種・組合せの指定は本モーダルが担い、追加後の買い目の表示と購入額・結果（的中・返還）・払戻額の扱いは買い目入力ブロックが担う。

## 7. 状態バリエーション

| # | 状態 | 画面サイズ |
|---|---|---|
| 1 | 買い方=通常・フォーメーション / 1点（各列1つ選択。通常の買い目として追加） | base |
| 2 | 買い方=ボックス（列は1つ、複数選択） | base |
| 3 | 買い方=ながし（軸列・相手列、ながしのパターンの選択欄あり） | base |
| 4 | 買い方=通常・フォーメーション / 2点以上（各列複数選択。フォーメーションとして追加） | base / md以上 |
| 5 | 枠連（行が枠番の範囲になる） | base |

`md` 以上は代表として買い方=通常・フォーメーションの2点以上の状態を用意している。買い方ごとの表の違いは `base` 側で網羅している。

上表は追加モードの状態である。指定内容の変更モード（見出し・買い方と券種の表示のみ・購入額入力・確定ボタンのラベル・1点になるときのプレビュー表示・結果状態と払戻額の注記）には専用のフレームを設けない。この部分は本ファイル（3.2.2）の記述が正となる（補足 #1）。

## 8. 使用したAPIとの対応

本モーダルは単独でAPIを呼ばない。確定した内容は呼び出し元の画面が保持し、記録の登録・更新時に送信する。

| 買い方 | 対応するスキーマ | 備考 |
|---|---|---|
| 通常・フォーメーション（1点） | `BetInput` | 通常の買い目1件として `bets` に追加される |
| 通常・フォーメーション（2点以上） | `BetGroupInput` + `FormationSpec` | フォーメーションの買い目の集合1件として `betGroups` に追加される。着順ごとの選択集合を持つ |
| フォーメーションの指定内容の変更（2点以上） | `BetGroupInput` + `FormationSpec` | 該当集合の指定内容と1点あたりの購入額を置き換えて `betGroups` に送る |
| フォーメーションの指定内容の変更（1点） | `BetInput` | 集合は `betGroups` から外し、その1点を通常の買い目（購入額は入力欄の値）として `bets` に送る（`RaceRecordInput` の記述に従う） |
| ボックス（1点を含む） | `BetGroupInput` + `BoxSpec` | 買い目の集合1件として `betGroups` に追加される。追加時に1点でも集合として追加する。変更の結果が1点でも `betGroups` に送る |
| ながし（1点を含む） | `BetGroupInput` + `NagashiSpec` | 同上。軸・相手・着順固定・マルチの指定を持つ |

画面上の選択肢をまとめただけで、APIとデータ上の買い方の区別（通常の買い目とフォーメーション）は変えていない。

点数（`betCount`）と集合の購入額（`amount`）はサーバー側で算出されるため送らない。モーダル上の点数表示は確定前の確認用に画面側で算出した値である。
