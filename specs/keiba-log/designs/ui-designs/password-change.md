## 1. 画面の目的

ログイン中のユーザーが、現在のパスワードを確認したうえで新しいパスワードに変更する認証必須画面（`REQ-AUTH-008`）。グローバルサイドバーのアカウントメニュー「パスワード変更」から遷移する。現在のパスワードの入力を必須とし、正しくない場合はパスワードを更新しない（#4, #5。`business-rules.md` のアカウントのルール #7）。変更が完了しても操作した端末の認証状態は維持し（#8）、他の端末では新しいパスワードでの再ログインが必要になる（#2）。パスワード再設定メールに記載された再設定コードを入力して再設定する経路（現在のパスワード入力を伴わない）は本画面の対象外で、パスワード再設定画面が担当する。

## 2. 表示要素

### 2.1 入力状態（通常・送信中・各エラー）

| 要素 | 説明 |
|---|---|
| グローバルサイドバー | 共通パーツ。`md` 未満はドロワー（タイトル行の開閉トリガーから開く）。ナビ項目「ホーム」「馬券記録一覧」のどちらも現在位置にしない（本画面はアカウントメニューから遷移する画面のため） |
| 画面タイトル行 | 画面タイトル「パスワード変更」と、`md` 未満でのサイドバー開閉トリガー。他の認証必須画面と同じ構成 |
| フォーム単位のメッセージ | 特定の項目に紐付かない結果（試行回数超過による制限・通信／サーバーエラー）を伝えるメッセージ。フォームの先頭に、該当する結果のときだけ表示する |
| 「現在のパスワードの確認」セクション | 見出し・補助テキストと現在のパスワード入力欄。パスワード入力ブロックの外側に置き、見出し・ラベルで新しいパスワードと明確に区別する。強度要件の提示は付けない（既存パスワードの入力のため） |
| 「新しいパスワードの設定」セクション | 見出し・補助テキストとパスワード入力ブロック |
| パスワード入力ブロック | 共通パーツ（オーナー: アカウント登録画面）。新しいパスワードの入力・強度要件の提示・新しいパスワード（確認）の入力をまとめたブロック。強度要件の項目とプレースホルダーはオーナーの定義のまま使う |
| 他の端末のログイン状態に関する注記 | 変更すると、この端末以外では新しいパスワードでログインし直す必要があること、他の端末への反映には時間がかかる場合があることを送信前に伝える（#2） |
| 入力フィールドのエラー注釈 | 入力値が不正な項目の直下に表示する、その項目固有の指摘文言 |
| 「変更する」ボタン | フォームを送信する主操作。送信中はラベルを変え非活性にする |
| 「キャンセル」ボタン | 変更せずに前の画面へ戻る副操作。送信中は非活性にする |
| グローバルフッター | 共通パーツ（オーナー: ログイン画面） |

### 2.2 変更完了状態

パスワードの変更（3.2 の①）が成功した後は、続く処理の結果にかかわらず必ず変更完了系の状態を表示し、「パスワードを変更しました」と伝える。入力フォームは表示しない。サイドバー・画面タイトル行・フッターは入力状態と同じく表示する。

| 要素 | 説明 |
|---|---|
| ステータスアイコン | 変更が完了したことを示すアイコン |
| 完了の見出し | 「パスワードを変更しました」。3種類の完了状態で共通 |
| 完了案内 | 状態に応じた案内。通常の完了では、この端末ではこのまま利用を続けられること・他の端末では新しいパスワードでログインし直す必要があること（反映に時間がかかる場合があること）を伝える |
| 注意メッセージ（他の端末のログイン解除が未完了） | 他の端末のログイン状態を解除できなかったときだけ表示する。パスワードの変更自体は完了していることを併記する |
| 「ホームへ進む」ボタン | ホーム画面へ遷移する主操作。通常の完了・他の端末のログイン解除が未完了のときに表示する |
| 「もう一度試す」ボタン | 他の端末のログイン状態の解除をやり直す副操作。他の端末のログイン解除が未完了のときだけ表示する |
| 「ログイン画面へ進む」ボタン | ログイン画面へ遷移する主操作。再ログインが必要なときだけ表示する（「ホームへ進む」の代わり） |

| 完了状態 | 表示する要素 |
|---|---|
| 変更完了 | アイコン・見出し・完了案内・「ホームへ進む」 |
| 変更完了（他の端末のログイン解除が未完了） | アイコン・見出し・完了案内（この端末では利用を続けられること）・注意メッセージ・「ホームへ進む」・「もう一度試す」 |
| 変更完了（再ログインが必要） | アイコン・見出し・完了案内（パスワードは変更済みであること、新しいパスワードでログインし直す必要があること）・「ログイン画面へ進む」 |

## 3. インタラクション仕様

### 3.1 遷移・開閉

| 操作・状況 | 動作 |
|---|---|
| 画面を開く（未認証） | 画面を表示せずログイン画面へ遷移する（`REQ-AUTH-004`） |
| サイドバー開閉トリガー押下（`md` 未満） | サイドバーをドロワーとして開く。開閉・項目選択の挙動は共通パーツ（`home.md` 3.1）に従う |
| サイドバーのナビ項目「ホーム」「馬券記録一覧」 | 各画面へ遷移する。入力途中の値は破棄する（確認は求めない） |
| アカウントメニュー「パスワード変更」 | 本画面を開いている状態のため遷移しない。ドロワー表示時はメニューとドロワーを閉じるだけ |
| 「キャンセル」押下 | 変更せず前の画面へ戻る。前の画面が存在しない（URLを直接開いた）場合はホーム画面へ遷移する |

### 3.2 送信と結果

パスワードの変更はブラウザから Cognito に直接リクエストする（本APIにエンドポイントはない）。処理は ①パスワードの変更 → ②全端末のログイン状態の解除 → ③新しいパスワードでの再ログイン（この端末のログイン状態の差し替え）の順に行う。手順の詳細は `designs/architecture.md` 5.1 を参照する。

①が成功した時点でパスワードは変更済みのため、②③が失敗しても「変更できなかった」とは伝えない。

| 操作・状況 | 動作 |
|---|---|
| 「変更する」押下 | 入力値のクライアント側チェック（3.3）を行う。不正がなければ、送信前にこの端末のログイン状態の有効期限を確認する（下の「認証切れ」）。期限内であれば送信中状態に切り替えて①を実行する。送信中状態は①〜③がすべて終わるまで続け、その間は「変更する」「キャンセル」を押下できないようにする（二重送信の防止） |
| 認証切れ（送信前の確認でログイン状態の有効期限が切れている） | ①を実行せず、認証状態を終了してログイン画面へ遷移する（`REQ-AUTH-004`）。認証切れの判定はこの送信前の確認で行う（①の失敗結果からは判定しない） |
| ①現在のパスワードが正しくない | 送信前の確認で期限内だったうえで①が認証エラーで失敗した場合に、この扱いとする。パスワードは更新されていない（#5）。現在のパスワード欄をエラー表示にし、直下に正しくない旨の注釈を出す。現在のパスワード欄の入力値をクリアしてフォーカスを移す。新しいパスワード欄の入力値は保持する |
| ①新しいパスワードがポリシーに適合しない | パスワードは更新されていない。新しいパスワード欄をエラー表示にし、直下に注釈を出す（クライアント側チェックをすり抜けた場合の保険）。注釈の文言はパスワード入力ブロックの定義（`signup.md` 3.3「パスワードがポリシーに合わないと返された」）に従う。フォーム単位のメッセージは出さず、入力値を保持する |
| ①試行回数超過による制限 | パスワードは更新されていない。フォーム単位のメッセージで、試行回数が上限に達したため時間をおいて再度試す必要があることを伝える。項目の入力枠はエラー表示にしない。入力値を保持し、ボタンは押下可能に戻す |
| ①通信エラー・サーバーエラー | パスワードは更新されていない。フォーム単位のメッセージで変更できなかったことを伝え、入力値を保持したままボタンを押下可能に戻し、やり直せるようにする |
| ①②③がすべて成功 | パスワードが更新され（#1）、他の端末のログイン状態は解除され（#2）、この端末のログイン状態は維持される（#8）。「変更完了」に切り替える |
| ①成功・②失敗・③成功 | パスワードは変更済み、この端末のログイン状態は維持されている。他の端末のログイン状態は解除できていない。「変更完了（他の端末のログイン解除が未完了）」に切り替える。②が失敗しても③は実行する（この端末のログイン状態を確実に差し替えるため） |
| 「もう一度試す」押下 | ②③をやり直す。実行中は「もう一度試す」のラベルを変えて非活性にし、「ホームへ進む」も押下できないようにする。②③が成功すれば「変更完了」に、②が再び失敗すれば同じ状態のまま、③が失敗すれば「変更完了（再ログインが必要）」に切り替える。やり直しは本画面を表示している間だけ可能で、「ホームへ進む」で離れた後は、もう一度パスワードを変更することで解除できる |
| ①成功・③失敗 | パスワードは変更済みだが、この端末のログイン状態を維持できない。認証状態を終了し、「変更完了（再ログインが必要）」に切り替える。ログイン画面へは自動で遷移させず、パスワードが変更済みであることを確認できるようにしてから「ログイン画面へ進む」で遷移させる。この状態でサイドバーのナビ項目を操作した場合は、認証必須画面へのアクセスとしてログイン画面へ遷移する（`REQ-AUTH-004`） |
| ①成功・②③とも失敗 | 「変更完了（再ログインが必要）」の表示に加えて、他の端末のログイン解除が未完了である旨の注意メッセージを出す。「もう一度試す」は表示せず、ログインし直した後にもう一度パスワードを変更すると解除できることを本文で伝える |
| 「ホームへ進む」押下 | ホーム画面へ遷移する |
| 「ログイン画面へ進む」押下 | ログイン画面へ遷移する |

### 3.3 入力値のチェックと不正時の表示

| 操作・状況 | 動作 |
|---|---|
| 入力値が不正（現在のパスワードの未入力、新しいパスワードの未入力・値の制限違反、確認入力の未入力・不一致のいずれか。値の制限は `business-rules.md` が正） | パスワードを更新せず、不正な項目の入力枠をエラー表示にし、直下にその項目固有の注釈を出す（#9） |
| 現在のパスワードが未入力 | 現在のパスワード欄をエラー表示にする（#4）。現在のパスワード欄には値の制限（文字数・文字種）のチェックは行わず、必須チェックのみ行う（正誤の判定は Cognito に委ねる） |
| 新しいパスワードが強度要件のいずれかを満たさない・最大文字数を超える | 新しいパスワード欄をエラー表示にし、直下に注釈を出す。注釈の文言と強度要件の一覧の扱い（達成済み・未達の表示を残す、最大文字数は一覧に載せず注釈で扱う）はパスワード入力ブロックの定義（`signup.md` 3.3）に従う |
| 新しいパスワードと確認入力が一致しない | 確認入力欄をエラー表示にし、一致しないことを示す注釈を出す |
| 新しいパスワードが現在のパスワードと同じ | 本画面では禁止しない（要件・業務ルールに制限がないため） |
| エラー表示の方式 | 入力値不正は項目ごとの表示に統一し、フォーム単位のメッセージは出さない。最初の不正な項目へフォーカスを移す |
| 再送信時 | 直前の項目ごとのエラー表示とフォーム単位のメッセージを送信時にクリアし、新しい結果に応じて出し直す |

強度要件の提示（入力中の達成状態の表示）はパスワード入力ブロックの仕様（`signup.md` 3.2）に従う。

### 3.4 共通の操作性

- 押下できる要素はすべて最小タップ領域を下回らない。
- キーボード操作の順序は画面の視覚順（タイトル行 → 現在のパスワード → 新しいパスワード → 新しいパスワード（確認）→ 変更する → キャンセル → フッター）に合わせる。
- フォーム単位のメッセージ・完了状態の注意メッセージが表示されたとき、スクリーンリーダー利用者に通知されるようにする。
- 変更完了系の状態に切り替わったとき、フォーカスを完了の見出しに移す。
- パスワード欄は入力値を伏せて表示する。
