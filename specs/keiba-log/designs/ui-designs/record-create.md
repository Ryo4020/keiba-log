## 1. 画面の目的

馬券記録を新規登録する認証必須画面。レース記録の登録（`REQ-TICKET-001`）と簡易記録の登録（`REQ-TICKET-002`）の2要件を1画面で担う。画面の最上位に記録種別のタブを置き、タブを切り替えると日付・競馬場などの共通属性を含む入力フォーム全体が切り替わる。閲覧専用の画面ではなく、入力と登録の実行のみを担う。

## 2. 画面の構成

上から順に次の領域を並べる。

| 項目 | 内容 |
|---|---|
| 切り替えの単位 | タブを切り替えると、日付・競馬場などの共通属性を含む入力フォーム全体が切り替わる。共通属性だけを残して下部のみを差し替える構成にはしない |
| 入力値の保持 | 共通属性の入力値はタブごとに独立して保持する。一方のタブで入力した日付が他方のタブに引き継がれることはない |

## 3. レース記録タブ

### 3.1 入力項目

| 項目 | 入力方式 | 備考 |
|---|---|---|
| 日付 | 日付入力 | 必須。**未来日を許容する**（上限なし）。範囲は `business-rules.md` のレース記録の項目定義に従う。共通パーツ「記録共通入力ブロック」に含む |
| 競馬場 | 選択式 | 必須。マスタデータからの選択式（`REQ-TICKET-001` #2）。共通パーツ「記録共通入力ブロック」に含む |
| レース番号 | 選択式 | 必須。選択肢は `business-rules.md` の「レース番号・馬番・枠番の取りうる値」に従う |
| 結果の確定状態 | 選択式（2値の単一選択） | 必須。登録時にレース記録単位で選択する（`REQ-TICKET-001` #9）。選択に応じて結果に関する入力の扱いが変わることを注記で示す |
| 買い目 | 後述（3.2） | 1件以上必須。通常の買い目と買い目の集合を混在させられる |
| 購入額 | 自動算出（入力させない） | 全買い目の購入額合計。算出は `business-rules.md` の「購入金額のルール」に従う（`REQ-TICKET-001` #8） |

### 3.2 買い目の入力

買い目の入力は「買い目入力モーダル」（別画面。`designs/ui-designs/bet-input-modal.md` を参照）が担う。本画面は「買い目を追加」ボタンでモーダルを開く起点と、追加済みの買い目の表示・一覧管理のみを持つ。

| 操作 | 動作 |
|---|---|
| 「＋ 買い目を追加」 | 買い目入力モーダルを開く。モーダル内で券種・買い方（通常・フォーメーション／ボックス／ながし）・買い方の指定内容・購入額を指定し、確定すると成立した買い目が本画面に追加される（`REQ-TICKET-001` #3, #4）。成立する買い目が1点の場合、「通常」「フォーメーション」の指定は通常の買い目として、ボックス・ながしは1点だけを含む買い目の集合として追加される（`business-rules.md` の「買い目の集合」の複数の項目にまたがるルール 項番18 (d)） |
| 集合の「指定内容を変更」 | 買い目の集合の指定内容を編集する場合に、同じ買い目入力モーダルを現在の指定内容と「1点あたりの購入額」を初期値として開く。モーダルの変更モードには購入額の入力欄があり、指定内容の変更と同時に「1点あたりの購入額」も変更できる（`business-rules.md` の項番11）。確定すると、集合に含まれる買い目は変更後の指定内容から成立する組合せに作り直され、各買い目の購入額はモーダルで入力された購入額になる。作り直された買い目の結果の扱いは、下記「指定内容の変更による作り直しと結果の扱い」に従う。成立する買い目が1点になる場合の画面側の結果は、ボックス・ながしは1点だけを含む集合のまま、フォーメーションは通常の買い目への置き換えとなる（下記「指定内容の変更で1点になったとき」）。1点になるときに確認ダイアログは出さない |
| 集合の「1点あたりの購入額」の変更 | 集合に含まれるすべての買い目の購入額をその値に揃える。点数は変わらず、集合の小計と購入額合計を再計算して表示する。範囲と購入単位は `business-rules.md` の「購入金額のルール」に従う |

追加された買い目は、通常の買い目（1組ずつ指定したもの）と買い目の集合（買い方の指定内容から一括で成立したもの）を区別して表示する（`REQ-TICKET-001` UI設計上の留意点）。

| 項目 | 内容 |
|---|---|
| 集合のまとまり | 集合の見出し（券種・買い方・指定内容・点数・**1点あたりの購入額の入力欄**・集合に対する操作）と、集合に含まれる買い目を1つのグループとして表示する。集合に含まれる買い目は見出しの下に左へインデントして並べ、どの見出しに属するかが分かるようにする |
| 集合に含まれる買い目の表示 | **確定後のときだけ**、見出しの下に1点ずつ表示する。組と結果に関する入力だけを持つコンパクトな表示とし、券種と購入額は見出しで示すため買い目ごとには表示しない。**確定前は個別の行を表示せず、集合の見出しのみを表示する**（確定前は買い目ごとに入力する項目がないため） |
| 通常の買い目との見た目の統一 | 結果の選択ボタンと払戻額の入力欄は、通常の買い目と同じ見た目にする |

買い方・買い方の指定内容の入力方法、成立した買い目のプレビュー、点数と金額の自動算出（`REQ-TICKET-001` #6。算出は `business-rules.md` の「点数（買い目数）の算出ルール」に従う）は、すべて買い目入力モーダル側の仕様に従う。

#### 指定内容の変更による作り直しと結果の扱い

集合の「指定内容を変更」を確定して集合内の買い目が作り直されたとき（2点以上になる場合、ボックス・ながしで1点になる場合、フォーメーションで1点になって通常の買い目に置き換わる場合のすべて）は、作り直された買い目の結果の指定と払戻額が未入力に戻る（`business-rules.md` の「買い目の集合」の複数の項目にまたがるルール 項番11、「結果入力のルール」の「買い目の集合の作り直し・置き換えに伴う結果の扱い」）。画面側の結果は次のとおり。

| 結果の確定状態 | 画面の結果 |
|---|---|
| 確定前 | 変化なし。もともと集合内の買い目は表示されず、結果に関する入力も持たない |
| 確定後 | 作り直された買い目は、的中・返還のどちらも選ばれていない状態（不的中）で表示される。的中が選ばれていないため、払戻額の入力欄は非表示になり、入力済みだった払戻額は破棄される。ユーザーは必要なら改めて的中・返還を指定し、払戻額を入力する |

| 項目 | 内容 |
|---|---|
| 他の買い目・集合への影響 | 作り直されなかった他の買い目・他の集合の結果の指定・払戻額は変わらない |
| 指定内容が実際には変わらないとき | 成立する組合せが変わらないときは作り直しが起きないため、結果の指定・払戻額は変わらない |
| 購入額の変更のみのとき | 指定内容を変えず「1点あたりの購入額」だけを変更する場合（集合の見出しの入力欄での変更）は、結果の指定・払戻額は変わらない |
| 「バラす」との違い | 「バラす」は従来どおり各買い目の結果の指定・払戻額を保持する |

#### 指定内容の変更で1点になったとき

「指定内容を変更」を確定した結果、成立する買い目が1点になる場合の扱いは買い方によって異なる（`business-rules.md` の「買い目の集合」の複数の項目にまたがるルール 項番12・項番18）。どちらの場合も、確認ダイアログは出さない。結果の指定・払戻額は上記「指定内容の変更による作り直しと結果の扱い」に従い、未入力に戻る。

| 買い方 | 画面の結果 |
|---|---|
| ボックス・ながし | 1点だけを含む集合のまま保持する。集合の見出しとグループ、集合に対する操作（1点あたりの購入額の入力欄・指定内容を変更・バラす・集合を削除）は残る。確定後は、見出しの下に1点分の買い目を集合内の買い目の表示で示す。1点あたりの購入額はモーダルで入力された値になる |
| フォーメーション | 集合は解体され、その1点は通常の買い目に置き換わる（集合が解体され、残った1件が通常の買い目と同じ扱いになる点は「バラす」と同じ） |

フォーメーションで通常の買い目に置き換わるときの画面側の結果は次のとおり。

| 項目 | 内容 |
|---|---|
| 表示の変化 | 集合の見出しとグループが消え、残った1点が通常の買い目の表示に変わる。集合に対する操作（1点あたりの購入額の入力欄・指定内容を変更・バラす・集合を削除）は表示されなくなり、通常の買い目に対する操作（券種・組合せ・購入額の変更、削除）に変わる |
| 件数・購入額合計 | 件数は、変更前の集合に含まれていた点数から、置き換わった1件に変わる。購入額合計は、置き換わった1件の購入額で再計算して表示する。残った1件の購入額は、モーダルで入力された購入額（変更と同時に購入額を変更した場合はその値、しなかった場合は変更前の「1点あたりの購入額」） |
| 結果の指定・払戻額 | 未入力に戻る。確定後は、的中・返還の指定が外れた状態（不的中）の通常の買い目として表示され、払戻額の入力欄は非表示になる。確定前は結果に関する入力を持たない |
| 元に戻せない | 置き換え後は、集合が保持していた買い方・買い方の指定内容・1点あたりの購入額は保持されず、集合に戻すことはできない。バラした場合と同じく一方向の変化である |

#### 件数の上限

| 項目 | 内容 |
|---|---|
| 上限 | 1件のレース記録が持つ買い目は1件以上200件以下（`REQ-TICKET-001` #7。範囲は `business-rules.md` の「エンティティの関係と件数の制限」に従う） |
| 件数の数え方 | 通常の買い目と、すべての買い目の集合に含まれる買い目の合計 |
| 現在の件数の提示 | 買い目の領域に現在の件数と上限を常に表示し、残りいくつ追加できるかが分かる状態にする |
| 上限を超える指定 | 買い目入力モーダルで成立する件数が既存の件数と合わせて上限を超える場合、その指定内容は成立しない。モーダル上で成立しないことを示し、確定させない |
| 下限 | 買い目が0件のレース記録は成立しない。買い目未入力の状態では登録を実行させない |

#### 買い目に対する操作

| 対象 | 操作 |
|---|---|
| 通常の買い目 | 券種・組合せ・購入額の変更、当該買い目の削除 |
| 買い目の集合 | 1点あたりの購入額の変更、買い方の指定内容の変更、集合をバラす（確認ダイアログを経て実行する）、集合の削除。集合に含まれる買い目を個別に変更・削除する操作は提供しない（`business-rules.md` の「買い目に対して行える操作」に従う） |

### 3.3 結果の確定状態による分岐

結果に関する入力の可否と取りうる値は `business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」に従う。画面上の扱いは次のとおり。

| 結果の確定状態 | 画面の挙動 |
|---|---|
| 確定前 | 的中・返還の指定と払戻額の入力を提供しない。買い目入力ブロックは結果に関する入力欄を持たない状態で表示する。すべての買い目が結果未確定として登録される |
| 確定後 | 買い目1件（1点）ごとに的中・返還を指定できる。的中に指定した買い目には払戻額を入力する。いずれにも指定しなかった買い目は不的中になる |

| 項目 | 内容 |
|---|---|
| 指定の単位 | 買い目1件ごと。**買い目の集合に含まれる買い目も、集合単位ではなく1件ごとに指定する** |
| 指定の方式 | 的中・返還の2択の単一選択とする。**どちらも選択しない場合は不的中として扱う**。単一選択にすることで、同一の買い目を的中と返還の両方に指定できないことを構造上担保する |
| 払戻額の扱い | **的中を選んだ買い目のみ払戻額の入力欄を表示する**。返還・不的中（的中・返還のいずれも選ばない状態）では入力欄自体を表示しない |
| 確定状態を切り替えたときの表示 | 確定前と確定後で買い目入力ブロックの表示が切り替わる。切り替えによって結果に関する入力の扱いが変わることを、確定状態の選択欄の注記で示す（`REQ-TICKET-001` UI設計上の留意点） |

## 4. 簡易記録タブ

### 4.1 入力項目

| 項目 | 入力方式 | 備考 |
|---|---|---|
| 日付 | 日付入力 | 必須。**未来日を許容しない**（上限は JST の当日）。範囲は `business-rules.md` の「エンティティ項目定義 > 簡易記録」の日付に従い、タイムゾーンの詳細も同ファイルが正とする。レース記録タブとは入力可能範囲が異なることを補助テキストで示す。補助テキストと入力欄の下の注記は、上限が「当日」とだけ読める書き方にせず、JST（日本標準時）の当日であることが読み取れる表記にする |
| 競馬場 | 選択式 | 必須。マスタデータからの選択式（`REQ-TICKET-002` #2） |
| 購入額 | 数値入力 | 必須。ユーザーが直接入力する。範囲と購入単位は `business-rules.md` の簡易記録の項目定義および「購入金額のルール」に従う |
| 払戻額 | 数値入力 | 必須。範囲は `business-rules.md` の簡易記録の項目定義に従う（0を許容する） |

### 4.2 持たせない項目

| 項目 | 理由 |
|---|---|
| 買い目 | 簡易記録は買い目を持たない（`REQ-TICKET-002` #3）。買い目の入力領域・追加操作を置かない |
| 結果の確定状態・結果状態 | 簡易記録は結果状態を持たない（`REQ-TICKET-002` #4）。確定状態の選択欄を置かない |
| レース番号 | 簡易記録の項目ではないため置かない |

購入額はユーザー入力であり、レース記録タブのように買い目から自動算出しない点が両タブの違いである。

## 5. インタラクション仕様

### 5.1 登録の実行

| 操作・状況 | 動作 |
|---|---|
| 登録ボタン押下 | 入力値のクライアント側チェックを行う。簡易記録タブの日付が未来日かどうかは、端末のタイムゾーンによらず JST の当日を基準に判定する（日付の値 `YYYY-MM-DD` は暦日そのものとして比較し、タイムゾーン変換は行わない。`business-rules.md` に従う）。不正がなければ送信中状態に切り替え、`POST /records` を呼ぶ。送信中は再押下できないようにする（二重送信の防止） |
| リクエストボディ | 選択中のタブに応じて `RaceRecordInput` または `SimpleRecordInput` を送る。`recordType` で記録種別を指定する（`REQ-TICKET-001` #13 / `REQ-TICKET-002` #6） |
| `201` を受け取った | 登録が完了した。馬券記録一覧画面へ遷移する |
| `400` を受け取った | 登録されていない。サーバー側の検証で不正と判定された項目を示す |
| `401` を受け取った | 認証状態を終了し、ログイン画面へ遷移する（`REQ-AUTH-004`） |
| `409` を受け取った | 書き込みが競合した。やり直せる状態にして再実行を促す |
| `500` を受け取った | 登録されていないことを示し、ボタンを押下可能に戻して同じ操作をやり直せる状態にする |
| キャンセル押下 | 入力を破棄して前の画面へ戻る |
| 買い目が0件のとき | レース記録タブでは登録を実行させない。買い目を追加する必要があることを示す |

`POST /records` のリクエストでは、買い目の結果状態はクライアント側で確定させた値を送る（的中・返還の指定から定まる値、または確定前の場合は結果未確定）。点数・購入額はサーバー側で算出されるため送らない（`api.yml` の `RaceRecordInput` / `BetGroupInput` の定義に従う）。

### 5.2 入力値の検証と不正時の表示

| 操作・状況 | 動作 |
|---|---|
| 入力値が不正 | 登録を実行せず、不正な項目の入力枠をエラー表示にし、直下にその項目固有の注釈を出す（`REQ-TICKET-001` #14 / `REQ-TICKET-002` #7）。買い目の集合の1点あたりの購入額も同じ方式 |
| エラー表示の方式 | 項目ごとの表示に統一し、フォーム全体のエラーバナーは出さない（ログイン画面・アカウント登録画面の入力値不正時と同じ方式） |
| 再送信時 | 直前の項目ごとのエラー表示は送信時にクリアし、新しい検証結果に応じて出し直す |
| 成立しない選択の抑止 | 券種と買い方の成立しない組み合わせ、および件数の上限を超える指定内容は、エラーとして出すのではなく選択・確定させない形で防ぐ（`REQ-TICKET-001` #5, #7） |

### 5.3 共通の操作性

- 押下できる要素（タブ・選択式の入力・買い目の追加操作・集合に対する操作・登録・キャンセル）はすべて最小タップ領域（`tap-target-min`）を下回らない。
- 選択式の入力が多いため、`md` 未満では選択肢の一覧を画面幅に収まる形で提示する。
- キーボード操作の順序は画面の視覚順（タイトル行 → タブ → 共通属性 → 記録種別固有の入力 → 買い目 → 登録アクションバー）に合わせる。
- タブを切り替えたとき、フォーカスは切り替え後のフォームの先頭に移す。
- 買い目入力モーダルを閉じたときは、開く操作を行ったボタン（「買い目を追加」または集合の「指定内容を変更」）にフォーカスを戻す。モーダル表示中のフォーカス制御は `bet-input-modal.md` に従う。

### 6.1 新規に追加する共通パーツ（本画面がオーナー）

| パーツ名 | 役割 | 他画面で流用する際の注意 |
|---|---|---|
| 記録共通入力ブロック | 日付・競馬場という、記録種別に依らず共通する入力のまとまり。見出しやカードの枠は使用側の画面が用意する | レース番号・結果の確定状態・購入額などの記録種別固有の入力はこのパーツに含めず、使用側で兄弟要素として並べる。日付の入力可能範囲は記録種別によって異なるため、補助テキストは使用側で差し替える。登録画面ではタブごとに独立して配置する |
| 買い目入力ブロック | 買い目1件（1点）分の入力のまとまり。種別（通常の買い目／買い目の集合に含まれる買い目）と、属するレース記録の結果の確定状態（確定前／確定後）の組み合わせでバリアントを持つ。集合に含まれる買い目は確定後のバリアントのみ持つ | 集合に含まれる買い目は確定前には表示しない。集合に含まれる買い目のバリアントは、組と結果に関する入力のみを持つコンパクトな表示とし、券種・購入額は表示しない（集合の見出しで示すため）。組も編集させない（集合の指定内容から定まるため）。集合の見出しとあわせてグループに入れ、見出しの下にインデントして配置する。結果の選択ボタンと払戻額の入力欄は通常の買い目のバリアントと同じ見た目にする。確定後のバリアントのみ結果（的中・返還の指定）と払戻額を持つ。的中・返還は2択の単一選択とし、両方への指定を構造上できないようにする。**どちらも選ばない場合は不的中として扱う**。**払戻額の入力欄は的中を選んだときのみ表示する**。種別を示すバッジは持たない（見出し行の券種名で判別する）。買い目の追加・削除の操作は使用側の画面が持つ |

## 8. 使用したAPIとの対応

| API | 用途 | 対応するスキーマ |
|---|---|---|
| `POST /records` | 登録の実行 | レース記録タブは `RaceRecordInput`（`bets` は `BetInput`、`betGroups` は `BetGroupInput`・`MethodSpec`）、簡易記録タブは `SimpleRecordInput` |

買い目の集合の1点あたりの購入額は `BetGroupInput` の `unitAmount` として送る。

1点の買い目の送り方は次のとおり（`api.yml` はサーバーが1点だけを含む集合を受け入れると定めている）。

| 本画面の状態 | 送るスキーマ |
|---|---|
| 「通常」「フォーメーション」の指定で成立した1点（新規追加時） | `bets` の `BetInput`（通常の買い目） |
| ボックス・ながしの指定で成立した1点（新規追加時、および指定内容の変更後） | `betGroups` の `BetGroupInput`（`bets` が1件の集合） |
| フォーメーションの指定内容の変更で1点になり、通常の買い目に置き換わったもの | `bets` の `BetInput` |

本画面は登録前の入力状態を扱うため、指定内容の変更で作り直された買い目は、結果の指定・払戻額が未入力の状態で送る（確定前は結果未確定、確定後は的中・返還の指定なし＝不的中。払戻額は入力値を持たず、`payoutAmount` の値は `api.yml` の定義に従う）。

画面で入力しない項目: `purchaseAmount`（レース記録タブ。サーバー側で算出）、`betCount` / `amount`（買い目の集合。サーバー側で算出）、`betId` / `betGroupId`（新規登録では送らずサーバー側で採番）。

## 補足

買い目入力モーダル側の確定時の扱いは `bet-input-modal.md` に従う。本画面は、確定後の画面側の結果（上記「指定内容の変更による作り直しと結果の扱い」「指定内容の変更で1点になったとき」）のみを定める。

買い目の集合の「バラす」は、馬券記録編集画面と同じく確認ダイアログ（共通パーツ・オーナー: ホーム画面）で取り消せない操作であることを伝えてから実行する。ダイアログの文言とボタンは `record-edit.md` の 2.5 と Figma（`208:364`）に従う。

買い方の指定内容の入力方法（チェックボックスの格子など）は買い目入力モーダル（`bet-input-modal.md`）側で確定済み。
