## 1. 画面の目的

登録済みの馬券記録を呼び出し、内容を修正して保存する認証必須画面。初期表示で既存の記録内容が入力済みの状態になる（`REQ-TICKET-003` #1）。記録種別は変更できず、記録種別に応じてレース記録用または簡易記録用の入力項目を表示する。閲覧専用の詳細画面は設けず、本画面が内容確認も兼ねる。記録の削除も本画面から行える。本画面の URL は `designs/ui-overview.md` 1節「画面の URL」に従い、`/records/edit?key=<recordKey>` とする。

## 2. 表示要素

### 2.1 画面共通

| 要素 | 説明 |
|---|---|
| グローバルサイドバー | 共通パーツ。`md` 未満はドロワー（タイトル行の開閉ボタンから開く） |
| 画面タイトル「馬券記録を編集」 | 画面名 |
| 記録種別バッジ | 編集中の記録の記録種別（レース記録／簡易記録）を示す。表示のみで切り替え操作は持たない（`REQ-TICKET-003` #3） |
| 記録種別は変更不可の注記 | 記録種別を編集で変更できないことを示す |
| 保存アクションバー | 「変更を保存」「キャンセル」と注記。レース記録では購入額合計（自動算出）も表示する |
| 記録の削除 | 画面下部に置く破壊的操作の領域。見出し・「この記録を削除」ボタン・取り消せない旨の注記。保存操作とは別の領域・見た目で区別する |
| グローバルフッター | 共通パーツ |

### 2.2 レース記録

| 要素 | 説明 |
|---|---|
| 記録共通入力ブロック | 日付・競馬場。日付は未来日を許容する（範囲は `business-rules.md` のレース記録の項目定義） |
| レース番号 | 選択式。選択肢は `business-rules.md` の「レース番号・馬番・枠番の取りうる値」 |
| 結果の確定状態 | 確定前／確定後の2値の単一選択。現在値が判別できる。注記で切り替えによる結果入力の扱いの変化と、確定後→確定前で入力済みの結果が破棄されることを示す |
| 買い目ヘッダー | 現在の件数と上限、購入額合計。件数の範囲は `business-rules.md` の「エンティティの関係と件数の制限」 |
| 買い目の注記 | 確定状態に応じた結果入力の扱い |
| 「＋ 買い目を追加」 | 買い目入力モーダルを開く |
| 通常の買い目 | 買い目入力ブロック（通常）。券種・組・購入額、確定後は結果（的中・返還の指定）と払戻額。削除ボタンを持つ |
| 買い目の集合 / 見出し | 集合チップ・券種名・買い方名（表示のみ。変更不可 `REQ-TICKET-003` #14）、買い方の指定内容（表示）、点数（自動算出の表示）、**1点あたりの購入額の入力欄**、集合単位の操作の注記、「指定内容を変更」「バラす」、集合の削除ボタン |
| 集合内の買い目 | 確定後のときだけ見出しの下にインデントして1点ずつ表示する。組（表示のみ）と結果・払戻額のみを持つ。**確定前は表示せず見出しのみ** |
| 残り追加可能件数 | 上限まで残りいくつ追加できるか |

買い目の集合は、「バラす」を行ったとき、およびフォーメーションの集合の指定内容を変更して成立する買い目が1点になったときに解体される。解体後は、含まれていた買い目（後者では残った1件）が「通常の買い目」として表示され、集合の見出しは表示されない。解体された集合は復元できない。ボックス・ながしの集合は、指定内容の変更で1点になっても解体されず、1点だけを含む集合として表示する。

解体時の結果の扱いは両者で異なる。「バラす」は含まれていた買い目の結果の指定（的中・返還）と払戻額を保持する。フォーメーションの指定内容の変更で1点になって解体される場合は、残った1件の結果の指定・払戻額が未入力に戻る（確定後のレース記録では的中・返還の指定が外れた状態＝不的中になり、払戻額は破棄される。確定前は変化なし）。

フォーメーションの集合が1点になって通常の買い目になった後の専用フレームは Figma に設けない。見た目は既存の買い目入力ブロック（通常）に従う。

### 2.3 簡易記録

| 要素 | 説明 |
|---|---|
| 記録共通入力ブロック | 日付・競馬場。日付は未来日を許容しない（範囲は `business-rules.md` の簡易記録の項目定義） |
| 購入額 | 数値入力。範囲と購入単位は `business-rules.md` の簡易記録の項目定義・「購入金額のルール」 |
| 払戻額 | 数値入力。範囲は `business-rules.md` の簡易記録の項目定義 |
| 入力項目の注記 | 簡易記録はレース番号・結果の確定状態・買い目を持たないこと |

### 2.4 記録が見つからない状態

| 要素 | 説明 |
|---|---|
| 見出し「記録が見つかりません」と説明 | 記録が存在しないか削除済みであることを示す。URL の `key` が無い・形式が不正な場合と、他人の記録である場合も同じ表示にし、原因を区別して伝えない |
| 「馬券記録一覧へ戻る」 | 馬券記録一覧画面へ遷移する |

入力フォーム・保存アクションバー・記録の削除・記録種別バッジは表示しない。サイドバー・フッターは表示する。

### 2.5 確認ダイアログ

共通パーツ「確認ダイアログ」を、編集画面の上にオーバーレイを敷いて中央に表示する。見出し・本文・注意ブロック・ボタン行の構成は共通パーツに従い、本画面では文言とボタンのラベルだけを差し替える。文言の細部は Figma が正。

| ダイアログ | 伝える内容 | ボタン |
|---|---|---|
| 集合をバラす | 集合を解体し、含まれる買い目をそれぞれ通常の買い目にすること。各買い目の結果の指定（的中・返還）と払戻額は保持されること。元に戻せないこと（注意ブロック） | 「キャンセル」「バラす」 |
| 確定後 → 確定前 | すべての買い目が結果未確定になること。入力済みの的中・返還の指定と払戻額が破棄され、元に戻せないこと（注意ブロック） | 「キャンセル」「確定前に戻す」 |
| 記録の削除 | 記録と含まれるすべての買い目が削除されること。元に戻せないこと（注意ブロック） | 「キャンセル」「削除する」（共通パーツの破壊的操作の見た目） |

「バラす」「確定前に戻す」は破壊的操作の見た目を使わず、通常の主操作の見た目にする。

## 3. インタラクション仕様

### 3.1 初期表示

| 操作・状況 | 動作 |
|---|---|
| 画面を開く | URL のクエリ `key` を読み取り、デコードした値を `recordKey` として `GET /records/{recordKey}` で記録を取得する（パスに入れる際は改めて URL エンコードする）。`key` が複数あるときは最初の値を使う。取得中は入力フォームを操作させない |
| `key` が無い・空 | API を呼ばず、記録が見つからない状態を表示する |
| `key` の形式 | クライアント側では形式を判定しない。空でなければそのまま API に渡し、判定は API の応答に任せる |
| `200` | 取得した記録種別に応じたフォームを、既存の内容を入力済みの状態で表示する（買い目・集合・確定状態・結果・払戻額を含む） |
| `400` | `key` の形式が不正と判定された。記録が見つからない状態を表示する（`404` と区別しない） |
| `401` | 認証状態を終了し、ログイン画面へ遷移する（`REQ-AUTH-004`） |
| `404` | 記録が見つからない状態を表示する（存在しない・他人の記録・削除済み。`REQ-TICKET-003` #2） |
| `500` | 取得できなかったことを示し、再読み込みでやり直せるようにする |

### 3.2 レース記録の編集

| 操作・状況 | 動作 |
|---|---|
| 「＋ 買い目を追加」 | 買い目入力モーダル（`bet-input-modal.md`）を開く。買い方は「通常・フォーメーション／ボックス／ながし」の3択。「通常・フォーメーション」は成立した点数が1点なら通常の買い目、2点以上ならフォーメーションの買い目の集合として追加する（`bet-input-modal.md` の 3.2.1）。ボックス・ながしは買い目の集合として追加する（#5, #7） |
| 通常の買い目の購入額変更・削除 | 当該買い目のみに反映する（#6）。削除で買い目が0件になる操作は行わせない（#15） |
| 集合の「1点あたりの購入額」の変更 | 集合に含まれるすべての買い目の購入額をその値に揃える。点数は変わらず、小計・購入額合計を再計算して表示する（#13） |
| 集合の「指定内容を変更」 | 現在の指定内容を初期値として買い目入力モーダルを開く。券種・買い方は変更させない（#14）。モーダルには指定内容に加えて「1点あたりの購入額」の入力欄があり、指定内容の変更と同時に購入額も変更できる。購入額の初期値は、呼び出し時点の集合の「1点あたりの購入額」（集合の入力欄に未保存の編集中の値があるときはその現在値）。モーダルで確定した時点の値が、作り直された買い目（1点になって通常の買い目になる場合はその1件）の購入額になる。1点になる場合も確認ダイアログは出さない。成立する点数と買い方で動作が分かれる（#12）。<br>・**フォーメーションの集合で変更後が2点以上**: 集合は残り、集合内の買い目を変更後の指定内容から作り直す。点数と購入額合計（1点あたりの購入額 × 点数）を再計算して表示する。<br>・**ボックス・ながしの集合（変更後が1点でも）**: 集合は残り、集合内の買い目を変更後の指定内容から作り直す。1点になった場合は1点だけを含む集合として保持し、集合の見出しも表示したままにする。点数と購入額合計を再計算して表示する。<br>・**フォーメーションの集合で変更後が1点**: 集合は解体され、その1点は通常の買い目1件に置き換わる（買い方そのものを変える操作ではないため #14 とは矛盾しない）。集合の見出し（集合チップ・買い方名・指定内容・点数・1点あたりの購入額・「指定内容を変更」「バラす」・集合の削除）は消え、通常の買い目として表示される。元の集合は復元できない。買い目の件数は「集合の旧点数 → 1」に減り、購入額合計も再計算する。通常の買い目になったあとは、購入額の変更・削除を個別に行える。<br>・**結果の扱い（上記いずれの場合も共通）**: 作り直された（置き換わった）買い目の結果の指定（的中・返還）と払戻額は未入力に戻る。確定後のレース記録では、的中・返還の指定が外れた状態（不的中）になり、払戻額は破棄される。必要なら改めて指定・入力する。確定前は変化しない。他の買い目・他の集合の結果は変えない。指定内容が実際には変わらない（成立する組合せが変わらない）ときは作り直しが起きないため、結果も変わらない |
| 集合の「バラす」 | 確認ダイアログを表示し、取り消せない操作であることを伝える。承認すると集合を解体し、含まれていた買い目を通常の買い目として表示する（結果状態は変えない）。キャンセルすると何もしない（#9, #10） |
| 集合の削除 | 集合と含まれるすべての買い目を削除する（#8）。残る買い目が0件になる場合は行わせない（#15） |
| 集合内の買い目 | 個別の追加・削除・購入額の変更・組の変更の操作を提供しない（#11） |
| 件数の範囲外になる追加 | 買い目入力モーダル側で確定させない（#15） |
| 確定前 → 確定後 | 確認なしで切り替える。各買い目に結果（的中・返還の指定）を表示し、集合内の買い目を表示する（#16, #17） |
| 確定後 → 確定前 | 確認ダイアログで、入力済みの的中・返還の指定と払戻額が破棄されることを伝える。承認するとすべての買い目を結果未確定に戻し、結果の入力欄と集合内の買い目を非表示にする。キャンセルすると確定後のまま（#18。`business-rules.md` の「結果の確定状態を変更したときの扱い」） |
| 結果の指定 | 的中・返還の2択の単一選択。どちらも選ばない買い目は不的中。的中を選んだ買い目のみ払戻額の入力欄を表示する（`business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」） |

### 3.3 保存・キャンセル

| 操作・状況 | 動作 |
|---|---|
| 「変更を保存」 | クライアント側チェックを行い、不正がなければ送信中状態にして `PUT /records/{recordKey}` を呼ぶ。記録全体を送る全置換。`recordType` は変更しない。送信中は再押下させない。解体された集合（「バラす」、またはフォーメーションの指定内容の変更で1点になったもの）は `betGroups` から外し、含まれていた買い目（後者では残った1件）を `bets` に通常の買い目として入れて送る。どちらも同じ構成で送る（`api.yml` の `RaceRecordInput.betGroups` の説明に合致）。ボックス・ながしの集合は、指定内容の変更で1点になっても解体されないため、1点だけを含む集合として `betGroups` に残して送る（サーバーは1点だけを含む集合を受け入れる） |
| 日付を変更して保存 | 保存が成功すると `recordKey` が変わるが、`200` で本画面を離れるため URL の `key` は書き換えない。`200` 以外の応答（`400`・`409`・`500` など）では保存されておらず `recordKey` も変わらないため、URL の `key` は元のままとし、やり直しも元の `recordKey` で行う。本画面にとどまったまま `recordKey` が変わる経路は持たない（持たせる場合は、ブラウザ履歴を増やさない置き換えで URL の `key` を新しい値に更新する） |
| `200` | 変更が反映された（#19）。遷移元（馬券記録一覧画面またはホーム画面）に戻る |
| `400` | 保存されていない。不正と判定された項目を項目ごとに示す |
| `401` | 認証状態を終了し、ログイン画面へ遷移する |
| `404` | 記録が見つからない状態を表示する |
| `409` | 書き込みが競合した。入力内容を保持したまま、やり直しを促す |
| `500` | 保存されていないことを示し、ボタンを押下可能に戻してやり直せるようにする |
| 「キャンセル」 | 変更を破棄して遷移元に戻る |

### 3.4 入力値不正

| 操作・状況 | 動作 |
|---|---|
| 入力値が不正 | 保存を実行せず、不正な項目の入力枠をエラー表示にし、直下にその項目固有の注釈を出す（#20）。集合の1点あたりの購入額も同じ方式 |
| エラー表示の方式 | 項目ごとの表示に統一し、エラーバナーは出さない。最初の不正な項目へフォーカスを移す |
| 再送信時 | 直前のエラー表示をクリアし、新しい検証結果で出し直す |

### 3.5 記録の削除

| 操作・状況 | 動作 |
|---|---|
| 「この記録を削除」 | 確認ダイアログを表示し、削除すると元に戻せないことを伝える |
| ダイアログで承認 | `DELETE /records/{recordKey}` を1回だけ呼ぶ。送信中は再押下させない |
| `204` | 馬券記録一覧画面へ遷移する |
| `401` | 認証状態を終了し、ログイン画面へ遷移する |
| `404` | すでに存在しない。記録が見つからない状態を表示する |
| `409` | 競合した。やり直しを促す |
| `500` | 削除されていないことを示し、やり直せるようにする |
| ダイアログでキャンセル | 何もせず編集画面に戻る |

### 3.6 共通の操作性

- 押下できる要素はすべて最小タップ領域（`tap-target-min`）を下回らない。
- キーボード操作の順序は画面の視覚順に合わせる。
- 確認ダイアログ（2.5）の初期フォーカスは「キャンセル」に置く。「キャンセル」押下・オーバーレイ押下・Esc のいずれでも何もせずに閉じる。表示中は背後の要素にフォーカスを移さない。
- 買い目入力モーダル・確認ダイアログを閉じたときは、開く操作を行ったボタンにフォーカスを戻す。
