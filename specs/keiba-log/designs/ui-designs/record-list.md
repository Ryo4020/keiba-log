## 1. 画面の目的

ログイン中のユーザー自身の馬券記録を、日付の新しい順に一覧で確認する認証必須画面（`REQ-TICKET-005`）。ホーム画面の直近記録リストとは異なり、全件をページングしながら閲覧できる点と、レース記録の買い目を1点ずつ確認できる点、各行から記録の削除を開始できる点（`REQ-TICKET-004`）が本画面固有の役割である。行を選択すると馬券記録編集画面に遷移する。絞り込み・検索・並び替えは置かない。

## 2. 表示要素

| 要素 | 説明 |
|---|---|
| グローバルサイドバー | ナビゲーションとアカウントメニューの入口。共通パーツ（オーナー: ホーム画面）。本画面では「馬券記録一覧」を現在位置としてハイライトする |
| 画面タイトル行 | 画面タイトル「馬券記録一覧」と、狭い画面幅でのサイドバー開閉トリガー |
| 新規登録の導線 | 馬券記録登録画面へ遷移するボタン。共通パーツ（オーナー: ホーム画面） |
| 一覧カード | 馬券記録の一覧を収める領域。`GET /records` の `items` を返ってきた順（日付の新しい順）に表示する。クライアント側で並べ替えない |
| 馬券記録リスト行（拡張） | 1記録を表す行。共通パーツ「馬券記録リスト行」（オーナー: ホーム画面）をベースに、本画面独自の「買い目リスト」と「削除ボタン」を追加した拡張版。行本体（日付・競馬場とレース番号・記録種別バッジ・購入額・払戻額・収支の6要素）はホーム画面の仕様を厳密に踏襲する。画面サイズによらず表形式にはせず、列見出しを持たないカード的な1件単位のまとまりとして扱う |
| 行ヘッダー | 馬券記録リスト行（拡張）の先頭にあるまとまり。「日付・レース名（`{venue} 第{raceNumber}R`）・記録種別バッジ」を1記録の見出しとしてまとめた部分と、「購入額・払戻額・収支」をそれぞれのラベルとともにまとめた部分の2つで構成する。金額側は列見出しを持たないため、各値に対応するラベルを行内に置く |
| 買い目リスト | レース記録の行にのみ表示する、その記録が持つ買い目・買い目の集合を1点ずつ列挙する表示。1点につき「券種名・組（組合せ）・一点当たりの購入額・状態・払戻額」の5項目を示す。トグルで開閉する。本画面がオーナーの新規共通パーツ（詳細は4節） |
| 買い目リストトグル | 買い目リストの開閉を切り替える操作。買い目リストに内包する。畳んだ状態では「買い目 N点」の形で件数のみを示す |
| 買い目の集合の見出し行 | 買い目の集合を1つのまとまりとして示す行。券種名と買い方名・買い方の指定内容（`methodSpec` を人が読める形にしたもの）・点数（`betCount`）・1点あたりの購入額（`unitAmount`）を示し、その配下に集合に含まれる買い目を1点ずつ並べる。購入額の合計（`amount`）は表示しない。買い目リストに内包する |
| 削除ボタン | 行ごとに削除の確認操作を開始するボタン。行全体の押下（編集画面への遷移）および買い目リストトグルとは独立した操作として、行ヘッダーの右端に分離して配置する |
| ページング操作 | 「次のページを読み込む」ボタン。`nextCursor` が存在する場合にのみ表示し、押下すると次ページの記録を末尾に追加読み込みする。ページ番号ジャンプは置かない |
| 空状態表示 | 表示対象の記録が0件のときに一覧カード領域を差し替える表示。共通パーツ（オーナー: ホーム画面）を流用し、文言のみ本画面向けに差し替える |
| 確認ダイアログ | 削除の確認操作。共通パーツ（オーナー: ホーム画面）を流用し、本文のみ本画面向けに差し替える |
| グローバルフッター | 全画面共通。共通パーツ（オーナー: ログイン画面）のため本画面では設計しない |

行本体の確定状態による表記の分岐は、ホーム画面の「馬券記録リスト行」の定義（下表）をそのまま適用する。

| 条件 | 購入額 | 払戻額 | 収支 |
|---|---|---|---|
| `recordType` = `RACE` かつ `confirmationStatus` = `PENDING` | `purchaseAmount` を金額で表示 | 「確定前」 | 「確定前」 |
| `recordType` = `RACE` かつ `confirmationStatus` = `CONFIRMED` | `purchaseAmount` を金額で表示 | 金額で表示。的中がなければ「0円」 | 金額で表示 |
| `recordType` = `SIMPLE` | `purchaseAmount` を金額で表示 | 金額で表示 | 金額で表示 |

買い目1点の「状態」は `resultStatus` に対応させる。

| `resultStatus` | 表示 |
|---|---|
| `UNCONFIRMED`（結果未確定） | 「確定前」 |
| `WON`（的中） | 「的中」 |
| `REFUNDED`（返還） | 「返還」 |
| `LOST`（不的中） | 何も表示しない（空欄） |

画面に出さない項目: `items[].recordId`（表示・照合用であり画面上には出さない）、`items[].createdAt`（同一日付の並び順の根拠であり表示はしない）。

## 3. インタラクション仕様

### 3.1 一覧表示とページング

| 操作・状況 | 動作 |
|---|---|
| 画面表示時 | `GET /records`（`cursor` 省略）を呼び、1ページ目（最大20件）を表示する |
| 一覧カードの行 | 押下すると当該馬券記録の編集画面へ遷移する。遷移には `recordKey` を使う |
| 「次のページを読み込む」押下 | 前回レスポンスの `nextCursor` を `cursor` に指定して `GET /records` を呼び、取得した記録を既存の一覧の末尾に追加表示する |
| `nextCursor` が `null` | 「次のページを読み込む」を表示しない（これ以上のページが存在しない） |
| 読み込み中（初回・追加読み込み共通） | 対象領域（初回は一覧カード全体、追加読み込み時はページング操作のボタン）をプレースホルダー・読み込み中の表示に差し替える |
| `GET /records` が `500` | 一覧カード領域をエラー表示に差し替え、「再読み込み」ボタンを置く。追加読み込み時の失敗は、既存の一覧は保持したままページング操作の位置にエラーとやり直しの手段を表示する |
| `401` を受け取った | 画面を表示せずログイン画面へ遷移する（`REQ-AUTH-004`） |
| `items` が0件（1ページ目） | 一覧カード領域を空状態表示に差し替える（`REQ-TICKET-005` #11） |

### 3.2 買い目リストの開閉

| 操作・状況 | 動作 |
|---|---|
| 行の初期表示 | 買い目リストは畳んだ状態で表示し、「買い目 N点」と件数のみを示す。件数は通常の買い目（`bets`）と、すべての買い目の集合に含まれる買い目（`betGroups[].bets`）の合計 |
| 買い目リストトグル押下（畳んだ状態） | 当該行の買い目リストを展開し、買い目を1点ずつ全件表示する。行の選択（編集画面への遷移）は発火させない |
| 買い目リストトグル押下（展開状態） | 当該行の買い目リストを畳み、件数のみの表示に戻す |
| 買い目の集合の見出し行 | トグルを持たない。買い目リストが展開されている間、集合に含まれる買い目は常に1点ずつ表示される |
| 買い目リスト内の要素の押下 | 何も起こさない（表示専用）。買い目を個別に選択・編集する操作は本画面に置かない |
| 追加読み込み・再読み込み後 | 追加された行の買い目リストは畳んだ状態で表示する。既に展開していた行の開閉状態は維持する |
| 簡易記録の行 | 買い目リストとトグルを表示しない（`REQ-TICKET-005` #8） |

買い目リストは、既定で畳んだ状態にすることで、1レース記録が買い目を最大200件持つ場合でも一覧の行が過大にならないようにしている（`REQ-TICKET-005` UI設計上の留意点）。展開はユーザーの明示的な操作に限る。

### 3.3 削除の確認フロー

| 操作・状況 | 動作 |
|---|---|
| 行の削除ボタン押下 | 確認ダイアログを開く（`REQ-TICKET-004` #1）。この時点では何も削除しない。対象の記録種別（レース記録／簡易記録）に応じて本文の説明を変える（4節参照） |
| 「キャンセル」押下 / オーバーレイ押下 / Esc | ダイアログを閉じる。削除しない（`REQ-TICKET-004` #2）。取りやめ手段はこの3つを必ず提供する |
| 「削除する」押下 | `DELETE /records/{recordKey}` を1回だけ呼ぶ。実行中は両ボタンを押下不可にし、ラベルを「削除中…」に変える（二重送信の防止） |
| `204` を受け取った | ダイアログを閉じ、一覧から当該行を除去する（`REQ-TICKET-004` #3）。再取得は行わずクライアント側で行を除去する |
| `401` を受け取った | 認証状態を終了し、ログイン画面へ遷移する（`REQ-AUTH-004`） |
| `404` を受け取った | 対象が既に存在しない状態のため、ダイアログを閉じて一覧から当該行を除去する（他クライアントでの削除・データ不整合への対応） |
| `500` を受け取った | ダイアログを閉じずにエラーメッセージを表示する。ボタンを押下可能に戻し、同じ操作をやり直せる状態にする |

削除は取り消せないことを、確認ダイアログの本文と注意ブロックの両方で示す（`REQ-TICKET-004` UI設計上の留意点）。初期フォーカスは取りやめボタンに置く。レース記録の削除では、含まれる買い目・買い目の集合も同時に削除されることを本文で明示する（`REQ-TICKET-004` #4）。

### 3.4 共通の操作性

- 削除ボタン・ページング操作・一覧行・買い目リストトグルはすべて最小タップ領域（`tap-target-min`）を下回らない。
- 行の押下領域・削除ボタン・買い目リストトグルは互いに重ならないように分離して配置する。削除ボタンおよびトグルの押下が行の選択（編集画面への遷移）を誤って発火させないこと。
- キーボード操作の順序は画面の視覚順（タイトル行 → 新規登録 → 一覧の各行（行本体 → 買い目リストトグル → 削除ボタン）→ ページング操作）に合わせる。買い目リストが展開されていても、内部の表示要素はフォーカス対象にしない。
- 確認ダイアログを開いている間は背後の要素にフォーカスを移さない。閉じたときは削除ボタン押下時にフォーカスを戻す（削除が完了した場合は次に存在する行、または一覧の先頭に戻す）。
- 一覧行はホバーで面の見え方を変え、選択できる行であることを示す（ホーム画面の馬券記録リスト行と同じ挙動）。

## 4. 共通パーツ

### 4.1 新規に追加する共通パーツ（本画面がオーナー）

| パーツ名 | 役割 | 他画面で流用する際の注意 |
|---|---|---|
| 買い目リスト | レース記録が持つ買い目・買い目の集合を1点ずつ列挙する表示。1点につき「券種名・組（組合せ）・一点当たりの購入額・状態・払戻額」の5項目を示す。通常の買い目（`bets`）は1点で1行、買い目の集合（`betGroups`）は見出し行を1本置き、その配下に含まれる買い目（`betGroups[].bets`）を1点ずつ並べる。見出し行は券種名と買い方名・買い方の指定内容・点数・1点あたりの購入額を示し、配下の買い目の行では券種名を繰り返さない。トグルで開閉し、初期状態は畳んだ状態で「買い目 N点」の件数のみを示す（`REQ-TICKET-005` #6, #7 と UI設計上の留意点） | 表示専用のパーツで、トグル以外は押下不可。集合の見出し行にはトグルを持たせない。見出し行は1点あたりの購入額（`unitAmount`）を示し、購入額の合計（`amount`）は示さない。組（組合せ）と買い方の指定内容の表記は `requirements/business-rules.md` の「組合せの表記ルール」「買い方の指定内容の表記ルール」に従い、集合の見出し行と個別の買い目の両方に同じルールを適用する。見出し行に出す買い方名は同ファイルの「買い方名の表記」に従う（本ファイルでは表記の値を重複定義しない）。買い目が1件もない構成は成立しないため空表示は用意しない。簡易記録には使わない（`REQ-TICKET-005` #8）。区切り線の引き方・各項目の縦位置の揃え方・インデントの表現はFigmaを参照する |

`ui-overview.md` の共通パーツ一覧に本パーツを登録済み（オーナー: 馬券記録一覧画面）。Figma上ではコンポーネント化済みで、以下の粒度に分けている（base/md以上それぞれに対応するコンポーネントを用意）。

- **買い目リスト**: トグル＋本体を含むコンポーネント。展開状態・畳んだ状態のバリアントを持つコンポーネントセット
- **買い目行（通常）**: 券種名・組・購入額・状態・払戻額の5項目を持つ1行
- **買い目行（集合内）**: 券種名を省略した4項目（組・購入額・状態・払戻額）の1行
- **買い目の集合**: 券種・買い方名、指定内容、点数・1点あたりの購入額を示す見出し行と、その配下に含む複数の買い目行（集合内）
- **買い目リストトグル**: 展開・畳んだ状態の2バリアントを持つコンポーネントセット

買い目の集合・買い目リストは実データによって配下の行数・行内の項目構成（状態・払戻額の有無）が変わるため、各画面上の実際の使用箇所ではコンポーネントをそのままインスタンスとして使うか、行数に応じてインスタンスをデタッチし配下の行数・テキストを実データに合わせて調整している。買い目リストトグル・買い目行（通常）・買い目行（集合内）は構造が固定のため、インスタンスのテキスト上書きのみで対応する。
