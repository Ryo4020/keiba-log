## 1. 画面の目的

未認証で利用する画面群の1つ。メールアドレスとパスワードを入力してアカウントを新規作成する（`REQ-AUTH-001`）。登録の実行を受け付けると、メールアドレスの存在・有効化状態にかかわらず常に同じ形で確認コード入力画面へ進み、入力したメールアドレスを引き継ぐ（#6・#7）。登録の実行時点ではユーザーを認証状態にしない（#9）。本画面からログイン画面へ戻れる。

## 3. インタラクション仕様

### 3.1 送信・遷移

| 操作・状況 | 動作 |
|---|---|
| アカウント登録ボタン押下 | 入力値のクライアント側チェックを行う（3.3）。不正がなければ送信中状態に切り替え、登録処理を呼ぶ。送信中は再押下できないようにする（二重送信の防止） |
| 登録の実行を受け付けた（#6） | 確認コード入力画面へ遷移する。本画面では受け付けの案内を出さない（確認コードの入力が残っていることの案内は遷移先の画面にあるため、二重にしない）。受け付けとして扱う応答は 3.5 のとおり |
| 受け付けとして扱う応答の間の差（#7） | 内部では存在しないメールアドレス・期限切れの未確認アカウント・期限内の未確認アカウント・有効化済みアカウントのいずれであっても（#1・#3・#4・#5）、遷移先・表示・遷移までのタイミングを同じにする。応答を受け取ったら、どの場合も待ち時間を足さずにすぐ遷移する |
| 遷移時に引き継ぐ値 | 本画面で入力したメールアドレスだけを引き継ぐ。画面遷移時のアプリ内の状態で渡し、URL（クエリ文字列など）に含めない。パスワード・パスワード（確認）は引き継がず、遷移時に破棄する |
| 確認コードの送信 | 本画面からは確認コードの再送を呼ばない（受け付けの応答の種類によらず、自動再送はしない） |
| 既存の未確認アカウントのパスワード | 既存の未確認アカウントには最初の登録時のパスワードが残り、今回入力したパスワードは反映されない（`business-rules.md` アカウント 項番3）。アカウントの存在が分かるため、画面上では個別に伝えない |
| 登録の実行を受け付けた直後 | ユーザーを認証状態にしない（#9）。ホーム画面等の認証必須画面へは遷移させない |
| 「ログイン画面に戻る」押下 | ログイン画面へ遷移する |

### 3.2 パスワード強度要件の提示

| 操作・状況 | 動作 |
|---|---|
| パスワード入力欄にフォーカス・入力する | 強度要件の一覧（8文字以上／半角英大文字を1文字以上／半角英小文字を1文字以上／半角数字を1文字以上／記号を1文字以上）を常に表示する |
| 入力内容が各条件を満たす | 満たした条件の表示を達成済みの見た目に切り替える。条件は個別に判定し、達成状況に応じて表示を更新する。「記号」に当たる文字の範囲は Cognito の仕様に従う（`business-rules.md`「Cognito の仕様に委ねる値」） |
| 送信前（未入力を含む） | 未達成の条件は通常の見た目のままとし、エラーとしては扱わない（送信前の入力補助であり、エラー表示とは役割が異なる） |

### 3.3 入力値のチェックと不正時の表示

| 操作・状況 | 動作 |
|---|---|
| 入力値が不正（メールアドレスの形式・最大文字数、パスワードの強度要件・最大文字数、パスワード確認の不一致のいずれかを満たさない。値の制限は `business-rules.md` が正） | アカウントを作成せず、不正な項目の入力枠をエラー表示にし、直下にその項目固有の注釈を出す（#8） |
| パスワードが強度要件のいずれかを満たさない | パスワード入力欄をエラー表示にし、直下に「下記の条件をすべて満たすパスワードを入力してください」を出す。強度要件の一覧は達成済み・未達の表示のまま残す |
| パスワードが最大文字数を超える | 最大文字数は Cognito の仕様に従うため強度要件の一覧には載せず、この注釈で扱う。パスワード入力欄をエラー表示にし、直下に「パスワードが長すぎます。文字数を減らして入力してください」の趣旨を出す。表示は入力値不正エラーのパスワード入力欄と同じで、注釈の文言だけが異なる（専用のフレームは作っていない） |
| メールアドレス・パスワード・パスワード確認のいずれか（複数の場合を含む）が未入力のまま送信 | 該当項目を入力値不正と同様に扱い、入力枠をエラー表示にする |
| パスワードとパスワード確認が一致しない | パスワード確認の入力枠をエラー表示にし、一致しないことを示す注釈を出す |
| 登録の実行で、パスワードがポリシーに合わないと返された（クライアント側チェックをすり抜けた場合の保険） | 画面にとどまり、パスワード入力欄をエラー表示にし、直下に「このパスワードは使用できません。条件を確認して、別のパスワードを入力してください」を出す。エラーバナーは出さない。入力値は残す |
| エラー表示後に再度入力・送信する | 直前の項目ごとのエラー表示とエラーバナーは送信時にクリアし、新しい結果に応じて出し直す |

入力値不正のときはエラーバナーを出さない（項目ごとの注釈と役割が重複するため。ログイン画面・確認コード入力画面と同じ方式）。

### 3.4 回数上限・通信エラー

| 操作・状況 | 動作 |
|---|---|
| 登録の回数が上限に達した | 画面にとどまり、エラーバナーで「操作の回数が上限に達したため、現在は実行できません。しばらく時間をおいてから、もう一度お試しください。」の趣旨を示す。入力値は残す。上限・解除までの時間は表示しない |
| 通信エラー・想定外の失敗 | 画面にとどまり、エラーバナーで「通信エラーが発生しました。通信環境を確認して、もう一度お試しください。」の趣旨を示す。入力値は残す |

いずれの文言もアカウントの有無・状態に触れない。

### 3.5 応答と表示の対応

| 応答（想定） | 表示 |
|---|---|
| 登録の成功 | 確認コード入力画面へ遷移（受け付け） |
| そのメールアドレスのユーザーが既にいる（`UsernameExistsException` の想定。未確認・確認済みを問わず返る） | 確認コード入力画面へ遷移（受け付け）。登録の成功と同じ |
| パスワードがポリシーに合わない（`InvalidPasswordException` の想定） | パスワード入力欄の項目エラー（3.3） |
| 回数の超過（`TooManyRequestsException`・`LimitExceededException` の想定） | 回数上限（3.4） |
| 通信の失敗・上記以外 | 通信エラー（3.4） |

画面上の文言には、例外名・サービス名・設計ドキュメント名を出さない。

### 3.6 共通の操作性

- 押下できる要素（アカウント登録ボタン・「ログイン画面に戻る」）は最小タップ領域を下回らない。
- キーボード操作の順序は画面の視覚順（メールアドレス → パスワード → パスワード確認 → アカウント登録ボタン → ログイン画面に戻る → フッター）に合わせる。
- エラーバナーが出たときはフォーカスをバナーに移し、スクリーンリーダーにも通知する。パスワード入力欄の項目エラーのときはフォーカスをパスワード入力欄に移す。
- エラーバナーは自動で消さず、次の送信までそのまま出す。
- 確認コード入力画面へ遷移した後のフォーカス・案内は遷移先の画面で扱う。

## 4. 共通パーツ

本画面は「パスワード入力ブロック」のオーナーである。「グローバルフッター」「未認証画面レイアウト」はログイン画面の既存デザインをインスタンスとして配置し、再デザインしていない。エラーバナーは共通パーツではなく、確認コード入力画面・ログイン画面の既存のバナーと同じ見た目で配置している。

### オーナーとして提供するパーツ

| パーツ名 | 役割 | 他画面で流用する際の注意 |
|---|---|---|
| パスワード入力ブロック | 新しいパスワードの入力・確認入力・強度要件の提示をまとめたブロック（パスワード入力欄＋強度要件の提示＋パスワード確認入力欄）。パスワード再設定画面・パスワード変更画面が流用する | 強度要件の判定対象は「新しいパスワード」の入力欄のみで、確認入力欄には要件表示を付けない。パスワード変更画面では、このブロックの前に「現在のパスワード」入力欄が別途必要になる（`business-rules.md` のパスワード変更時の現在パスワード確認ルール）が、それは流用先の画面がこのブロックの外側に追加するものであり、本ブロック自体には含まれない。強度要件の項目は5つ（8文字以上／半角英大文字／半角英小文字／半角数字／記号を各1文字以上）で、`business-rules.md` の定義に合わせている。最大文字数は一覧に載せない。新しいパスワード入力欄のプレースホルダーも「8文字以上で入力してください」に変えている。流用先のインスタンスで強度要件・プレースホルダーの文言や達成状態をオーバーライドしている場合は、オーバーライドが優先されて旧文言（8〜128文字・半角英字・半角記号など）や4項目分の達成状態が残るため、流用先の画面で確認する必要がある |
