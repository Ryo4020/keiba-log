# ビジネスルール: keiba-log

| 項目 | 内容 |
|---|---|
| 機能名 | `keiba-log` |
| 担当 | business-rules-analyst |
| インプット | `requirements/overview.md`, `requirements/functional-requirements.md` |

## 前提

本プロダクトはユーザーが購入した馬券の内容（買い目、すなわち券種と対象の組合せ）と、購入額・払戻額・結果をそのまま記録する。レース結果から的中を判定することは行わない。したがって、出走頭数・着順・オッズなどからルールで結果を導出する類のルールは対象としない。

## ドメイン用語定義

| 用語 | 定義 |
|---|---|
| 中央競馬（JRA） | 日本中央競馬会が開催する競馬。全国10か所の競馬場で開催される |
| 地方競馬（NAR） | 地方公共団体が主催者となって開催する競馬。地方競馬全国協会（NAR）が開催を支援する |
| 主催区分 | 競馬場が中央競馬（JRA）と地方競馬（NAR）のいずれに属するかを表す区分 |
| 勝馬投票券（馬券） | 競走の結果を予想して購入する投票券 |
| 賭式（券種） | 馬券の種類。何を的中対象とするかを定めた分類（単勝・複勝・枠連など） |
| 馬番 | 出走馬1頭ごとに与えられる番号 |
| 枠番 | 出走馬を最大8つのグループに割り振った番号 |
| ゾロ目 | 枠連において、同一の枠番同士の組合せ（例: 3枠-3枠） |
| 組合せ（対象） | 買い目が内包する、購入した番号（馬番または枠番）の組合せ。構造は券種に対応する |
| 買い方 | 買い目を登録する方式。通常・ボックス・ながし・フォーメーションがある。通常は買い目を1組ずつ指定して通常の買い目として登録する方式であり、それ以外は複数の買い目を買い目の集合として一括登録する手段である |
| 通常の買い目 | 買い目の集合に属さず、1組ずつ指定して登録した単独の買い目 |
| 買い目の集合 | 買い方（ボックス・ながし・フォーメーション）による一括登録で作られる、複数の買い目のまとまり。集合をバラすと、含まれる買い目は通常の買い目と同じ扱いになる。フォーメーションの指定内容を変更した結果、成立する買い目が1点になったときも、集合は解体され、その1点は通常の買い目になる（ただし結果状態・払戻額は「バラす」と異なり未入力に戻る）。ボックス・ながしは、成立する買い目が1点でも、1点だけを含む集合として保持する。新規の一括登録で成立する買い目が1点となる場合の扱いは「買い目の集合」の複数の項目にまたがるルール 項番18を参照 |
| 一括登録 | ボックス・ながし・フォーメーションの指定内容から成立する組合せをすべて買い目として同時に登録すること。一括登録によって買い目の集合が作られる |
| バラす | 買い目の集合を解体し、含まれていた買い目を通常の買い目と同じ扱いにする操作。各買い目の組合せ・購入額・件数・結果状態・払戻額は変わらない。フォーメーションの指定内容の変更で成立する買い目が1点になったときも、集合が解体され、残った1件が通常の買い目と同じ扱いになる点はバラすと同じだが、結果状態・払戻額が未入力に戻る点はバラすと異なる |
| 軸 | ながしにおいて、必ず組合せに含める馬（または枠） |
| 相手（ヒモ） | ながしにおいて、軸と組み合わせる馬（または枠） |
| 点数 | 買い目の個数。1つの買い目を1点として数える |
| 払戻金 | 的中した馬券に対して支払われる金額 |
| 返還 | 購入が無効となり、購入額と同額が購入者に返されること |
| 収支額 | 払戻額の合計から購入額の合計を差し引いた金額 |
| 回収率 | 購入額の合計に対する払戻額の合計の割合 |

「馬券記録」「記録種別」「レース記録」「簡易記録」「買い目」はアプリ用語として `requirements/functional-requirements.md` の用語定義で定義済みである。本ファイルでは定義を重複させず、そちらを参照する。「通常の買い目」「買い目の集合」は買い方（通常・ボックス・ながし・フォーメーション）という競馬ドメインの分類から生じる区別であるため、本ファイルのドメイン用語として上表で定義する。

### 買い方（購入方式）

| # | 買い方 | 定義 |
|---|---|---|
| 1 | 通常 | 買い目を1組ずつ指定して登録する |
| 2 | ボックス | 選択した対象（馬番または枠番）から作れる組合せをすべて買い目として一括登録する |

| 4 | フォーメーション | 着順ごと（または組合せの構成位置ごと）に選択集合を指定し、その直積から成立する組合せをすべて買い目として一括登録する |

#### 買い方名の表記

買い方の名称（画面表示に用いる表記）を一意に定める。

| # | ルール |
|---|---|
| 1 | ながしの買い方名は「ながし」に統一する。「流し」という漢字表記は用いない（ドメイン用語としての併記は上表の定義のみに留める） |
| 2 | ながしのパターンのうちマルチの指定（「ながしのパターン」の項番3・項番5）の場合は「ながし（マルチ）」と表記する |
| 3 | 軸の頭数（軸1頭・軸2頭）および着順指定の有無は買い方名に含めない。これらは「買い方の指定内容の表記ルール」による指定内容の表記から読み取れる |

### ながしのパターン

| # | パターン | 適用券種 | 定義 |
|---|---|---|---|
| 1 | 軸1頭ながし | 枠連・馬連・ワイド・三連複 | 軸1つと相手の組合せを一括登録する |
| 2 | 軸1頭・着順指定ながし | 馬単・三連単 | 軸の着順（1着・2着・3着）を固定して一括登録する |
| 3 | 軸1頭マルチ | 馬単・三連単 | 軸が取りうるすべての着順を網羅して一括登録する |
| 4 | 軸2頭ながし | 三連複・三連単 | 軸2つと相手の組合せを一括登録する |
| 5 | 軸2頭マルチ | 三連単 | 軸2つと相手1つの3つについて、すべての着順を網羅して一括登録する |

着順を区別する券種（馬単・三連単）では、軸の着順を固定せずマルチでもない軸1頭のながしは、成立する組合せが項番3（軸1頭マルチ）と完全に一致するため、独立したパターンとして成立しない。したがって馬単・三連単で軸1頭のながしを行う場合は、項番2（軸1頭・着順指定ながし）または項番3（軸1頭マルチ）のいずれかとなる。

| 枠連 | 1着・2着となった馬の枠番の組合せを当てる | しない | 枠番 | 2 | 枠番2つの順序なし組合せ。同一枠番同士（ゾロ目）も1組合せとして成立する |
| 馬連 | 1着・2着となった馬の馬番の組合せを当てる | しない | 馬番 | 2 | 馬番2つの順序なし組合せ |

| 三連複 | 1着から3着までに入る馬の馬番の組合せを当てる | しない | 馬番 | 3 | 馬番3つの順序なし組合せ |
| 三連単 | 1着から3着までの馬の馬番を着順どおりに当てる | する | 馬番 | 3 | 馬番3つの順列 |

### 組合せの表記ルール

組合せ（買い目が内包する馬番・枠番の組合せ）を表記する際の区切り文字を一意に定める。本ルールは画面横断の共通ルールとして、組合せを表示するすべての箇所に適用する。

区切り文字は券種の「着順の区別」によって決まる。どの券種が着順を区別するかは「券種の属性」の「着順の区別」列に従う。

| 着順の区別 | 区切り文字 | 番号の並び順 | 表記例 |
|---|---|---|---|
| する | `>` | 左から1着・2着・3着の順。着順の順序をそのまま表す | 馬単: `3>1` / 三連単: `1>3>5` |
| しない | `-` | 昇順 | 枠連: `1-3`（ゾロ目は `3-3`） / 馬連・ワイド: `1-3` / 三連複: `1-3-5` |
| なし | ―（選択数が1のため区切り文字を使わない） | ― | 単勝・複勝: `7` |

### 買い方の指定内容の表記ルール

買い目の集合（ボックス・ながし・フォーメーション）の指定内容を表記する際のルールを定める。集合に含まれる個々の買い目は「組合せの表記ルール」に従って表記する。

| 買い方 | 表記 | 表記例 |
|---|---|---|
| ボックス | 選択した対象を `,` で列挙する | `1,2,3` |
| フォーメーション | 着順（構成位置）ごとの選択集合を「組合せの表記ルール」の区切り文字で区切る。各集合内の複数の番号は `,` で列挙する | 三連単: `1,2>3,4,5>1,2,3,4` / 三連複: `1,2-3,4,5-1,2,3,4` |
| ながし | 組合せの構成位置（着順）ごとの選択集合を区切り文字で区切って並べる。フォーメーションと同じ表記形式を用いる。区切り文字は下表「区切り文字の決まり方」に従い、パターンごとの表記は下表「ながしのパターンごとの表記」に従う | 三連単の軸1頭・2着固定（軸1・相手3,4,5）: `3,4,5>1>3,4,5` |

#### 区切り文字の決まり方

買い方の指定内容は、いずれの買い方も「組合せの構成位置（着順）ごとの選択集合を区切り文字で区切って並べる」形式に統一する。用いる区切り文字は次のとおり定める。

| 指定の種類 | 区切り文字 | 理由 |
|---|---|---|
| 着順を固定する指定 | 「組合せの表記ルール」の区切り文字に従う（着順を区別する券種は `>`、区別しない券種は `-`） | 構成位置が着順に対応するため、組合せの表記と同じ区切り文字で意味を表せる |
| 着順を固定しない指定 | 着順を区別する券種であっても例外的に `-` を使う | 各位置の着順が定まらないため `>` では意味を表せない |

この決まり方により、フォーメーションおよび軸1頭・着順指定ながしは（着順を区別する券種の場合）`>` となり、ながし（マルチ）は `-` となる。

#### ながしのパターンごとの表記

| パターン | 表記の考え方 | 表記例 |
|---|---|---|
| 軸1頭ながし | 軸の位置に軸、残りの位置に相手の集合を置く。三連系は軸以外のすべての位置を相手の集合で埋める。着順を区別しない券種のみに適用されるため区切り文字は `-` | 馬連（軸1・相手3,4,5）: `1-3,4,5`<br>三連複（軸1・相手3,4,5）: `1-3,4,5-3,4,5` |
| 軸1頭・着順指定ながし | 固定した着順の位置に軸、残りの位置に相手の集合を置く。着順を固定するため `>` | 三連単で軸を2着に固定（軸1・相手3,4,5）: `3,4,5>1>3,4,5` |
| 軸1頭マルチ | 軸の位置に軸、残りの位置に相手の集合を置く。着順を固定しないため例外的に `-` | 馬単（軸1・相手3,4,5）: `1-3,4,5`<br>三連単（軸1・相手3,4,5）: `1-3,4,5-3,4,5` |
| 軸2頭ながし | 2つの軸をそれぞれの位置に置き、残りの位置に相手の集合を置く。三連複は着順を区別しないため `-`、三連単は軸が上位2着に固定されるため `>` | 三連複（軸1,2・相手5,6,7）: `1-2-5,6,7`<br>三連単（軸1,2・相手5,6,7）: `1>2>5,6,7` |
| 軸2頭マルチ | 2つの軸と相手を位置ごとに置く。着順を固定しないため例外的に `-` | 三連単（軸1,2・相手5,6,7）: `1-2-5,6,7` |

#### 相手が全番号の場合

相手として軸以外のすべての番号が選択されている場合は、相手の集合を `全` と表記する。

| # | ルール |
|---|---|
| 1 | 判定の対象となる番号の範囲は「レース番号・馬番・枠番の取りうる値」に従う（馬番は1〜18、枠番は1〜8）。本プロダクトは出走頭数を扱わないため、マスタデータの番号の範囲で判定する |
| 2 | 判定条件は「その範囲の番号のうち、軸として選択されていないすべての番号が相手に含まれていること」とする |
| 3 | 条件を満たす場合、相手の集合を番号の列挙に代えて `全` と表記する |

表記例: 三連単で軸を2着に固定し、相手が全番号の場合 → `全>1>全`

### 券種 × 買い方 のマトリクス

`○` = 成立する、`×` = 成立しない。括弧内は成立に必要な最小の選択数。

| 券種 | 通常 | ボックス | ながし（軸1） | ながし（軸2） | フォーメーション |
|---|---|---|---|---|---|
| 単勝 | ○ | ×（1頭を選ぶ賭式のため組合せが作れない） | × | × | × |
| 複勝 | ○ | ×（同上） | × | × | × |
| 枠連 | ○ | ○（2枠以上・ゾロ目を含まない） | ○（軸1枠＋相手1枠以上・ゾロ目を含む） | × | ○（各集合1枠以上・ゾロ目を含む） |
| 馬連 | ○ | ○（2頭以上） | ○（軸1頭＋相手1頭以上） | × | ○（各集合1頭以上） |
| ワイド | ○ | ○（2頭以上） | ○（軸1頭＋相手1頭以上） | × | ○（各集合1頭以上） |
| 馬単 | ○ | ○（2頭以上） | ○（軸1頭＋相手1頭以上） | × | ○（各集合1頭以上） |
| 三連複 | ○ | ○（3頭以上） | ○（軸1頭＋相手2頭以上） | ○（軸2頭＋相手1頭以上） | ○（各集合1頭以上、合計3頭以上） |
| 三連単 | ○ | ○（3頭以上） | ○（軸1頭＋相手2頭以上） | ○（軸2頭＋相手1頭以上） | ○（各集合1頭以上、合計3頭以上） |

枠連は、ながし・フォーメーションではゾロ目を組合せに含めるが、ボックスではゾロ目を含めない。この点で他の二連系の券種（馬連・ワイド・馬単）と扱いが異なる。

軸2頭のながしは、組合せに3つの対象を要する三連複・三連単でのみ成立する。二連系の券種で軸を2つ指定した状態は、組合せがひとつに確定するため「通常」と同義となる。

## エンティティ項目定義

ユーザーが登録・編集できるデータ単位ごとに、項目とその値の仕様を定義する。システムが内部で自動生成・管理するだけのデータは対象としない。

### エンティティの関係と件数の制限

| 親 | 子 | 件数の制限 |
|---|---|---|
| アカウント | 馬券記録（レース記録・簡易記録） | 0件以上。すべての馬券記録は登録したユーザー自身のデータとして扱う |
| レース記録 | 買い目 | 1件以上200件以下。通常の買い目と、そのレース記録が持つすべての買い目の集合に含まれる買い目の合計で数える。買い目が0件のレース記録は成立しないため、すべての買い目を削除することはできない |
| レース記録 | 買い目の集合 | 0件以上。買い目の集合を持たず、通常の買い目のみでレース記録を構成してもよい。1つの集合は買い目を1件以上含むため、集合の件数は最大200件となる |
| 買い目の集合 | 買い目 | 1件以上。上限は個別に定めず、レース記録全体の200件の上限に従う。買い目が0件の買い目の集合は成立しない。1点だけを含む集合も成立しうる（ボックス・ながし、およびAPIに直接送られたフォーメーションの集合）。フォーメーションの指定内容の変更の結果が1点になる場合は集合が解体される（「買い目の集合」の複数の項目にまたがるルール 項番18） |
| 簡易記録 | 買い目 / 買い目の集合 | 持たない（0件） |

買い目は、通常の買い目としてレース記録に直接属するか、買い目の集合に属してその集合を通じてレース記録に属する。1つの買い目が同時に両方に属することはない。

馬券記録に共通する事項

| # | ルール |
|---|---|
| 1 | 記録種別（レース記録／簡易記録）は登録時に決まり、登録後に変更できない |
| 2 | 馬券記録は、登録したユーザー自身のデータとして扱う |

### アカウント

ユーザー自身の認証情報を表すエンティティ。認証方式はメールアドレスとパスワードのみとする。アカウントの有効化状態（未確認アカウント／有効化済みアカウント）はユーザーが入力する項目ではないため、項目として扱わない。

アカウントは Amazon Cognito User Pool で管理する。メールアドレスの確認は、確認メールに記載された確認コードを入力する方式とする。パスワード再設定は、パスワード再設定メールに記載された再設定コードと新しいパスワードを入力して設定する方式とする。本節の値は次の2種類に分かれる。

- 具体的な値を記載したもの: Cognito の設定（ユーザープールのパスワードポリシー・属性の定義）でその値にする前提で定めた値
- 「Cognito の仕様に従う」と記載したもの: Cognito の設定で変更できない固定の仕様に委ねる値。本プロダクト独自の値は定めない。委ねる値の一覧と参照先は下表「Cognito の仕様に委ねる値」を参照

| 項目 | 値の種類 | 必須 | 値の制限 |
|---|---|---|---|
| メールアドレス | 文字列 | 必須 | 最大254文字。`ローカル部@ドメイン` の形式であること。形式の判定基準は Cognito の仕様に従う。1つのメールアドレスにつき有効なアカウントは1つまで（詳細は下表「メールアドレスの一意性」を参照） |
| パスワード | 文字列 | 必須 | 8文字以上。最大文字数は Cognito の仕様に従う。半角英大文字・半角英小文字・半角数字・記号をそれぞれ1文字以上含む。記号として扱う文字の範囲は Cognito の仕様に従う |

### レース記録

記録種別が「レース記録」の馬券記録。レース単位で馬券の内容を記録する単位であり、通常の買い目と買い目の集合を直接持つ。そのレースの結果が確定前か確定後かを表す「結果の確定状態」をレース記録自身の項目として持つ。

| 2 | 1件のレース記録が持てる買い目は1件以上200件以下とする。件数は、通常の買い目と、そのレース記録が持つすべての買い目の集合に含まれる買い目の合計で数える。買い目を0件にすることはできず、201件以上を持つこともできない |
| 3 | 買い目の集合は0件以上持てる。通常の買い目のみ、買い目の集合のみ、両者の併存のいずれの構成も成立する |

### 買い目の集合

買い方（ボックス・ながし・フォーメーション）による一括登録で作られる、複数の買い目のまとまり。ただし、フォーメーションの指定内容を変更した結果、成立する買い目が1点になるときは、集合は解体され、その1点は通常の買い目になる（項番18）。ボックス・ながしは、成立する買い目が1点でも1点だけを含む集合として保持する（項番18）。券種・買い方・買い方の指定内容と、含まれる買い目に一律に適用する「1点あたりの購入額」を保持する。

券種は買い目の集合自身の項目として持つ。買い方の指定内容の妥当性（成立する買い方・選択対象・選択数・最小の選択数）が券種によって定まるため、集合の単位で券種が確定していなければ買い目を生成できない。集合に含まれる各買い目も券種を項目として持ち、その値は集合の券種と一致する。

複数の項目にまたがるルール

| # | ルール |
|---|---|
| 1 | 券種は登録後に変更できない。券種を変更したい場合は、既存の買い目の集合を編集するのではなく、別の買い目の集合を新規に追加する |
| 2 | 買い方は登録後に変更できない（例: ボックスからフォーメーションへの変更はできない）。別の買い方で登録したい場合は、別の買い目の集合を新規に追加する。フォーメーションの指定内容の変更の結果、成立する買い目が1点になって通常の買い目になること（項番18）は、買い方（フォーメーション）そのものを別の買い方に変える操作ではないため、本項と矛盾しない |
| 3 | 券種と買い方の組み合わせは「券種 × 買い方 のマトリクス」で成立するものに限る。買い方「通常」は買い目の集合を作らない（通常の買い目として登録される）ため、集合の買い方はボックス・ながし・フォーメーションのいずれかとなる |
| 4 | 買い方の指定内容の構造は買い方に対応する。ボックスは選択集合、ながしは軸と相手、フォーメーションは着順（構成位置）ごとの選択集合を指定する。ながしのパターンは「ながしのパターン」を参照 |
| 5 | 買い方の指定内容で選択する対象（馬番／枠番）と選択数は券種に対応する。「券種の属性」を参照 |
| 6 | 枠連のゾロ目（同一枠番同士の組合せ）を買い目に含められるかは買い方によって異なる。「枠連のゾロ目のルール」を参照 |
| 7 | 買い方の指定内容は、成立に必要な最小の選択数を下回ることはできない。最小の選択数は券種と買い方の組み合わせごとに定まる。「券種 × 買い方 のマトリクス」を参照 |
| 8 | 「バラす」操作を行うと、買い目の集合は解体される。集合に含まれていた買い目は通常の買い目と同じ扱いになり、各買い目の組合せ・券種・購入額・件数・結果状態・払戻額は変わらない（フォーメーションの指定内容の変更で1点になって解体される場合は、結果状態・払戻額が未入力に戻る点で異なる。項番18）。解体によって集合が保持していた買い方・買い方の指定内容・1点あたりの購入額は保持されなくなる |
| 9 | 「バラす」操作、およびフォーメーションの指定内容の変更の結果が1点になることによる解体（項番18）は一方向であり、解体した買い目の集合を復元することはできない。バラした後に同じ買い方で登録したい場合は、別の買い目の集合を新規に追加する |
| 10 | 買い目の集合に属する買い目は個別に操作できない。買い目を個別に追加・削除することも、買い目ごとに購入額を変更することもできない。含まれる買い目は買い方の指定内容から一意に定まるため、買い目の増減は買い方の指定内容の変更によって行い、購入額の変更は「1点あたりの購入額」による一律の変更で行う。個別に操作したい場合は集合をバラす |
| 11 | 買い方の指定内容を変更すると、含まれる買い目は変更後の指定内容から成立する組合せの集合に作り直され、各買い目の購入額は当該集合の「1点あたりの購入額」となる。指定内容の変更と同時に「1点あたりの購入額」を変更してよく、その場合は変更後の値が各買い目の購入額となる（変更しない場合は変更前の値）。フォーメーションで変更後に成立する買い目が1点になる場合は項番18に従う。作り直されるとき、作り直された買い目（集合に含まれるすべての買い目）の結果状態と払戻額は未入力に戻る。レース記録の結果の確定状態が確定前なら、もともと全買い目が結果未確定で払戻額を持たないため変化はない。確定後なら、作り直された買い目は的中・返還の指定が外れた状態（「結果入力のルール」上は不的中）になり、入力済みの払戻額は破棄される。必要な場合、ユーザーは改めて的中・返還を指定し、払戻額を入力する。作り直されなかった他の買い目・他の集合の結果状態・払戻額は変わらない。指定内容が実際に変わらない（成立する組合せが変わらない）ときは作り直しが起きないため、本項の結果の扱いの対象外であり、買い目の結果状態・払戻額は変わらない。「バラす」（項番8）は従来どおり結果状態・払戻額を保持する |
| 12 | 集合に含まれる買い目の件数は1件以上とする。買い目を0件にすることはできない。1点だけを含む集合は成立しうる。ボックス・ながしは指定内容の変更の結果が1点になっても、1点だけを含む集合のまま保持する。サーバーは1点だけを含む買い目の集合を受け入れ、拒否しない（API に直接送られたフォーメーションの集合を含む）。フォーメーションの指定内容の変更の結果が1点になる場合は集合が解体される（項番18）ため、その変更の結果として1点のフォーメーションの集合が保持されることはない。上限は個別に定めず、レース記録全体の200件の上限に従う |
| 13 | 一括登録によって成立する買い目の件数が、属するレース記録の既存の買い目の件数と合わせて200件を超える場合、その買い方の指定内容は成立しない。件数の求め方は「点数（買い目数）の算出ルール」を参照 |
| 14 | 集合に含まれる買い目の券種はすべて同一であり、集合の券種と一致する |
| 15 | 集合に含まれる買い目の購入額はすべて同額であり、集合の「1点あたりの購入額」と一致する |
| 16 | 同一の買い目の集合の中に、同一の組合せの買い目を2件以上持つことはできない。買い方の指定内容から同一の組合せが複数回生成される場合は1件の買い目として扱う（「点数（買い目数）の算出ルール」のフォーメーションの共通ルールを参照） |
| 17 | 点数は当該集合に含まれる買い目の件数であり、集合の購入額は `1点あたりの購入額 × 点数` である |
| 18 | 成立する買い目が1点になる場合の扱いは次のとおり。<br>(a) フォーメーションの買い目の集合の指定内容を変更した結果、成立する買い目が1点になる場合、集合は解体され、その1点は通常の買い目に置き換わる。集合が解体され、残った1件が通常の買い目と同じ扱いになる点は「バラす」（項番8）と同じである。一方、結果状態・払戻額は「バラす」と異なり保持されず、未入力に戻る（項番11）。解体後は、集合が保持していた買い方・買い方の指定内容・1点あたりの購入額は保持されず、集合は復元できない（項番8・項番9）。<br>(b) 置き換わった1件の購入額は、指定内容の変更の時点で入力された「1点あたりの購入額」とする。変更と同時に1点あたりの購入額を変更した場合はその値、変更しなかった場合は変更前の値となる（項番11）。<br>(c) 指定内容の変更の結果が1点になったときに集合を解体して通常の買い目にするのは、フォーメーションの集合だけである。ボックス・ながしは、変更の結果が1点になっても解体せず、1点だけを含む集合のまま保持する（項番12）。<br>(d) 新規の一括登録の時点では、画面の「通常」「フォーメーション」の指定で成立する買い目が1点の場合、買い方「通常」の通常の買い目として登録する。ボックス・ながしは、成立する買い目が1点でも、1点だけを含む買い目の集合として登録する。<br>(e) サーバーは1点だけを含む買い目の集合を受け入れ、拒否しない（項番12） |

| 項目 | 値の種類 | 必須 | 値の制限 |
|---|---|---|---|
| 券種 | 選択式 | 必須 | 「対象とする券種（8種）」のマスタデータを参照。登録後に変更できない |
| 買い方 | 選択式 | 必須 | 「買い方（購入方式）」のマスタデータのうちボックス・ながし・フォーメーションのいずれか。券種との組み合わせは「券種 × 買い方 のマトリクス」で成立するものに限る。登録後に変更できない |
| 買い方の指定内容 | 選択式の集合 | 必須 | 買い方に対応する選択の構造（ボックスの選択集合／ながしの軸と相手／フォーメーションの着順ごとの選択集合）で指定する。選択対象と取りうる値は「券種の属性」および「レース番号・馬番・枠番の取りうる値」に従う。最小の選択数は「券種 × 買い方 のマトリクス」を参照。成立する買い目が、属するレース記録の200件の上限を超える指定はできない |
| 1点あたりの購入額 | 整数 | 必須 | 0より大きく `1,000,000` 以下。購入単位は「購入金額のルール」を参照。集合に含まれるすべての買い目の購入額がこの値となる |
| 点数 | 整数 | 自動算出 | 当該集合に含まれる買い目の件数。1以上。上限は属するレース記録の200件の上限に従う。ユーザーは直接入力しない |
| 購入額 | 整数 | 自動算出 | `1点あたりの購入額 × 点数`。「購入金額のルール」を参照 |

### 買い目

レース記録に属する1点分の購入単位。券種と、その券種に対応する1つの組合せ（馬番または枠番の組合せ）を持ち、購入額・結果状態・払戻額を持つ。1つの買い目を1点として数える。

買い目は、1組ずつ指定して通常の買い目としてレース記録に追加するか、買い方（ボックス・ながし・フォーメーション）による一括登録で買い目の集合に含まれる形で追加する。

複数の項目にまたがるルール

| # | ルール |
|---|---|
| 1 | 組合せの構造（選択対象・選択数・順序の区別）は、当該買い目の券種に対応する。「券種の属性」を参照 |
| 2 | 通常の買い目では、券種・組合せ・購入額をユーザーが買い目ごとに指定する |
| 3 | 買い目の集合に含まれる買い目では、券種は集合の券種、購入額は集合の「1点あたりの購入額」、組合せは集合の買い方の指定内容から成立する組合せとなる。いずれも買い目ごとには指定しない |
| 4 | 結果状態と払戻額は、属するレース記録の結果の確定状態に応じて定まる。結果状態の決まり方と払戻額の値の成立条件は「結果入力のルール（結果の確定状態による条件分岐）」を参照。結果状態の定義は「結果状態（買い目単位）」を参照。通常の買い目と買い目の集合に含まれる買い目のいずれも、買い目1件ごとに結果状態と払戻額を持つ |
| 5 | 購入額の変更・買い目の削除は、通常の買い目に対して買い目ごとに行える。買い目の集合に含まれる買い目に対しては行えない。「買い目に対して行える操作」を参照 |
| 6 | 1件のレース記録に属する買い目をすべて削除することはできず、1件以上を保持する |
| 7 | 組合せの重複は、券種と所属の単位によって扱いが異なる。詳細は下表「同一の組合せの重複の扱い」を参照 |

同一の組合せの重複の扱い

| 範囲 | 扱い |
|---|---|
| 同一の買い目の集合の中 | 券種は集合内で共通であるため、同一の組合せの買い目を2件以上持つことはできない。買い方の指定内容から同一の組合せが複数回生成される場合は1件として数える |
| 券種が異なる買い目どうし | 番号の組合せが同一でも別の買い目として成立する（例: 馬連 `1-2` とワイド `1-2` は別の買い目） |
| 通常の買い目どうし | 券種と組合せがともに同一の買い目が複数存在してよい |
| 通常の買い目と、買い目の集合に含まれる買い目の間 | 券種と組合せがともに同一の買い目が併存してよい |
| 異なる買い目の集合に含まれる買い目の間 | 券種と組合せがともに同一の買い目が併存してよい |

集合の外側で重複を許容するのは、買い方の異なる複数の買い目の集合を1件のレース記録に登録できること（買い目の集合の買い方は変更できず、別の買い方は別の集合として登録する）、および買い目の集合をバラしても組合せ・購入額・件数が変わらないことと整合させるためである。重複する買い目はそれぞれ独立に1点として数え、購入額・払戻額・結果状態も買い目ごとに持つ。

| 項目 | 値の種類 | 必須 | 値の制限 |
|---|---|---|---|
| 券種 | 選択式 | 必須 | 「対象とする券種（8種）」のマスタデータを参照。通常の買い目はユーザーが選択する。買い目の集合に含まれる買い目は集合の券種と一致する |
| 組合せ | 選択式の集合 | 必須 | 当該買い目の券種に対応する1つの組合せ。通常の買い目はユーザーが直接選択し、買い目の集合に含まれる買い目は集合の買い方の指定内容から成立する組合せが設定される。取りうる値は「券種の属性」および「レース番号・馬番・枠番の取りうる値」に従う |
| 購入額 | 整数 | 必須 | 0より大きく `1,000,000` 以下。購入単位は「購入金額のルール」を参照。通常の買い目はユーザーが入力し、買い目の集合に含まれる買い目は集合の「1点あたりの購入額」と一致する |
| 結果状態 | 選択式 | 必須 | 「結果状態（買い目単位）」の4値（結果未確定／的中／不的中／返還） |
| 払戻額 | 整数 | 結果状態が「的中」のときのみ必須 | 0より大きく `99,999,999` 以下。結果状態ごとの値の成立条件は「結果入力のルール（結果の確定状態による条件分岐）」を参照 |

#### 買い目に対して行える操作

`○` = 行える、`×` = 行えない。買い目の集合をバラすと、その集合に含まれていた買い目は「通常の買い目」の列の扱いに変わる。

| # | 操作 | 内容 | 買い目の集合に属する買い目 | 通常の買い目 |
|---|---|---|---|---|
| 1 | 買い目を1組ずつ追加する | 券種・組合せ・購入額を指定して買い目を1件追加する。追加された買い目は通常の買い目となる | ×（集合に買い目を個別に追加することはできない） | ○ |
| 2 | 買い方で一括登録する | ボックス・ながし・フォーメーションの指定内容から成立する組合せをすべて買い目として登録する | ―（買い目の集合の作成時、および買い方の指定内容の変更時に集合の単位で行う） | ―（通常の買い目に対する操作ではない。一括登録したい場合は買い目の集合を新規に追加する） |
| 3 | 買い目ごとに購入額を変更する | 買い目1件の購入額を個別に変更する | × | ○ |
| 4 | 買い目を削除する | 買い目1件を個別に削除する | × | ○（レース記録に残る買い目が1件以上となる範囲で行える） |

買い目の集合に対して行える操作

| # | 操作 | 内容 | 備考 |
|---|---|---|---|
| 1 | バラす | 買い目の集合を解体し、含まれていた買い目を通常の買い目と同じ扱いにする | 操作の主体は買い目の集合であり、買い目1件を単位に行う操作ではない。組合せ・券種・購入額・件数は変わらない。一方向の操作であり、解体した集合は復元できない |
| 2 | 含まれる買い目をまとめて作り直す | 買い方の指定内容を変更し、含まれる買い目を作り直す | 各買い目の購入額は集合の「1点あたりの購入額」となる（指定内容の変更と同時に1点あたりの購入額を変更してもよい）。フォーメーションで変更後に成立する買い目が1点になる場合は、集合は解体され、その1点は通常の買い目に置き換わる（買い目の集合の項番18。買い方そのものを別の買い方に変える操作ではない）。ボックス・ながしは変更後に1点になっても1点だけを含む集合のまま保持する。作り直された（置き換わった）買い目の結果状態・払戻額は未入力に戻る（買い目の集合の項番11）。指定内容が実際に変わらないときは作り直しが起きず、結果状態・払戻額は変わらない |
| 3 | 購入額を一律に変更する | 「1点あたりの購入額」を変更し、含まれるすべての買い目の購入額をその値に揃える | 集合内の買い目の購入額は常に同額である。指定内容の変更を伴わない変更では、結果状態・払戻額は変わらない。指定内容の変更と同時に行う場合は #2 に従う |
| 4 | 買い目の集合を削除する | 集合と、それに含まれるすべての買い目を削除する | レース記録に残る買い目が1件以上となる範囲で行える |

### 簡易記録

記録種別が「簡易記録」の馬券記録。複数レース分の購入額・払戻額をまとめて記録する単位であり、買い目・買い目の集合を持たない。券種・買い方・組合せ・レース番号・結果状態を持たない。

| 項目 | 値の種類 | 必須 | 値の制限 |
|---|---|---|---|
| 日付 | 日付 | 必須 | `YYYY-MM-DD` 形式。`1900-01-01` 以上、JST（日本標準時、UTC+9）の当日以下。未来日は不可（結果が確定したものだけを対象とする記録種別のため）。日付の値（`YYYY-MM-DD`）は暦日そのものであり、タイムゾーン変換は行わない |
| 競馬場 | 選択式 | 必須 | 「対象とする競馬場（JRA・10場）」「対象とする競馬場（NAR・14場）」のマスタデータを参照 |
| 購入額 | 整数 | 必須 | 0より大きく `99,999,999` 以下。購入単位は「購入金額のルール」の簡易記録の行を参照 |
| 払戻額 | 整数 | 必須 | 0以上 `99,999,999` 以下。0を許容する |

## 算出・生成ルール

### 枠連のゾロ目のルール

| 買い方 | ゾロ目の扱い |
|---|---|
| 通常 | 同一の枠番を2つ指定することで、1つの買い目（1点）として登録できる |
| ボックス | 含めない。異なる枠番同士の組合せのみを数える |
| ながし | 含める。軸に選んだ枠と同一の枠を相手として指定でき、その組合せはゾロ目となる |
| フォーメーション | 含める。2つの選択集合の双方に同一の枠が含まれる場合、その枠のゾロ目が組合せとして成立する |

### 購入金額のルール

| 条件 | ルール |
|---|---|
| 購入単位 | 1つの買い目（1点）あたり100円単位。100円未満の単位では購入できない |
| 通常の買い目の購入額 | ユーザーが買い目ごとに入力した金額。買い目ごとに異なる金額でよい。追加後も買い目ごとに個別に変更できる |
| 買い目の集合に含まれる買い目の購入額 | 属する買い目の集合の「1点あたりの購入額」と常に一致する。集合内の買い目の購入額はすべて同額であり、個別に変更できない |
| 買い目の集合の購入額 | `1点あたりの購入額 × 点数`。集合内の買い目の購入額が一律であるため積で求まる。各買い目の購入額が100円単位であるため、合計も必ず100円の整数倍となる |
| レース記録の購入額 | そのレース記録に属するすべての買い目の購入額の合計。すなわち、各通常の買い目の購入額の合計と、各買い目の集合の購入額の合計との和。したがって購入額は必ず100円の整数倍となる |
| 簡易記録の購入額 | 複数レース分の購入額を合算した金額であり、合算前の各購入が100円単位であるため、合計も必ず100円の整数倍となる |

### 点数（買い目数）の算出ルール

本節の計算式は、買い目の集合ごとに、その集合の券種・買い方・買い方の指定内容から一括登録される買い目の件数を求めるものである。式の中で数える「組合せ」1つが買い目1件（1点）に対応する。

通常の買い目は1組ずつ指定して追加するため、追加のたびにレース記録の買い目の件数が1増える。通常の買い目を個別に削除した場合、件数は残っている買い目の数となる。

本節の計算式で求まる件数が、属するレース記録の既存の買い目の件数と合わせて200件を超える場合、その買い方の指定内容は成立しない。1件のレース記録が持てる買い目は、通常の買い目とすべての買い目の集合に含まれる買い目の合計で最大200件であるため、その上限を超える一括登録は行えない（例: 三連単のボックスで7頭を選ぶと `P(7,3)` = 210件となり、単独で200件を超えるため成立しない）。

以下の記号を用いる。

| 記号 | 定義 |
|---|---|
| `n` | ボックスで選択した対象（馬番または枠番）の個数 |
| `m` | ながしで選択した相手の個数 |
| `A`, `B`, `C` | フォーメーションの選択集合。三連系では `A` = 1着候補、`B` = 2着候補、`C` = 3着候補。二連系では `A` = 1着（1頭目）候補、`B` = 2着（2頭目）候補 |
| `\|X\|` | 集合 `X` の要素数 |
| `k` | 二連系フォーメーションにおける `\|A∩B\|` |
| `C(n,k)` | `n` 個から `k` 個を選ぶ順序なし組合せ数。`n! ÷ (k! × (n−k)!)` |
| `P(n,k)` | `n` 個から `k` 個を選ぶ順列数。`n! ÷ (n−k)!` |

#### 通常

| 条件 | ルール |
|---|---|
| すべての券種 | 1点 |

#### ボックス

| 券種 | 順序の区別 | 点数 |
|---|---|---|
| 単勝・複勝 | ― | 成立しない |
| 枠連 | しない | `C(n,2)` = `n × (n−1) ÷ 2`（ゾロ目を含まない） |
| 馬連 | しない | `C(n,2)` = `n × (n−1) ÷ 2` |
| ワイド | しない | `C(n,2)` = `n × (n−1) ÷ 2` |

| 三連単 | する | `P(n,3)` = `n × (n−1) × (n−2)` |

#### ながし（流し）

共通ルールとして、軸に選んだ対象を相手に含めることはできない。ただし枠連はこの共通ルールの例外とし、軸と同一の枠を相手に含めることができる（馬番を選ぶ券種では、同一馬が1つの組合せに重複することがありえないため例外を認めない）。

| 券種 | パターン | 点数 |
|---|---|---|
| 単勝・複勝 | ― | 成立しない |
| 枠連 | 軸1枠 | `m`（相手の枠数をそのまま点数とする。相手に軸と同一の枠を含めた場合、その1点がゾロ目となる） |
| 馬連 | 軸1頭 | `m` |
| ワイド | 軸1頭 | `m` |
| 馬単 | 軸1頭・1着固定 | `m` |
| 馬単 | 軸1頭・2着固定 | `m` |
| 馬単 | 軸1頭マルチ | `2m` |
| 三連複 | 軸1頭 | `C(m,2)` = `m × (m−1) ÷ 2` |
| 三連複 | 軸2頭 | `m` |
| 三連単 | 軸1頭・1着固定 | `P(m,2)` = `m × (m−1)` |
| 三連単 | 軸1頭・2着固定 | `m × (m−1)` |
| 三連単 | 軸1頭・3着固定 | `m × (m−1)` |
| 三連単 | 軸1頭マルチ | `3 × m × (m−1)` |
| 三連単 | 軸2頭・着順を確定して指定（軸2頭それぞれの着順と、相手が入る着順を指定） | `m` |
| 三連単 | 軸2頭・軸2頭の着順の入れ替えも購入 | `2m` |
| 三連単 | 軸2頭マルチ | `6m` |

#### フォーメーション

共通ルール

| # | ルール |
|---|---|
| 1 | 同一の対象が複数の集合に含まれていてよい |
| 2 | 1つの組合せの中で同一の対象が重複する組合せは成立しないため、点数に含めない。ただし枠連はこのルールの例外とし、同一の枠番同士の組合せ（ゾロ目）を成立する1点として数える |
| 3 | 同一の組合せが複数回生成される場合は1点として数える（重複排除する） |
| 4 | 順序を区別しない券種では、要素の並び順が異なるだけの組合せは同一の組合せとして扱う |

券種ごとの点数

| 券種 | 点数 |
|---|---|
| 単勝・複勝 | 成立しない |
| 馬単 | `\|A\| × \|B\| − k` |
| 馬連・ワイド | `\|A\| × \|B\| − k − k × (k−1) ÷ 2` |
| 枠連 | `\|A\| × \|B\| − k × (k−1) ÷ 2` |
| 三連単 | `\|A\| × \|B\| × \|C\| − (\|A∩B\| × \|C\| + \|A∩C\| × \|B\| + \|B∩C\| × \|A\|) + 2 × \|A∩B∩C\|` |
| 三連複 | `A × B × C` から重複のない3つ組を列挙し、順序を無視した組合せとして重複排除した個数。3集合が互いに素な場合は `\|A\| × \|B\| × \|C\|` |

二連系フォーメーションの点数式の導出（`k` = `\|A∩B\|`）

| # | 手順 |
|---|---|
| 1 | `a ∈ A`, `b ∈ B` の直積を数える。総数は `\|A\| × \|B\|` |
| 2 | `a` = `b` となる組は `A∩B` の要素と1対1に対応し `k` 組ある。馬番を選ぶ券種（馬連・ワイド・馬単）はこれらが成立しないため差し引く。枠連はゾロ目として成立するため差し引かない |
| 3 | 順序を区別しない券種では、`a` と `b` がともに `A∩B` に属し `a ≠ b` である組合せが、`(a,b)` と `(b,a)` の2通りで生成される。該当する順序なし組合せは `C(k,2)` = `k × (k−1) ÷ 2` 個あり、それぞれ1回ずつ重複して数えているため差し引く |
| 4 | 順序を区別する馬単では手順3の重複が発生しない（`(a,b)` と `(b,a)` は別の組合せ） |

三連複フォーメーションの点数を求める手順（一般形）

| # | 手順 |
|---|---|
| 1 | `a ∈ A`, `b ∈ B`, `c ∈ C` の全通りを列挙する |
| 2 | `a`, `b`, `c` に同一の対象が含まれる組を除外する |
| 3 | 残った組を順序を無視した集合 `{a, b, c}` に変換する |
| 4 | 重複を除いた集合の個数を点数とする |

検算例

| 例 | 式 | 点数 | 内訳 |
|---|---|---|---|
| 枠連フォーメーション `A = {1,2}`, `B = {2,3}` | `2 × 2 − 0` | 4 | `1-2`, `1-3`, `2-2`, `2-3`（`2-2` がゾロ目） |
| 枠連フォーメーション `A = B = {1,2,3}` | `3 × 3 − 3` | 6 | `1-1`, `1-2`, `1-3`, `2-2`, `2-3`, `3-3` |
| 馬連フォーメーション `A = {1,2}`, `B = {2,3}` | `2 × 2 − 1 − 0` | 3 | `1-2`, `1-3`, `2-3` |
| 馬連フォーメーション `A = B = {1,2,3}` | `3 × 3 − 3 − 3` | 3 | `1-2`, `1-3`, `2-3`（3頭ボックスと同じ） |
| 枠連ボックス 3枠 `{1,2,3}` | `C(3,2)` | 3 | `1-2`, `1-3`, `2-3`（ゾロ目を含まない） |
| 枠連 軸1枠ながし 軸 `3`、相手 `{3,5,7}` | `m` = 3 | 3 | `3-3`, `3-5`, `3-7`（`3-3` がゾロ目） |
| 馬連 軸1頭ながし 軸 `3`、相手 `{5,7}` | `m` = 2 | 2 | `3-5`, `3-7` |
| 三連単フォーメーション `A = B = C = {1,2,3}` | `27 − 27 + 6` | 6 | 3頭ボックスと同じ |
| 三連複フォーメーション `A = {1}`, `B = C = {2,3,4}` | 列挙 | 3 | `1-2-3`, `1-2-4`, `1-3-4`（軸1頭ながし・相手3頭と同じ） |

#### 成立する買い目が1点になりうる指定

上記の点数の計算式と「券種 × 買い方 のマトリクス」の最小の選択数から、成立する買い目が1点になりうる指定を次に示す。フォーメーションに限らず、ボックス・ながしでも最小の選択数の指定で1点になる。

| 買い方 | 券種・パターン | 1点になる指定 |
|---|---|---|
| ボックス | 枠連・馬連・ワイド | 最小の選択数（2枠／2頭）の指定（`C(2,2)` = 1） |
| ボックス | 三連複 | 最小の選択数（3頭）の指定（`C(3,3)` = 1） |
| ボックス | 馬単・三連単 | 1点にならない（最小の選択数でそれぞれ2点・6点） |
| ながし | 枠連・馬連・ワイド（軸1） | 相手が1つ（`m` = 1） |
| ながし | 馬単の軸1頭・1着固定、軸1頭・2着固定 | 相手が1頭（`m` = 1） |
| ながし | 馬単の軸1頭マルチ | 1点にならない（最小の選択数で2点） |
| ながし | 三連複の軸1頭 | 相手が2頭（`C(2,2)` = 1） |
| ながし | 三連複の軸2頭 | 相手が1頭（`m` = 1） |
| ながし | 三連単の軸2頭・着順を確定して指定 | 相手が1頭（`m` = 1） |
| ながし | 三連単のその他のパターン（軸1頭の着順指定・マルチ、軸2頭の入れ替え購入・マルチ） | 1点にならない（最小の選択数でそれぞれ2点以上） |
| フォーメーション | 枠連・馬連・ワイド・馬単・三連複・三連単 | 「券種ごとの点数」の式の結果が1となる指定（例: 各選択集合が1つずつで、対象が互いに重複しない指定） |
| 全買い方 | 単勝・複勝 | ボックス・ながし・フォーメーションは成立しないため該当なし |

これらの指定で成立する買い目が1点になる場合の扱いは「買い目の集合」の複数の項目にまたがるルール 項番18のとおり定める。要点は次のとおり。

| 場面 | 買い方 | 扱い |
|---|---|---|
| 指定内容の変更の結果が1点になる | フォーメーション | 集合を解体し、その1点を通常の買い目に置き換える（結果状態・払戻額は未入力に戻る） |
| 指定内容の変更の結果が1点になる | ボックス・ながし | 解体せず、1点だけを含む集合のまま保持する |
| 新規の一括登録で1点になる | 通常・フォーメーション（画面） | 買い方「通常」の通常の買い目として登録する |
| 新規の一括登録で1点になる | ボックス・ながし | 1点だけを含む買い目の集合として登録する |

### 結果入力のルール（結果の確定状態による条件分岐）

レース記録の結果に関する入力可否と、各項目が取りうる値を結果の確定状態ごとに一意に定める。本節が結果の確定状態・結果状態・払戻額に関する条件分岐の唯一の定義である。

前提となる単位

| 項目 | 定まる単位 |
|---|---|
| 結果の確定状態（確定前／確定後） | レース記録1件ごと |
| 結果状態（結果未確定／的中／不的中／返還） | 買い目1件（1点）ごと |
| 払戻額 | 買い目1件（1点）ごと |

簡易記録は結果の確定状態・結果状態を持たないため、本節の対象外とする（「記録種別ごとの結果状態を持つ単位」を参照）。

#### 結果の確定状態を選択・変更するタイミング

| タイミング | 扱い |
|---|---|
| レース記録の登録時 | 確定前・確定後のいずれかを選択する。確定後を選んだ場合は、登録時に的中・返還の指定と払戻額まで入力する |
| レース記録の編集時 | 確定前から確定後へ、確定後から確定前へ、双方向に変更できる。確定前で登録したレース記録を、後から編集で確定後に変更できる |

#### 結果の確定状態ごとの入力可否と値の成立条件

| 結果の確定状態 | 的中・返還の指定 | 各買い目の結果状態 | 払戻額 |
|---|---|---|---|
| 確定前 | 指定できない | すべて「結果未確定」。「的中」「不的中」「返還」の買い目は存在しない | 値を持たない |
| 確定後 | 的中とする買い目と返還とする買い目を指定する。いずれにも指定されなかった買い目は「不的中」となる | 「的中」「不的中」「返還」のいずれか。「結果未確定」の買い目は存在しない | 「的中」は必須で0より大きい値、「不的中」は0円、「返還」は値を持たない |

#### 的中・返還の指定ルール

| # | ルール |
|---|---|
| 1 | 指定の対象は、そのレース記録に属するすべての買い目（1点）である。通常の買い目も、買い目の集合に含まれる買い目も、買い目1件ごとに指定する。買い目の集合に含まれる買い目は集合単位ではなく1件ごとに指定する |
| 2 | ユーザーは買い目1件ごとに結果状態を直接選ぶのではなく、的中とする買い目と返還とする買い目を指定する。結果状態はその指定から定まる |
| 3 | 同一の買い目を「的中」と「返還」の両方に指定することはできない。1つの買い目に定まる結果状態は1つのみである |
| 4 | 的中・返還のいずれにも指定されなかった買い目は「不的中」となる |
| 5 | 「的中」と指定した買い目には払戻額を入力する。取りうる値は0より大きく `99,999,999` 以下 |
| 6 | 的中とする買い目の件数は0件でよい（全点が不的中となる）。返還とする買い目の件数も0件でよい |
| 7 | 券種と組合せがともに同一の買い目が1件のレース記録に複数存在する場合も、結果状態・払戻額は買い目1件ごとに指定する |

#### 結果の確定状態を変更したときの扱い

| 変更 | 各買い目の結果状態 | 払戻額 |
|---|---|---|
| 確定前 → 確定後 | すべての買い目が「結果未確定」から「的中」「不的中」「返還」のいずれかに定まる | 的中とした買い目には入力された値を保持する。不的中は0円、返還は値を持たない |
| 確定後 → 確定前 | すべての買い目の結果状態が「結果未確定」に戻る | 入力済みの払戻額は破棄される |

#### 買い目の集合の作り直し・置き換えに伴う結果の扱い

買い目の集合の指定内容の変更で含まれる買い目が作り直される（ボックス・ながしの1点の集合への作り直し、フォーメーションで1点になって通常の買い目に置き換わる場合を含む）ときは、結果の確定状態の変更とは別に、次のとおり扱う。結果の確定状態そのものは変わらない。

| 結果の確定状態 | 作り直された（置き換わった）買い目の結果状態 | 払戻額 |
|---|---|---|
| 確定前 | 「結果未確定」（もともと全買い目が結果未確定のため変化なし） | 値を持たない（変化なし） |
| 確定後 | 的中・返還の指定が外れた状態、すなわち「不的中」。確定後の買い目が「結果未確定」になることはない | 入力済みの払戻額は破棄される（不的中は0円）。ユーザーは必要なら改めて的中・返還を指定し、払戻額を入力する |

| # | ルール |
|---|---|
| 1 | 作り直されなかった他の買い目・他の集合の結果状態・払戻額は変えない |
| 2 | 指定内容が実際に変わらない（成立する組合せが変わらない）ときは作り直しが起きないため、本表の対象外である |
| 3 | 「バラす」は従来どおり結果状態・払戻額を保持する。本表の対象外である |

### 収支額・回収率の算出ルール

記号: `P` = 対象範囲の購入額合計、`R` = 対象範囲の払戻額合計

| 項目 | ルール |
|---|---|
| 返還分の扱い | 結果状態が「返還」である買い目は、購入がなかったものとして扱い、購入額合計 `P`・払戻額合計 `R` のいずれにも計上しない |
| 結果未確定分の扱い | 結果状態が「結果未確定」である買い目は、集計対象外として扱い、購入額合計 `P`・払戻額合計 `R` のいずれにも計上しない（確定分のみで集計する） |
| 返還・結果未確定の除外の適用範囲 | 上記2件の除外は結果状態を持つ単位、すなわちレース記録に属する買い目（1点）にのみ適用する。通常の買い目と買い目の集合に含まれる買い目のいずれも同様に扱う。簡易記録は結果状態を持たず返還・結果未確定を判別できないため、これらの除外ルールの適用対象外とする |
| 簡易記録の扱い | ユーザーが入力した購入額・払戻額をそのまま `P`・`R` の集計対象とする |
| 購入額合計 | `P` = レース記録に属する買い目のうち返還・結果未確定を除いた購入額と、簡易記録の購入額の総和 |
| 払戻額合計 | `R` = レース記録に属する買い目のうち返還・結果未確定を除いた払戻額と、簡易記録の払戻額の総和。不的中の買い目は0円として加算する |
| 収支額 | `収支額` = `R − P`。正の値は利益、負の値は損失、0は収支が均衡した状態を表す |
| 回収率 | `回収率（％）` = `R ÷ P × 100`。丸める前の値で、100％が収支の均衡点であり、100％超は利益、100％未満は損失を意味する |
| 回収率の表記の精度 | 算出した回収率は、小数第2位を四捨五入して小数第1位までの値とする。四捨五入は0.05以上を切り上げる通常の方法とする。丸めるのは最終の値だけであり、算出の途中（`R ÷ P` の商など）では丸めない。例: 85.26％ → 85.3％、100％ちょうど → 100.0％ |
| 利益・損失・均衡の判定 | 丸め前の値、すなわち収支額 `R − P` の正負で行う（正は利益、負は損失、0は均衡）。丸めた回収率では判定しない。丸めにより、99.95％以上100％未満の回収率が100.0％と表されることがあり、この場合も収支額は負であるため損失である。同様に、100％超100.05％未満の回収率も100.0％と表されるが、収支額は正であるため利益である |
| `P` = 0 の場合 | 回収率は定義されない（0で除算するため算出しない） |
| `R` = 0 かつ `P` > 0 の場合 | 回収率は0％（丸めた表記では0.0％と同じ値）、収支額は `−P` |

## 状態と状態遷移

### 認証状態

ログインによって成立する状態。ログイン中のユーザーが自分のデータを扱える状態にあるかどうかを表す。認証状態はログインが成立するたびに1つ成立する。1つのアカウントに、複数の端末でのログインによる複数の認証状態が同時に成立してよい。

| 状態 | 定義 | 遷移先 | 遷移条件 |
|---|---|---|---|
| 有効 | ログインが成立しており、自分のデータを扱える状態 | 失効 | 下表「有効から失効への遷移条件」のいずれかに該当したとき |
| 失効 | 認証状態が終了し、自分のデータを扱えない状態 | 有効 | 再度ログインしたとき（新たな認証状態が成立する） |

認証状態の有効期間は3日固定とし、操作の有無による延長は行わない。有効期間を超えた場合は再ログインが必要になる。

有効から失効への遷移条件

| # | 契機 | 失効する認証状態 | 失効しない認証状態 |
|---|---|---|---|
| 1 | ログイン成立時点から3日が経過したとき | 3日が経過した当該の認証状態 | 同じアカウントのほかの認証状態 |
| 2 | ログアウトしたとき | ログアウトを行った認証状態 | 同じアカウントのほかの認証状態 |
| 3 | ログイン中の画面操作でパスワードを変更したとき | 同じアカウントの既存の認証状態のうち、変更操作を行った認証状態以外のすべて | 変更操作を行った認証状態（維持される） |
| 4 | パスワード再設定メールの再設定コードを用いてパスワードを再設定したとき | 同じアカウントで再設定前に成立していたすべての認証状態。再設定を行った端末でログイン中であった場合、その認証状態も含む | なし（再設定の操作は認証状態を伴わず、再設定の完了によって認証状態にもならない） |
| 5 | アカウントが削除されたとき | 削除されたアカウントのすべての認証状態 | なし |

| # | ルール |
|---|---|
| 1 | 項番3・項番4の「既存の認証状態」は、パスワードの更新が完了した時点で成立していた認証状態を指す。更新後に新しいパスワードでログインして成立した認証状態は、項番3・項番4によっては失効しない |
| 2 | 項番3・項番4で失効する認証状態（操作を行った端末以外の認証状態）は、パスワードの更新の完了と同時に失効が反映されなくてよい。更新の完了から反映までの間、その認証状態で自分のデータを扱える期間が残ることを許容する。この期間の上限は実装方式に由来するため本ファイルでは値を定めず、`designs/architecture.md` の 5.1（パスワード変更）・5.2（パスワード再設定）の制約に従う |
| 3 | 項番5で失効する認証状態（削除されたアカウントのすべての認証状態）は、アカウントの削除の完了と同時に失効が反映されなくてよい（パスワード変更・再設定と同じ扱い）。削除の完了から反映までの間、その認証状態で自分のデータを扱える期間が残ることを許容する。この期間の上限は本ファイルでは値を定めず、`designs/architecture.md` の 5.1・5.2 の制約に従う。この期間中に削除済みアカウントの認証状態で馬券記録が新たに作られた場合、その記録は削除済みアカウントに属するデータであり、同じメールアドレスで再登録されたアカウント（削除済みアカウントとは別のアカウント）には引き継がれない。本プロダクトはこの状況を許容し、独自の対策は設けない |

### 結果状態（買い目単位）

結果状態は、レース記録に属する買い目（1点）ごとに定まる状態である。通常の買い目と買い目の集合に含まれる買い目のいずれも、買い目1件ごとに結果状態を持つ。券種と組合せが特定できる単位にのみ成立する概念であり、買い目以外には結果状態を定めない（買い目の集合そのものは結果状態を持たない）。

| 状態 | 定義 | 遷移先 | 遷移条件 |
|---|---|---|---|
| 結果未確定 | 購入済みで、結果がまだ確定していない | 的中 / 不的中 / 返還 | 属するレース記録の結果の確定状態が「確定後」になったとき |
| 的中 | 的中して払戻が発生した | 結果未確定 | 属するレース記録の結果の確定状態が「確定前」に戻されたとき |
| 不的中 | 的中しなかった。払戻は発生しない | 結果未確定 | 同上 |
| 返還 | 購入が無効となり購入額が返された。収支の算出対象から除外する | 結果未確定 | 同上 |

結果状態は、その買い目が属するレース記録の「結果の確定状態」が変更されたときにのみ遷移する。ただし次の例外がある。買い目の集合の指定内容の変更で含まれる買い目が作り直される（または通常の買い目に置き換わる）ときは、作り直された買い目は変更前の結果状態・払戻額を引き継がず、結果の確定状態に応じて、確定前なら「結果未確定」、確定後なら的中・返還の指定が外れた状態である「不的中」（払戻額は破棄）となる。確定後の買い目が「結果未確定」になることはない（詳細は「結果入力のルール」の「買い目の集合の作り直し・置き換えに伴う結果の扱い」を参照）。買い目の集合をバラす操作は、含まれていた買い目の結果状態を変更しない。遷移の際に各買い目がどの結果状態になるか、および払戻額の扱いは「結果入力のルール（結果の確定状態による条件分岐）」を参照。

### 結果の確定状態（レース記録単位）

結果の確定状態は、レース記録ごとに定まる状態である。レース記録の項目として持ち、登録時に選択し、編集時に変更できる。

| 状態 | 定義 | 遷移先 | 遷移条件 |
|---|---|---|---|
| 確定前 | そのレースの結果がまだ確定していない | 確定後 | ユーザーが結果を確定させたとき |
| 確定後 | そのレースの結果が確定している | 確定前 | ユーザーが結果を未確定に戻したとき |

各状態での入力可否、買い目の結果状態・払戻額の値の成立条件、および遷移に伴う結果状態・払戻額の扱いは「結果入力のルール（結果の確定状態による条件分岐）」を参照。

### 記録種別ごとの結果状態を持つ単位

| 記録種別 | 結果状態を持つ単位 | 取りうる結果状態 | 結果の確定状態 |
|---|---|---|---|
| レース記録 | 買い目（1点）ごと。通常の買い目と買い目の集合に含まれる買い目のいずれも1件ごとに持つ | 結果未確定 / 的中 / 不的中 / 返還 | 持つ（確定前 / 確定後） |
| 簡易記録 | なし（結果状態を持たない） | ― | 持たない |

簡易記録は複数レース分の購入額と払戻額を合算した記録であり、買い目・買い目の集合を持たないため券種も組合せも持たない。したがって「買い目1点の結果」という概念が成立しない。結果状態を持たないため、結果の確定状態も持たない。複数レースをまとめれば的中と不的中が混在するため、レコード単位で単一の結果状態を定めることはできない。
