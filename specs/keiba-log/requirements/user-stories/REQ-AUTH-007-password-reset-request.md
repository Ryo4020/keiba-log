# REQ-AUTH-007: パスワード再設定の申請

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-007` |
| 担当 | user-story-analyst |

## ユーザーストーリー

パスワードを忘れて自分のデータに入れなくなったとき再びログインできるようにするため、メールアドレスを入力して再設定を申請し、再設定コードを記載したパスワード再設定メールを受け取りたい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN 有効化済みアカウントのメールアドレスでパスワード再設定を申請する THEN システムはそのメールアドレス宛にパスワード再設定メールを送信しなければならない。 |
| 2 | WHEN | WHEN パスワード再設定メールを送信する THEN システムは有効期限を持つ再設定コードをそのメールに記載しなければならない。 |
| 3 | IF | IF 申請されたメールアドレスが登録されていない THEN システムはパスワード再設定メールを送信してはならない。 |
| 4 | IF | IF 申請されたメールアドレスが未確認アカウントのものである THEN システムはパスワード再設定メールを送信してはならない。 |
| 5 | IF | IF 同一のメールアドレスに対する申請回数が上限に達している THEN システムはパスワード再設定メールを送信してはならない。 |
| 6 | ユビキタス | システムはパスワード再設定の申請に対して、メールアドレスの登録状態（未登録・未確認・有効化済み）にかかわらず同一の結果を表示しなければならない。 |
| 7 | ユビキタス | システムはパスワード再設定の申請に対して、申請回数の上限に達したことを判別できる表示をしてはならない。 |
| 8 | IF | IF 入力値が不正である THEN システムは申請を実行せず、不正な項目を示さなければならない。 |
| 9 | WHEN | WHEN 申請の実行を受け付ける THEN システムは再設定コードと新しいパスワードを入力する手順へ進めなければならない。 |

※ メールアドレスの項目仕様および値の制限は `business-rules.md` の「エンティティ項目定義 > アカウント」に従う。
※ 再設定コードの有効期限、申請回数の上限は `business-rules.md` の「エンティティ項目定義 > アカウント」（Cognito の仕様に委ねる値）に従う。

## UI設計上の留意点

- 申請後の表示は「登録済みのメールアドレスであればメールが届く」という形にとどめ、未登録・未確認・有効化済みのいずれであるかが読み取れる差分を作らない。
- 申請後に、メールに記載された再設定コードを入力する画面へそのまま進めるようにする。
