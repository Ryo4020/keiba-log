# REQ-TICKET-005: 馬券記録一覧

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-TICKET-005` |
| 担当 | user-story-analyst |

## ユーザーストーリー

登録した馬券記録を日付の新しい順に一覧で確認したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN ユーザーが馬券記録一覧を表示する THEN システムはログイン中のユーザー自身の馬券記録のみを表示しなければならない。 |
| 2 | ユビキタス | システムは馬券記録一覧を日付の新しい順に並べなければならない。 |
| 3 | ユビキタス | システムは馬券記録一覧を1ページあたり20件で区切って表示しなければならない。 |
| 4 | WHEN | WHEN 表示対象の馬券記録が1ページの件数を超える THEN システムは他のページの馬券記録を表示する操作を提供しなければならない。 |
| 5 | ユビキタス | システムは一覧の各行に、記録種別を判別できる情報を表示しなければならない。 |
| 6 | ユビキタス | システムはレース記録の行に、当該レース記録が持つ買い目の券種・組合せ・購入額を確認できる情報を表示しなければならない（買い目の項目定義は `business-rules.md` を参照）。 |
| 7 | ユビキタス | システムはレース記録の行に、結果未確定の買い目を含むかどうかを判別できる情報を表示しなければならない。 |
| 8 | ユビキタス | システムは簡易記録の行に結果の確定状況および買い目に関する情報を表示してはならない。 |
| 9 | WHEN | WHEN ユーザーが一覧の行を選択する THEN システムは当該馬券記録の編集画面に遷移しなければならない。 |
| 10 | ユビキタス | システムは一覧の各行に、当該馬券記録の削除を開始する操作を提供しなければならない。 |
| 11 | IF | IF 表示対象の馬券記録が0件である THEN システムは空状態であることを示す表示をしなければならない。 |

## UI設計上の留意点

- 絞り込み・検索・並び順の変更を行う操作を置かないこと。
- 1件のレース記録は買い目を最大200件持つため、一覧の行に買い目を1件ずつすべて展開する表示は避け、件数・購入額合計などで要約した表示を検討すること。
