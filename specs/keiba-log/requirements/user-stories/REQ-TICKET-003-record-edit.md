# REQ-TICKET-003: 馬券記録の編集

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-TICKET-003` |
| 担当 | user-story-analyst |

## ユーザーストーリー

登録済みの馬券記録の内容を修正し、レース記録では買い目の構成と結果の確定状態を変更して結果を記録したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN ユーザーが馬券記録の編集を開始する THEN システムは対象の馬券記録の現在の内容を編集できる状態で表示しなければならない。 |
| 2 | IF | IF 対象がログイン中のユーザー自身の馬券記録でない THEN システムはその馬券記録を編集させてはならない。 |
| 3 | ユビキタス | システムは記録種別を編集で変更させてはならない。 |
| 4 | WHEN | WHEN ユーザーが馬券記録を編集する THEN システムは当該記録種別が持つ項目（`business-rules.md` の「エンティティ項目定義」）を変更できる状態にしなければならない。 |
| 5 | WHEN | WHEN ユーザーが買い目を1組ずつ指定して追加する THEN システムはその買い目を通常の買い目としてレース記録に追加しなければならない。 |
| 6 | WHEN | WHEN ユーザーが通常の買い目の購入額の変更または削除を行う THEN システムはその変更を当該買い目のみに反映しなければならない。 |
| 7 | WHEN | WHEN ユーザーが買い方による一括登録を実行する THEN システムは新たな買い目の集合をレース記録に追加しなければならない。 |
| 8 | WHEN | WHEN ユーザーが買い目の集合を削除する THEN システムは当該集合とそれに含まれるすべての買い目を削除しなければならない。 |
| 9 | WHEN | WHEN ユーザーが買い目の集合をバラす、またはフォーメーションの買い目の集合の指定内容の変更により成立する買い目が1点になる THEN システムは当該集合を解体し、含まれていた買い目を通常の買い目と同じ扱いにしなければならない。バラす場合は、含まれていた買い目の結果状態および払戻額を変更してはならない。 |
| 10 | ユビキタス | システムはバラした買い目の集合を復元させてはならない。 |
| 11 | ユビキタス | システムは買い目の集合に属する買い目に対して、買い目単位の追加・削除・購入額の変更を行わせてはならない。 |
| 12 | WHEN | WHEN ユーザーが買い目の集合の買い方の指定内容を変更する THEN システムは含まれる買い目を変更後の指定内容から成立する買い目に作り直し（フォーメーションで成立する買い目が1点になる場合は #9 のとおり通常の買い目に置き換え）、作り直した（置き換えた）買い目の結果状態および払戻額を `business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」の「買い目の集合の作り直し・置き換えに伴う結果の扱い」に従って扱わなければならない。 |
| 13 | WHEN | WHEN ユーザーが買い目の集合の1点あたりの購入額を変更する THEN システムは当該集合に含まれるすべての買い目の購入額をその値に揃えなければならない。 |
| 14 | ユビキタス | システムは買い目の集合の券種および買い方を編集で変更させてはならない。 |
| 15 | IF | IF レース記録に属する買い目の件数が `business-rules.md` の「エンティティの関係と件数の制限」に定められた範囲から外れる操作が行われようとする THEN システムはその操作を実行してはならない。 |
| 16 | ユビキタス | システムはレース記録の結果の確定状態を、レース記録単位で確定前と確定後の双方向に変更させなければならない。 |
| 17 | ユビキタス | システムは結果に関する入力の可否を、`business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」に従わせなければならない。 |
| 18 | WHEN | WHEN 結果の確定状態が変更される THEN システムは各買い目の結果状態および払戻額を、`business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」に従って扱わなければならない。 |
| 19 | WHEN | WHEN 正常な入力で保存を実行する THEN システムは変更内容を当該馬券記録に反映しなければならない。 |
| 20 | IF | IF 入力値が不正である THEN システムは保存を実行せず、不正な項目を示さなければならない。 |

## UI設計上の留意点

- 通常の買い目と買い目の集合に属する買い目が判別でき、集合に属する買い目には個別の操作が行えないことが分かること。
- 買い目の集合に対する操作（バラす・買い方の指定内容の変更・1点あたりの購入額の変更・削除）が集合単位の操作として示され、バラす操作が取り消せないことが操作前に分かること。指定内容の変更で買い目が作り直されると結果状態・払戻額が未入力に戻ること、およびフォーメーションで成立する買い目が1点になる場合は集合が解体されて通常の買い目になる（元に戻せない）ことが、変更を確定する前にプレビュー等で分かること。
- 結果の確定状態の現在値と変更操作がレース記録単位で判別でき、変更に応じて結果に関する入力の扱いが変わることが分かること（扱いの内容は `business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」による）。
