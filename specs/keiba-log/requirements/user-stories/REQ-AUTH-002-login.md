# REQ-AUTH-002: ログイン

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-002` |
| 担当 | user-story-analyst |

## ユーザーストーリー

自分のデータを扱える状態にするため、登録済みのメールアドレスとパスワードでログインしたい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN 有効化済みアカウントの正しい認証情報でログインを実行する THEN システムはユーザーを認証状態にしなければならない。 |
| 2 | WHEN | WHEN ユーザーを認証状態にする THEN システムはホーム画面を表示しなければならない。 |
| 3 | IF | IF 認証情報が一致しない THEN システムはユーザーを認証状態にしてはならない。 |
| 4 | IF | IF 認証情報が一致しない THEN システムはメールアドレスとパスワードのどちらが誤りかを判別できる表示をしてはならない。 |
| 5 | IF | IF 対象が未確認アカウントである THEN システムはユーザーを認証状態にせず、メールアドレスの確認が完了していないことを示さなければならない。 |
| 6 | IF | IF 入力値が不正である THEN システムはログインを実行せず、不正な項目を示さなければならない。 |
| 7 | IF | IF 対象が未確認アカウントである THEN システムは確認コードの入力に進めるようにしなければならない。 |

※ メールアドレス・パスワードの項目仕様および値の制限は `business-rules.md` の「エンティティ項目定義 > アカウント」に従う。

## UI設計上の留意点

- ログイン画面から、アカウント登録とパスワード再設定の申請へ到達できるようにする。
- 未確認アカウントでログインを試みたときは、確認が完了していないことと、確認コードの入力へ進む導線を同じ場所で示す。
