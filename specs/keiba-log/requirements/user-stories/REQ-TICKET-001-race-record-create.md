# REQ-TICKET-001: レース記録の登録

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-TICKET-001` |
| 担当 | user-story-analyst |

## ユーザーストーリー

購入した馬券の買い目をレース単位で入力し、そのレースの結果の確定状態を選んで、レース記録として登録したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN ユーザーがレース記録の登録を開始する THEN システムは日付・競馬場・レース番号と買い目を入力できる状態にしなければならない。 |
| 2 | ユビキタス | システムは競馬場・レース番号・券種・買い方・対象の入力を、`business-rules.md` に定義された選択肢からの選択式にしなければならない。 |
| 3 | WHEN | WHEN ユーザーが買い目を1組ずつ指定して登録する THEN システムはその買い目を通常の買い目としてレース記録に追加しなければならない。 |
| 4 | WHEN | WHEN ユーザーが買い方による一括登録を実行する THEN システムは指定内容から成立する買い目をまとめて登録し、1つの買い目の集合として保持しなければならない。ただし、フォーメーションで成立する買い目が1点になる場合は、通常の買い目として登録しなければならない。 |
| 5 | IF | IF 券種と買い方の組み合わせが `business-rules.md` の「券種 × 買い方 のマトリクス」で成立しない THEN システムはその組み合わせを選択させてはならない。 |
| 6 | ユビキタス | システムは一括登録によって成立する買い目の件数を、`business-rules.md` の「点数（買い目数）の算出ルール」に従って求めなければならない。 |
| 7 | ユビキタス | システムは1件のレース記録が持つ買い目の件数を、`business-rules.md` の「エンティティの関係と件数の制限」に定められた範囲に収めなければならない。 |
| 8 | ユビキタス | システムはレース記録の購入額を、`business-rules.md` の「購入金額のルール」に従って算出して表示しなければならない。 |
| 9 | ユビキタス | システムはレース記録の登録時に、結果の確定状態をレース記録単位で選択させなければならない。 |
| 10 | ユビキタス | システムは結果に関する入力の可否を、`business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」に従わせなければならない。 |
| 11 | WHEN | WHEN 登録を実行する THEN システムは各買い目の結果状態および払戻額を、`business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」に従って保存しなければならない。 |
| 12 | WHEN | WHEN 正常な入力で登録を実行する THEN システムはレース記録をログイン中のユーザー自身の馬券記録として保存しなければならない。 |
| 13 | WHEN | WHEN レース記録を保存する THEN システムは記録種別をレース記録として保存しなければならない。 |
| 14 | IF | IF 入力値が不正である THEN システムは登録を実行せず、不正な項目を示さなければならない。 |

## UI設計上の留意点

- 通常の買い目と買い目の集合を1件のレース記録に混在させられるため、どちらとして入力しているかが判別できること。
- 買い目の集合は、買い方の指定内容と、そこから成立した買い目の一覧を確認できること。
- 結果の確定状態の選択が登録時の入力として明示され、選択に応じて結果に関する入力の扱いが変わることが判別できること（扱いの内容は `business-rules.md` の「結果入力のルール（結果の確定状態による条件分岐）」による）。
