# REQ-AUTH-008: パスワードの変更

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-008` |
| 担当 | user-story-analyst |

## ユーザーストーリー

パスワードを新しい値に変更するため、パスワード再設定メールに記載された再設定コードと新しいパスワードを画面で入力して設定する場合と、ログイン中に現在のパスワードを確認しつつ画面上で変更する場合の両方で、新しいパスワードを入力して更新したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN 正常な入力でパスワードの更新を実行する（有効な再設定コードを入力した再設定・ログイン中の画面操作のいずれの経路でも） THEN システムは対象アカウントのパスワードを入力された値に更新しなければならない。 |
| 2 | WHEN | WHEN ログイン中の画面操作によるパスワードの更新が完了する THEN システムは対象アカウントの、更新操作を行った認証状態を除く既存の認証状態を失効させなければならない。 |
| 3 | WHEN | WHEN 再設定コードを入力してパスワードを再設定する THEN システムは現在のパスワードの入力を求めず、再設定コードと新しいパスワードの入力を受け付けなければならない。 |
| 4 | WHEN | WHEN ログイン中の画面操作でパスワードを変更する THEN システムは変更前の現在のパスワードの入力を必須としなければならない。 |
| 5 | IF | IF ログイン中の画面操作で入力された現在のパスワードが正しくない THEN システムはパスワードを更新してはならない。 |
| 6 | WHEN | WHEN 再設定コード経由でパスワードの更新が完了する THEN システムは使用した再設定コードを無効にしなければならない。 |
| 7 | WHEN | WHEN 再設定コード経由でパスワードの更新が完了する THEN システムはユーザーを認証状態にせず、ログイン画面へ誘導しなければならない。 |
| 8 | WHEN | WHEN ログイン中の画面操作でパスワードの更新が完了する THEN システムは操作を行ったユーザーの認証状態を維持しなければならない。 |
| 9 | IF | IF 入力値が不正である THEN システムはパスワードを更新せず、不正な項目を示さなければならない。 |
| 10 | IF | IF 入力された再設定コードの有効期限が切れている THEN システムはパスワードを更新してはならない。 |
| 11 | IF | IF 入力された再設定コードが誤り、または有効期限切れである THEN システムはパスワードを更新できないことを示さなければならない。 |
| 12 | WHEN | WHEN 再設定コード経由でパスワードの更新が完了する THEN システムは対象アカウントの、更新前に成立していたすべての認証状態を失効させなければならない。 |
| 13 | IF | IF 再設定コードの入力の試行回数が上限に達している THEN システムはパスワードを更新せず、更新できないことを示さなければならない。 |

※ パスワードの項目仕様および値の制限は `business-rules.md` の「エンティティ項目定義 > アカウント」に従う。
※ 再設定コードの有効期限、入力の試行回数の上限は `business-rules.md` の「エンティティ項目定義 > アカウント」（Cognito の仕様に委ねる値）に従う。
※ #2・#12 で失効する認証状態は、更新の完了と同時に失効しなくてもよい。許容する遅延は `business-rules.md` の「状態と状態遷移 > 認証状態」のルール2に従う。

## UI設計上の留意点

- ログイン中の画面操作では、現在のパスワード欄と新しいパスワード欄を明確に区別して表示する。
- 再設定コード経由では、再設定コードの欄と新しいパスワードの欄を同じ画面で入力できるようにする。期限切れは新しいパスワードを送信して初めて分かるため、入力前に期限を前提とした表示をしない。
- 再設定コードが使えなかった場合は、入力し直しとパスワード再設定の申請へ戻る導線の両方を用意する。
