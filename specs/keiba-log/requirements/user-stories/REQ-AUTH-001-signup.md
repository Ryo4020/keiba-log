# REQ-AUTH-001: アカウント登録

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-001` |
| 担当 | user-story-analyst |

## ユーザーストーリー

自分の馬券記録を残せるようにするため、メールアドレスとパスワードを入力して自分のアカウントを新規作成したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN アカウントが存在しないメールアドレスで正常な入力のアカウント登録を実行する THEN システムは未確認アカウントを作成しなければならない。 |
| 2 | WHEN | WHEN 未確認アカウントを作成する THEN システムは登録されたメールアドレス宛に確認コードを記載した確認メールを送信しなければならない。 |
| 3 | IF | IF 入力されたメールアドレスに未確認アカウントが存在する（確認コードの有効期限が切れている場合を含む） THEN システムは新しいアカウントを作成してはならない。 |
| 4 | IF | IF 入力されたメールアドレスに有効なアカウント（未確認アカウント・有効化済みアカウントのいずれか）が存在する THEN システムは既存のアカウントの有効化状態およびパスワードを変更してはならない。 |
| 5 | IF | IF 入力されたメールアドレスに有効化済みアカウントが存在する THEN システムは新しいアカウントを作成してはならない。 |
| 6 | WHEN | WHEN アカウント登録の実行を受け付ける THEN システムは確認コードを入力する手順へ進めなければならない。 |
| 7 | ユビキタス | システムはアカウント登録の結果として、入力されたメールアドレスのアカウントの存在および有効化状態を判別できる表示をしてはならない。 |
| 8 | IF | IF 入力値が不正である THEN システムはアカウントを作成せず、不正な項目を示さなければならない。 |
| 9 | WHEN | WHEN アカウント登録の実行を受け付ける THEN システムはユーザーを認証状態にしてはならない。 |

※ メールアドレス・パスワードの項目仕様および値の制限は `business-rules.md` の「エンティティ項目定義 > アカウント」に従う。
※ 確認コードの有効期限は `business-rules.md` の「エンティティ項目定義 > アカウント」（Cognito の仕様に委ねる値）に従う。

## UI設計上の留意点

- 登録の完了ではなく「確認メールに記載された確認コードの入力が残っている」ことが伝わる案内にする。
- 既存のアカウントがある場合は確認メールが送られないため、案内の文言で確認メールを送信したと断定しない。
- アカウントの存在・有効化状態が読み取れる差分（文言・遷移先・表示時間）を作らない。
