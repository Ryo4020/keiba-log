# REQ-AUTH-005: アカウント削除

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-005` |
| 担当 | user-story-analyst |

## ユーザーストーリー

サービスの利用をやめるときに自分のデータを残さないようにするため、自分のアカウントを削除したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHILE | WHILE ユーザーが認証状態である システムは自分のアカウントの削除を要求する手段を提供しなければならない。 |
| 2 | WHEN | WHEN ユーザーがアカウントの削除を要求する THEN システムは削除を実行する前に確認の操作を求めなければならない。 |
| 3 | WHEN | WHEN 確認の操作でユーザーが削除に同意する THEN システムはそのアカウントを削除しなければならない。 |
| 4 | WHEN | WHEN アカウントを削除する THEN システムはそのユーザーの馬券記録をすべて削除しなければならない。 |
| 5 | WHEN | WHEN アカウントの削除が完了する THEN システムは削除したアカウントのすべての認証状態を失効させなければならない。 |
| 6 | IF | IF 確認の操作でユーザーが削除を取りやめる THEN システムはアカウントおよび馬券記録を削除してはならない。 |
| 7 | ユビキタス | システムは削除したアカウントおよびその馬券記録を復元する手段を提供してはならない。 |

※ 削除を行った端末以外の認証状態は、削除の完了と同時に失効しなくてもよい。許容する遅延は `business-rules.md` の「状態と状態遷移 > 認証状態」のルール3に従う。

## UI設計上の留意点

- 確認の操作の中で、馬券記録もすべて削除されることと、削除を取り消せないことを明示する。
- 削除の実行を、日常操作から誤って到達しない位置に置く。
