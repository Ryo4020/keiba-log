# REQ-AUTH-006: メールアドレス確認

| 項目 | 内容 |
|---|---|
| 要件ID | `REQ-AUTH-006` |
| 担当 | user-story-analyst |

## ユーザーストーリー

登録したアカウントを使える状態にするため、確認メールに記載された確認コードを画面で入力してメールアドレスを確認し、アカウントを有効化したい。確認コードが手元にないときや期限が切れたときは、確認コードを再送して受け取り直したい。

## 受け入れ基準

| # | EARS | 内容 |
|---|---|---|
| 1 | WHEN | WHEN 未確認アカウントのメールアドレスと有効な確認コードを入力して確認を実行する THEN システムはそのアカウントを有効化済みアカウントにしなければならない。 |
| 2 | WHEN | WHEN アカウントを有効化する THEN システムは有効化に使用した確認コードを無効にしなければならない。 |
| 3 | WHEN | WHEN アカウントの有効化が完了する THEN システムは有効化が完了したことを示し、ログイン画面へ誘導しなければならない。 |
| 4 | IF | IF 入力された確認コードの有効期限が切れている THEN システムはアカウントを有効化してはならない。 |
| 5 | IF | IF 入力された確認コードでアカウントを有効化できない（誤り・期限切れ） THEN システムは確認コードの再送で新しい確認コードを受け取れることを示さなければならない。 |
| 6 | IF | IF 入力された確認コードでアカウントを有効化できない（誤り・期限切れ・対象が未確認アカウントでない） THEN システムは有効化できないことを、原因を判別できない同一の表示で示さなければならない。 |
| 7 | IF | IF 確認の対象が有効化済みアカウントである THEN システムはアカウントの状態を変更してはならない。 |
| 8 | WHILE | WHILE アカウントが未確認アカウントである システムはログインが必要な機能を利用させてはならない。 |
| 9 | WHEN | WHEN 未確認アカウントのメールアドレスで確認コードの再送を実行する THEN システムはそのメールアドレス宛に新しい確認コードを記載した確認メールを送信しなければならない。 |
| 10 | ユビキタス | システムは確認コードの再送と確認コードによる確認を、メールアドレスだけで（パスワードの入力もログインも要さずに）実行できるようにしなければならない。 |
| 11 | IF | IF 確認コードの再送の対象が未確認アカウントでない（有効化済みまたは存在しない） THEN システムは確認メールを送信せず、未確認アカウントの場合と判別できない表示をしなければならない。 |
| 12 | IF | IF 確認コードの再送または入力の回数が上限に達している THEN システムはその操作を実行せず、実行できないことを示さなければならない。 |

※ 確認コードの有効期限、再送・入力の回数の上限は `business-rules.md` の「エンティティ項目定義 > アカウント」（Cognito の仕様に委ねる値）に従う。
※ 再送と確認の対象は未確認アカウントに限る（`business-rules.md` の「エンティティ項目定義 > アカウント」の複数の項目にまたがるルール）。

## UI設計上の留意点

- 確認コードの入力と確認コードの再送を同じ場所から操作でき、コードが届かない・誤り・期限切れのいずれの場合も再送に進めるようにする。
- アカウント登録の直後と、未確認アカウントでのログイン時のどちらからも確認コードの入力に到達できるようにする。
- 誤り・期限切れ・有効化済みなど原因の違いが読み取れる差分（文言・表示時間）を作らない。
