# EARS記法（日本語）

受け入れ基準は EARS（Easy Approach to Requirements Syntax）に沿って記述する。1つの基準は必ず以下のいずれか1パターンに分類する。

## パターン一覧

| パターン | 記述形式 | 用途 |
|---|---|---|
| ユビキタス | 「システムは〜しなければならない」 | 常に成立すべき性質 |
| イベント駆動 | 「WHEN （トリガー） THEN システムは〜しなければならない」 | 特定操作・イベントへの応答 |
| 状態駆動 | 「WHILE （状態） システムは〜しなければならない」 | ある状態の間、継続して成立する振る舞い |
| オプション | 「WHERE （機能がある場合） システムは〜しなければならない」 | 条件付きで存在する機能 |
| 望ましくない事象 | 「IF （異常条件） THEN システムは〜しなければならない」 | エラー・例外・境界値の扱い |

## 書き方ルール

- 主語は必ず「システムは」とする。ユーザーの行動を主語にしない（ユーザーの行動は WHEN のトリガー部分に置く）
- 述語は「〜しなければならない」または禁止の「〜してはならない」で終える。「〜できる」「〜が望ましい」といった曖昧な語尾を使わない
- **1基準につき1つの検証可能な事柄**だけを書く。複数の振る舞いを「かつ」でつなげない
- 「適切に」「必要に応じて」「高速に」といった検証できない表現を使わない。判定できる条件・数値・メッセージ内容を書く
- 表形式で記述する場合は、各行に連番とパターン名を併記する

```markdown
| # | EARS | 内容 |
|---|---|---|
| 1 | ユビキタス | システムは〜しなければならない。 |
| 2 | WHEN | WHEN 〜 THEN システムは〜しなければならない。 |
| 3 | WHILE | WHILE 〜 システムは〜しなければならない。 |
| 4 | WHERE | WHERE 〜 システムは〜しなければならない。 |
| 5 | IF | IF 〜 THEN システムは〜しなければならない。 |
```

## 記述の粒度

EARS記法は**書くべき条件の形式**を定めるものであり、「あらゆるケースを列挙せよ」という指示ではない。

- 受け入れ基準は「その要件が満たされたと言える主要な振る舞い」に絞る
- ケースを網羅的に列挙しない。自明な正常系・異常系、他の条件から自然に導かれる派生動作は省略する
- 同じ目的を持つ複数の条件は1つに統合する
- 重要な境界条件のみ明示する

例: 入力値の検証は、項目ごとのルールを並べるのではなく「IF 入力値が不正である THEN システムは〜」のように1条件に丸める。
